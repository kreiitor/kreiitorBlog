## 先建立直觉

你以前可能经常这么写：

```cpp
int sum = 0;
for (int x : v) {
    sum += x;
}
```

这当然没错。

但标准库更鼓励你写成：

```cpp
int sum = std::accumulate(v.begin(), v.end(), 0);
```

这样写有几层好处：

- 它明确表达了「我现在在做归约/求和」；
- 它和具体容器解耦，只依赖迭代器区间；
- 它更容易和其他算法组合；
- 编译器和库实现也更容易为这种标准模式做优化。

## 9.1 算法概述

算法负责「处理数据」，容器负责「保存数据」，迭代器负责「走到数据」。

标准算法因此大多长这样：

```cpp
algo(first, last, ...)
```

参数的含义是：

- 给我一个起点；
- 给我一个终点；
- 我按某种规则处理这段区间。

### 标准算法相对手写循环的优势

很多手写循环都能替换成标准算法。算法把意图写在名字里：`find_if` 是按条件查找，`transform` 是逐个变换，`copy_if` 是按条件复制。它们不关心底层是 `vector`、`deque` 还是数组，只要迭代器合适就能复用。写代码时先想「我要做什么」，再挑语义最贴切的算法，最后才考虑手写 `for`。

### 看到一个循环先判断用途

看到一个循环，先判断它属于哪一类：

```text
我是在查找？
我是在统计？
我是在过滤？
我是在变换？
我是在排序？
我是在复制？
```

属于其中任何一类，大概率已经有现成的算法。

## 9.2 一些常用算法

下面按用途分组。先记住问题类型和对应的代表算法，比背全名字有用。

---

### 9.2.1 映射

「映射」指的是：

> 把每个元素按某个规则变成另一个元素。

这类问题的代表算法是：

```cpp
std::transform(...)
```

#### 一元变换

```cpp
std::transform(v.begin(), v.end(), out.begin(), [](int x) {
    return x * 2;
});
```

执行过程是：

- 依次读取 `v` 里的每个元素；
- 把它乘以 2；
- 把结果写进 `out`。

#### 二元变换

`transform` 还可以同时读取两个范围：

```cpp
std::transform(a.begin(), a.end(), b.begin(), out.begin(), std::plus<int>{});
```

它依次做这些事：

- 取 `a[i]` 和 `b[i]`；
- 做一次二元操作；
- 把结果写到 `out[i]`。

### `transform` 与 `copy` 的区别

`transform` 的过程是：

> **边读取，边变换，边写出。**

这和单纯 `copy` 不是一回事。

### 易错点

- 目标区间 `out` 必须有足够空间，或者你用 `back_inserter(out)`；
- 如果两个输入范围做二元变换，要确保第二个范围至少一样长。

---

### 9.2.2 归约

「归约」就是把多个值合成一个值。

最典型的算法是：

```cpp
std::accumulate(...)
std::reduce(...)
```

#### `accumulate`

```cpp
int sum = std::accumulate(v.begin(), v.end(), 0);
```

它的做法是：

- 从初始值 `0` 开始；
- 按顺序把每个元素加进去；
- 最后得到总和。

它也可以做别的归约：

```cpp
int product = std::accumulate(v.begin(), v.end(), 1, std::multiplies<int>{});
```

#### `reduce`

`reduce` 和 `accumulate` 看起来像，语义并不完全一样：

- `accumulate` 按顺序做；
- `reduce` 更适合并行化，所以它不应该依赖「必须按固定顺序计算」这个前提。

### 结合性的前提

操作**不满足结合性**时，`reduce` 可能给出意料之外的结果。

比如减法：

```cpp
((a - b) - c) - d
```

和

```cpp
a - (b - (c - d))
```

结果一般不同。

所以：

- 求和、乘积这类通常适合；
- 依赖固定顺序的操作要谨慎。

### 初始值的类型

初始值的类型也会影响结果。

例如：

```cpp
auto sum = std::accumulate(v.begin(), v.end(), 0);
```

这里初始值 `0` 是 `int`，那么整个累加过程可能也会按 `int` 来推导。

所以如果你希望结果是 `long long`、`double` 等，要显式给出对应初始值。

---

### 9.2.3 过滤

「过滤」就是：

> 只保留满足条件的元素，或者去掉不满足条件的元素。

这是现实代码里很常见的一类问题。

#### `copy_if`

```cpp
std::vector<int> out;
std::copy_if(v.begin(), v.end(), std::back_inserter(out), [](int x) {
    return x % 2 == 0;
});
```

这表示：

- 读 `v`；
- 遇到偶数就复制；
- 最终把偶数收集进 `out`。

#### `remove_if` + `erase`

要在容器自身上删掉不想要的元素，写法是：

```cpp
auto it = std::remove_if(v.begin(), v.end(), pred);
v.erase(it, v.end());
```

这里的关键是：

> `remove_if` 并不真的删除元素。

它做两件事：

- 把应该保留的元素前移，返回新的逻辑结尾；
- 真正删掉容器尾部那段，还得靠 `erase`。

这套写法叫 **erase-remove 惯用法**。

#### C++20 的改进

现代写法更直接：

```cpp
std::erase_if(v, pred);
```

这个接口更接近直觉。

### 忘记 `erase` 的后果

`remove` / `remove_if` 只重排区间并返回一个新的结束位置。忘记接 `erase`，容器长度并不会变。

---

### 9.2.4 生成

「生成」类算法用于批量写值。常用的有这几个：

#### `fill`

```cpp
std::fill(v.begin(), v.end(), 0);
```

把整个区间都填成同一个值。

#### `fill_n`

```cpp
std::fill_n(v.begin(), 5, 42);
```

从起点开始填 5 个元素。

#### `generate`

```cpp
int n = 0;
std::generate(v.begin(), v.end(), [&]() {
    return n++;
});
```

每次调用函数对象或 lambda 生成一个值，不写固定值。

#### `iota`

```cpp
std::iota(v.begin(), v.end(), 1);
```

把区间写成：

```text
1, 2, 3, 4, ...
```

### 三个生成算法的分工

- `fill`：全填同一个值；
- `generate`：每次调用一个「生成器」；
- `iota`：按递增序列生成。

---

### 9.2.5 复制

复制类算法用于把一个区间搬到另一个地方。

代表算法包括：

- `copy`
- `copy_backward`
- `copy_if`
- `move`

#### `copy`

```cpp
std::copy(src.begin(), src.end(), dst.begin());
```

最普通的区间复制。

#### `copy_backward`

当源区间和目标区间可能重叠时，要格外小心。

```cpp
std::copy_backward(src.begin(), src.end(), dst.end());
```

它是从后往前处理，更适合某些重叠场景。

### 区间重叠

如果区间重叠，盲目 `copy` 可能出问题。

经验规则是：

> 普通 `copy` 更适合「不重叠」或重叠方式安全的情况；
> 重叠时要考虑 `copy_backward`，或者更明确的方案。

#### `move`

```cpp
std::move(src.begin(), src.end(), dst.begin());
```

`std::move` 按移动语义搬运元素：源对象通常仍然有效，但其值不应再假定和原来一样。

这一点和第 3 节的移动语义是同一件事。

### 9.2.6 搜索

搜索类算法很多，按需求挑一个即可。

#### 查找某个值：`find`

```cpp
auto it = std::find(v.begin(), v.end(), 42);
```

#### 按条件查找：`find_if`

```cpp
auto it = std::find_if(v.begin(), v.end(), [](int x) {
    return x > 100;
});
```

#### 统计个数：`count` / `count_if`

```cpp
auto n = std::count(v.begin(), v.end(), 0);
auto m = std::count_if(v.begin(), v.end(), pred);
```

#### 有序区间上的查找

这类算法包括：

- `binary_search`
- `lower_bound`
- `upper_bound`
- `equal_range`

前提只有一个：

> 区间已经按同一比较规则有序。

### 有序前提

区间没排好序时，二分查找类算法的结果不可靠。

- `find` 不要求有序；
- `binary_search` 这类要求有序。

这两类别混。

### 9.2.7 排序

排序是最常见的操作之一，可选的算法也有好几种。

#### `sort`

```cpp
std::sort(v.begin(), v.end());
```

或者自定义比较：

```cpp
std::sort(v.begin(), v.end(), std::greater<int>{});
```

#### `stable_sort`

稳定排序的含义是：

> 如果两个元素「比较结果相等」，它们原来的先后顺序会被保留。

这在多关键字排序时非常有用。

#### `partial_sort`

只关心前几名、不需要后面完全有序时：

```cpp
std::partial_sort(v.begin(), v.begin() + k, v.end());
```

会比「全排序再取前 k 个」更贴切。

#### `nth_element`

```cpp
std::nth_element(v.begin(), v.begin() + k, v.end());
```

它能保证：

- 第 `k` 个位置上的元素，就是如果整体排序后会出现在那里的元素；
- 它前面的元素都不大于它；
- 它后面的元素都不小于它；
- 但前后两边不保证各自完全有序。

### 按需求选排序算法

- 要完整排序：`sort`
- 要保持相等元素原顺序：`stable_sort`
- 只要前 k 个：`partial_sort`
- 只关心第 k 个位置：`nth_element`

不要一律 `sort`。

---

### 9.2.8 其他

还有几个零散但常用的算法。

#### `for_each`

```cpp
std::for_each(v.begin(), v.end(), [](int x) {
    std::cout << x << ' ';
});
```

适合表达「对每个元素做某件事」。

#### `reverse`

```cpp
std::reverse(v.begin(), v.end());
```

原地翻转。

#### `shuffle`

```cpp
std::shuffle(v.begin(), v.end(), rng);
```

随机打乱序列。

#### `min` / `max` / `minmax`

`std::min`、`std::max`、`std::minmax` 这类小算法看起来简单，有两点要知道：

1. 它们常常比手写三元表达式更清楚；
2. 用 `initializer_list` 版本时，要注意类型一致性和潜在开销。

## 9.3 并行算法

C++17 给算法加了执行策略（execution policy）。

算法除了顺序版本，还可以带一个策略参数：

```cpp
std::sort(std::execution::par, v.begin(), v.end());
```

常见策略有：

- `seq`：顺序执行；
- `unseq`：可无序向量化；
- `par`：可并行；
- `par_unseq`：既可并行又可无序向量化。

### 并行不是默认选项

这不等于所有算法都该开并行：

> 标准库为某些算法提供了统一的并行接口，但前提是你的操作要适合并行。

### 不适合并行的操作

操作里只要出现下面这些情况，就不应该轻易加并行策略：

- 有共享可变状态；
- 有顺序依赖；
- 有副作用；
- 不是线程安全的。

## 9.4 C++20 的范围算法

C++20 引入了范围算法，调用形式变了。

旧写法：

```cpp
std::sort(v.begin(), v.end());
```

C++20 可以写成：

```cpp
std::ranges::sort(v);
```

这更自然，因为算法直接接收一个范围对象。

### 范围算法的改进

1. **代码更短**
   - 不用总手写 `begin/end`。

2. **更不容易把区间写错**
   - 少传两个参数，少两次出错机会。

3. **和视图更容易组合**
   - 后面第 10 节会看到这一点。

4. **支持投影（projection）**

#### 投影

投影是：

> 在比较或处理元素前，先取出它的某个成员。

例如对 `pair` 按第二个元素排序：

```cpp
std::ranges::sort(v, std::less<>{}, &std::pair<int, int>::second);
```

这样就不必手写一个啰嗦的比较器。

### `ranges` 与旧算法的关系

`ranges` 沿用了旧算法的设计，没有推翻它们，只是调用更自然、更安全。

## 9.5 小结

1. **先想语义，再写代码**
   - 先判断它在查找、过滤、归约、生成还是排序。

2. **优先找现成算法**
   - 不要一上来就手写循环。

3. **算法围绕区间工作**
   - 依赖迭代器或范围，不依赖具体容器类型。

4. **现代 C++ 更强调组合**
   - 旧风格是 `begin/end + 算法`；
   - 新风格是 `ranges + view + 算法`。
