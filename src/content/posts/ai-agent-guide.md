## 一个公式

整个系列围绕一个公式展开：

`Agent = LLM + 上下文 + 工具`

LLM 是决策内核，上下文是 Agent 在每个决策点能看到的信息，工具是它感知和改变外部世界的接口。三者合起来是“大脑 + 眼睛 + 手脚”；环境在 Agent 边界之外，只通过观察和行动两条边与 Agent 交互。

真正要回答的是这些设计为什么成立、代价是什么、什么情况下不适用，而不是“怎么调一个 Agent 框架”。

## 系列结构

第一部分（第 1–6 章）讲怎么构建 Agent：

- 第 1 章给出概念地图、ReAct 循环和 Harness 工程。
- 第 2–3 章讲上下文、记忆和知识库。
- 第 4–5 章讲工具、Coding Agent 和通用 Agent。
- 第 6 章把观察空间和动作空间往外扩。

第二部分（第 7–10 章）讲怎么让 Agent 变强：

- 第 7 章：评估，建立可度量的反馈。
- 第 8 章：模型后训练，把能力写进参数。
- 第 9 章：基于运行经验的持续进化。
- 第 10 章：多 Agent 协作。

## 阅读路径

第一遍按顺序读 1–6 章，先建立“Agent 怎么搭起来”的骨架。第 7–10 章可以按兴趣跳读：做产品先看评估和持续进化，做模型侧先看后训练，做平台先看多 Agent 协作。

第二遍带着问题读：当前系统的瓶颈在哪一层，模型、上下文、工具，还是评估反馈？设计模式不是清单，遇到具体系统要做取舍。

## 前置知识

- 会写 Python，能读懂一段调用 LLM API 的代码。
- 知道 token、prompt、上下文窗口、工具调用这些基本概念。
- 了解强化学习的基本术语更好，但不是必需；第 8 章会从头解释。

## 怎么读这个系列

- 每章先看“本章地图”，弄清这一章解决什么、和前后章什么关系。
- 图用 Mermaid、表格或“读图顺序”表来还原结构；无法从文字确定的关系不补造。
- 每章末尾有自测题，先自己答一遍，再回读对应小节。
