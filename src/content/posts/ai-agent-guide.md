## 这条学习路径讲什么

AI Agent 的最小工程结构可以写成：

```text
Agent = LLM + 上下文 + 工具
```

LLM 负责理解、推理和选择下一步行动；上下文保存当前决策可见的信息；工具把决策转换成对环境的作用。生产环境里，这三部分外面还会包一层 Harness，负责循环、状态、权限、验证和纠错。

这条路径围绕四个问题展开：

1. Agent 如何观察环境、保存状态并选择行动。
2. 上下文、工具和记忆如何组织，才能既可靠又便宜。
3. 如何评估一个 Agent，判断改动是否真的有效。
4. 如何通过后训练、经验积累和多 Agent 协作，让系统持续变好。

## 阅读顺序

- 想先建立整体框架：第 1 章 → 第 2 章 → 第 4 章 → 第 7 章。
- 想做工程实现：第 1 至 6 章顺序阅读，再读第 10 章。
- 关注评估与训练：第 1、2、4、7、8、9 章。
- 关注多 Agent：先读完第 2、4、6 章，再进入第 10 章。

## 前置知识

- 能读写 JSON，理解 HTTP 请求与响应。
- 用过至少一种 LLM API，知道消息、工具调用和流式输出。
- 会一点 Python，能读懂循环、异常和异步调用。
- 了解 Transformer 的基本结构即可，不需要手写训练代码。

## 学习建议

- 每读一个概念，试着回答：它解决什么问题，代价是什么，什么情况下不适用。
- 读上下文工程时，对照一次真实的 API 请求，把消息数组逐项拆开。
- 读工具与评估时，自己构造一个小任务，记录输入、轨迹、结果和失败原因。
- 不要只记框架名。模型、API 和框架都会变化，稳定的判断依据是任务、上下文、工具与验证之间的关系。
