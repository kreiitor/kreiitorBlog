## 本章地图

这一章要解决的问题很集中。整体的公式是 $\text{Agent} = \text{LLM} + \text{上下文} + \text{工具}$，而这一章只盯着 LLM 这个"大脑"：先用 Mid-training 把目标领域的知识与基础能力补齐，再用 SFT、RL 这些后训练方法塑造它利用上下文和工具的行为。第七章结尾已经点明，评估体系与仿真环境是后训练的两块基石，评估环境提供练习场，评估指标定义目标，本章就站在这两块基石上，讨论真正改动模型权重、把能力沉淀进参数这件事。这里对读者的底子做的是零假设，不预设你懂梯度、懂策略优化，它从"一个模型是怎么被训练出来的"讲起，把每一步的目的、原理和它解决的问题说清楚。读完这一章，你应该能回答五个问题：能力在哪些阶段形成，每一步在做什么，这些阶段通常怎么组合，什么条件下顺序可以不同，以及在自己的项目里该在哪一步下功夫。

### 四阶段全景：本章最重要的一张地图

现代模型的能力开发通常拆成四个环节。

1. **预训练（Pre-training）**在海量互联网文本上做"预测下一个词"的训练，让模型学会语言规律、世界知识和基本推理，像一个人读完了图书馆里所有的书，博学，但还不会好好回答问题。这是最贵的一步，动辄数千万美元，也是能力的地基。
2. **Mid-training（中期训练／继续预训练）**从一个已有的基础模型出发，在目标语言、领域文档、代码、长上下文或经过设计的能力数据上继续做语言建模。它没有从头重建地基，补的是通用预训练没覆盖好的"教材章节"。相比全量预训练，数据与计算规模更小；相比 SFT，它更适合吸收大量知识和建立任务所需的基础表征。有些团队把 Mid-training 算作预训练的后半程，有些称它继续预训练（Continued Pre-training, CPT）、领域自适应预训练（Domain-Adaptive Pre-training, DAPT）或任务自适应预训练（Task-Adaptive Pre-training, TAPT）。
3. **监督微调（SFT，Supervised Fine-Tuning，用标注好的"输入—输出"对来训练模型，类似老师给出标准答案让学生照着学）**用几千到几万条"问题—标准回答"示范，教会模型该用什么格式、什么风格、什么流程来回答，把有知识、有能力的模型变成一个听得懂指令、输出规整的助手。它便宜、快、稳，是当前几乎所有部署模型都会经过的一步。
4. **强化学习（RL，Reinforcement Learning，让模型反复尝试、按结果好坏给奖惩来改进行为，类似做题后按得分复盘）**不再直接模仿标准回答的 token，改让模型自己去试，把做得好的行为的概率调高、做得差的调低。当基模已经能偶尔成功，奖励、数据和环境又设计得当时，这一步能让模型在没见过的情况下做出更好的决策，也是本章篇幅最大、最需要工程功力的一步。

> 这里给的直觉类比：**预训练**是"接受通识教育"，**Mid-training** 是"集中研修专业教材"，**SFT** 是"老师示范答题与表达规范"，**RL** 是"自己下场做题、根据结果反复打磨"。

#### 两条主线

第一条主线落在本章的对照实验里。在 GeneralPoints 和 V-IRL 相同的任务、模型和预算设置下，SFT 更容易记住示范，RL 表现出更好的泛化：SFT 对训练答案过拟合，而 RL 在分布变化的测试中更容易学到可迁移策略。这里特别强调，这是这些实验条件下测得的结果，不是 SFT 与 RL 的普遍属性，数据足够多样、正则化得当时 SFT 也能泛化，奖励或环境有偏时 RL 也会过拟合。本章用"SFT 记忆，RL 泛化"概括这些实验，并在"从预训练到 RL：四阶段全景"一节解释两种优化目标为什么可能产生这种差异。

第二条主线跟算法无关：数据和环境比算法更重要。这是工业界最反直觉、也最值钱的一条经验。掌握现成 RL 算法（PPO、GRPO 等）的基本用法就够了，真正决定成败的是三件事：Mid-training 语料有没有补齐底座，示范数据有没有建立起行为协议，仿真环境与奖励能不能提供可靠的试错反馈。很多场景下，只要前两类数据质量到位，甚至根本不需要做 RL。这里说："本章会不断把你的注意力从'调哪个算法'拉回到'数据和环境做对了没有'。"

章首这份地图里的三组对照，后面都会展开细讲。Mid-training 并不等于重新预训练，它复用已有基础模型的表征，只在目标分布上继续做语言建模，数据与算力规模远小于全量预训练。它也不等于 SFT：两者的损失函数形式很像，差别在数据组织方式与监督密度，8.1.2 会展开。RL 也不是"更强的 SFT"，SFT 优化的是复现示范的概率，RL 优化的是期望奖励，两者的信号来源与失效方式都不一样，8.1.5 会展开。

> 这张地图可以压缩成一句：读完图书馆（预训练）→ 研修专业课（Mid-training）→ 老师示范答题（SFT）→ 自己刷题复盘（RL）；真正决定成败的是数据与环境，不是算法。

## 8.1 从预训练到RL：四阶段全景

引言给出了四个环节的地图，这一节把每一步的机制讲透。这里强调，它们使用的数据、优化目标、代价各不相同，理解这些差异是读懂整章的钥匙。表 8-1 先作总体介绍，随后逐项展开。

| 阶段 | 用什么数据 | 优化目标 | 学到什么 | 典型代价 |
| --- | --- | --- | --- | --- |
| 预训练 | 海量原始互联网文本 | 预测下一个词 | 语言规律、世界知识、基本推理 | 极高（数百万～数千万美元） |
| Mid-training | 目标语言／领域／能力语料与保留数据 | 继续预测下一个词（通常对全部 token 计算损失） | 补齐领域知识、语言和基础能力 | 中到高，取决于 token 规模与是否全参训练 |
| SFT | 几千～几万条"输入—输出"示范对 | 预测下一个词（只在回答上算损失） | 指令遵循、输出格式、风格、流程协议 | 低（几小时～几天） |
| RL | 任务、环境 + 奖励信号（参考答案可选） | 最大化期望奖励 | 可迁移的决策策略、探索出的新解法 | 高（常是 SFT 的几十～上百倍） |

这张表最值得先记住的是三条正交的轴：数据从哪来（原始文本 → 领域语料 → 示范对 → 环境奖励）、损失算在哪些 token 上（全部 token → 全部 token → 只算回答 → 不算逐 token 损失，改算标量奖励）、代价量级（极高 → 中到高 → 低 → 高）。有一个点容易看错：RL 的"高"说的是相对 SFT 的倍数高，这里写的是"常是 SFT 的几十～上百倍"，跟算力峰值没有关系。原因在 8.1.4 展开，RL 要反复 rollout、要跑奖励模型或验证器，还要多次前向／反向，所以单位"训练样本"的成本远高于 SFT。表里"Mid-training 通常对全部 token 计算损失"这句是 8.1.2、8.1.3 的伏笔：同样一个"预测下一个词"损失，算在哪些 token 上，决定了模型学到的到底是什么。

> 四个阶段的差别只有三件事：用什么数据、想让哪些 token 的概率变高、以及为此要花多少钱。

### 8.1.1 预训练在做什么：预测下一个词

现代大模型的全部"智能"，都建立在一个简单到令人意外的任务上：**预测下一个词（Next Token Prediction, NTP）**。给模型看一段文本的前半部分，让它猜下一个 token 是什么。输入"中国的首都是"，模型应该给"北京"很高的概率。每猜一次，就把自己的预测和真实的下一个 token 比较，差距（称为损失 Loss）越大，参数调整得越用力，下次在类似上下文里就猜得更准。在几万亿 token 的互联网文本上反复做这件事，模型被迫学会了语法、事实、逻辑乃至基本推理，因为要在海量语境里持续猜对下一个词，没有捷径，只能真正"消化"文本里的规律。

这里要求把这个视角一直带到 Mid-training、SFT 和 RL：**模型的输出本质上是一个概率分布**。给定前文，模型对词表里每一个可能的 token 都给出一个概率。所谓训练，归根结底就是调整这个概率分布，让我们想要的 token 概率更高、不想要的更低。四个环节的区别，只在于"想要什么"，以及"用什么信号来定义想要"。

为什么"猜下一个词"能长出推理能力？文本里留下了大量因果链条的痕迹：推导过程、代码注释、条件与结论。要在一个长上下文里把下一个 token 的概率压得足够准，模型不得不把这些链条的规律内化成参数。这里的措辞是"没有捷径，只能真正'消化'文本里的规律"，这也是后训练四阶段里唯一一个能力地基。

概率分布这个视角是本章的统一语言，后面会反复看到同一个句式：预训练让真实文本里出现的 token 概率更高；Mid-training 让目标领域真实文本里的 token 概率更高；SFT 让标注回答里的 token 概率更高；RL 让能拿到高奖励的那整条轨迹的概率更高，注意这里已经不再是逐 token 对齐某个标准答案。所以只要记住一句：训练就是调整概率分布，不同阶段只是"想要的"定义不同。

预训练之后的模型博学却不好用。你问它问题，它可能续写出更多问题，而不是回答，因为互联网文本里一个问题后面常常跟着另一个问题，它还没学会"被提问时应该回答"这个协议。这个坑在工程上很常见：基座模型（base model）第一次拿来做对话，很容易得到"用户：……\n助手：……\n用户：……"这种自己编对话的续写。模型没坏，它学到的分布本来就是网页文本的续写分布。

还有一对概念要分开：损失与奖励。损失是逐 token 的、可微的、越小越好，预训练／Mid-training／SFT 用它；奖励是轨迹级的、常常不可微、越大越好，RL 用它。另外，NTP 不等于只学词表统计，如果只需要统计下一个词，模型不需要跨句、跨段的推理能力；恰恰是"在几万亿 token 上都要猜准"这个约束，把长距离依赖也逼了出来。

> 预训练就是"在几万亿 token 上反复猜下一个词"，猜得越准损失越小，模型被迫把语言、事实和推理都压进了参数，但它只是一个博学的续写器，还不是助手。

### 8.1.2 Mid-training 的本质：在目标分布上继续学习

通用预训练不可能覆盖所有语言、领域和能力。如果模型几乎读不懂韩语文档、不了解企业内部协议，或者没有形成目标任务所需的代码与长上下文表征，那么跳过这一步，直接教它"如何回答"，或者只按成败给奖惩，是补不上这些缺失的基础能力的。Mid-training 沿用预训练的下一个 token 目标，但把数据分布收窄到目标领域，并混入一部分通用保留数据以控制遗忘。它回答的问题是"模型是否拥有完成任务所需的知识与基本能力"，而不是"回答要长什么样"或"哪条策略奖励最高"。

Mid-training 与 SFT 的损失函数看起来很像，但数据组织和监督密度不同：Mid-training 通常把整段文档、代码或推导都当作学习目标，对大量 token 计算损失；SFT 把数据组织成输入—输出示范，通常只在回答 token 上计算损失。由此能推出一个实用判断，用少量问答 SFT 让模型背下一批事实，在技术上并非不可能，但它只反复强化少数访问路径，容易记住问法，而形不成广泛可调用的知识。这里给的选型结论是，需要吸收大规模、彼此关联的领域知识时，优先考虑 Mid-training；需要知识可更新、可追溯时，优先考虑 RAG。

理解 Mid-training 的关键词是"继续"和"收窄"：地基已经打好，你只是把接下来读的书换成专业课教材加一部分通识读物。混入通用保留数据（replay）的目的很实在，就是防止灾难性遗忘：只喂韩语语料，英语能力会退化；只喂代码，自然语言对话会退化。

"对全部 token 算损失"为什么这么重要？设想一份企业内部协议文档，它是一段连续文本，模型要预测的是每一个位置的下一个 token，所以必须整体吸收术语、句式、事实之间的关联结构。SFT 的一条样本是"问题→回答"，损失只回传回答部分，模型学到的是面对这种问法该怎么答。前者建立表示，后者建立协议。

这里那句"只反复强化少数访问路径"值得琢磨。假设用 200 条问答教模型公司报销规则，模型很可能只学会"当被问到'报销流程是什么'时输出这段文字"这一条路径。换一种问法、换一种语言，或者要求它做多跳推理（"我上周三订的机票能报吗？"），它就会掉链子。它背下的是答案字符串，不是可推理的知识结构。

三个工具的分工可以这样记：Mid-training 把稳定、规模大、需要形成内部表征的知识与能力写进权重；RAG 把频繁更新、必须溯源的事实放在外部检索里；SFT 教模型怎么用这些知识和工具来回答，管的是格式、流程、风格。看到"都是预测下一个词"就以为 Mid-training 和 SFT 可以互相替代，是初学本章最常见的误解：两者可以都用交叉熵，但算在哪些 token 上、数据是不是连续文档，决定了它们学到的东西完全不同。

> Mid-training 是"把专业教材整本读进去"（全 token 损失、知识进权重），SFT 是"老师示范怎么答题"（只在回答上算损失、协议进行为）；知识要更新就交给 RAG。

### 8.1.3 SFT 的本质：换了数据的"预测下一个词"

这里称为本章第一个需要打通的关键认知：**SFT 在数学上和预训练是同一个任务**，都是预测下一个词、最小化同一个损失函数。很多初学者以为 SFT 是一种全新方法，其实不是。

它与预训练的差别只有两点，而且都落在数据和损失上。数据不同：预训练用原始互联网文本，无结构、什么都有；SFT 用人工精心准备的"输入—输出"对，格式统一为"用户提问→理想回答"。模型在这些示范上继续做预测下一个词，于是把"被提问时该怎么组织回答"这个协议学了进去。另一处差别在损失只算在"回答"上，也就是 loss masking（损失屏蔽）：一条 SFT 样本包含问题和标注回答两部分，我们不希望模型学"怎么提问"，只希望它学"怎么回答"，所以计算损失时把问题部分的 token 屏蔽掉，只对回答部分回传梯度。这里说这是"SFT 在工程上与预训练唯一实质性的区别"。

理解了这一点，也就能看出 SFT 为什么会在有限示范上表现出记忆倾向：它的优化目标是让标注回答里每一个 token 的概率尽可能高，也就是尽量复现示范。对目标明确、格式固定的任务，这种方法极其高效，几千条样例就见效；当数据覆盖面和多样性不足时，模型可能对示范中的表面模式或捷径过拟合，在分布变化后性能下降。

一句话概括 SFT 的本质：用极高的样本效率，把一套稳定的"输入→输出"映射与协议固化进参数。它固化的是格式、风格、流程这类协议性知识（该怎么说、怎么做），不是大量事实性知识（知道什么），后者要靠预训练或 RAG。

SFT 和后面的 RL 都要更新模型参数，而全参数微调对显存的要求很高，要为数十亿参数都存梯度和优化器状态。**LoRA（Low-Rank Adaptation，低秩适配）**是最常用的省钱办法：不动原始的大权重矩阵，只在旁边挂一个很小的"补丁"（低秩矩阵）来学习任务，参数量仅占原始的 1%–5%，却能接近全参微调的效果；因为原权重被冻结，LoRA 对基座已有能力的扰动也更小，灾难性遗忘的风险更低。

这里给出几条经过验证的实践经验（脚注 a：Schulman, John and Thinking Machines Lab, "LoRA Without Regret", 2025）：

- 必须把 LoRA 应用到所有主要权重矩阵，尤其参数占比最大的 MLP 层；只加在注意力层会掉点。
- 最优学习率约是全参微调的 10 倍（SFT、RL 都成立，是个非常实用的迁移规则）。
- SFT 用中高 rank（64–256）；RL 因每轮信息量很小，用小 rank（8–32）甚至 rank=1 就够。
- 部署时一台推理服务器可同时加载多个 LoRA adapter 做多租户服务。

这里声明，这里把 LoRA 当作贯穿所有后训练方法的工程默认项，不再单独展开。

落到工程上，「换了数据的预测下一个词」就是一条很具体的流水线：把样本拼成 `[提问 token…][回答 token…]`，前向算 logits，把提问段的标签置为忽略（通常置为 -100），反向传播。所以 SFT 的实现成本极低，它就是预训练代码把数据换成对话格式、再加一个掩码。

样本效率为什么这么高？预训练要从零建立表示，所以需要万亿 token；SFT 只在已有的概率分布上做微调，把"回答时该走哪条路"调高一点就够了。几千条样本之所以够用，是因为表达能力已经由预训练提供了。记忆倾向的另一面是它的失效方式：SFT 的目标函数是让示范里的 token 概率高，所以它与示范分布绑定。这里在 8.1.5 会给出 GeneralPoints 的具体例子，示范里把 J/Q/K 都当作 10，测试值一变分数就掉，这就是过拟合表面模式的教科书式表现。

LoRA 那几条经验值得逐条理解。必须覆盖 MLP 层，是因为 Transformer 的参数大头在 MLP 层，只在注意力层挂 adapter，等于只让模型改注意力偏好，没有能力改变 FFN 里存储的知识与特征变换。学习率要放大约 10 倍，是因为可训练参数量少了一两个数量级，梯度信号被摊薄到更少的参数上，加上初始化为零、补丁本身接近恒等映射，需要更大的步长才能走到有效区域。RL 用小 rank，是因为它每轮只从奖励里获得极少量信息（一个标量奖励要摊到整条轨迹），需要改动的方向很少，高 rank 反而容易过拟合或训练不稳。多 adapter 多租户则是部署侧的额外收益：基座权重共享，只把不同的 LoRA 补丁挂上去，一台机器上就能同时服务多个定制模型。

这几条的反例同样具体：以为 LoRA 只加在注意力层就行，这里明确说会掉点；以为 rank 越大越好，SFT 需要中高 rank 来学习较复杂的协议映射，RL 反而需要小 rank。还有一点要分清，SFT 不是知识注入工具，它固化的是格式、风格、流程，要注入事实知识得靠预训练／Mid-training 或 RAG。

> SFT ＝ 预训练同一把损失函数 + 换了"输入—输出"示范数据 + 只在回答上算损失；它买的是极省的样本效率换稳定的输出协议。

### 8.1.4 什么时候需要先补底座，再做SFT/RL

RL 策略不直接模仿参考回答的 token，它用奖励评估模型自己生成的回答，奖励计算仍可以使用参考答案或偏好数据。要从这种信号里学习，至少要满足两个前提：输出能被验证，并且当前策略偶尔能探索到有价值的行为。

第一个前提是格式支持。如果任务要求输出 JSON 或工具调用，而模型吐出的是无法解析的文本，奖励函数连"成功还是失败"都判断不了。此时 SFT 可以先扮演"把话说利索"的角色，用少量示范稳定格式与基本流程，使奖励可计算，再由 RL 优化策略。这就是常见的"先 SFT、后 RL"。

第二个前提更根本，是能力支持。先在留出任务上以与训练相近的温度采样，测量 pass@1 和 pass@k。若单次成功概率为 $p$，近似独立采样 $k$ 次至少成功一次的概率为

$$
\mathrm{pass@}k = 1 - (1-p)^k
$$

其中 $p$ 是单次采样（一条 rollout）的成功概率，$k$ 是采样次数，$\mathrm{pass@}k$ 是 $k$ 次里至少成功一次的概率；该式假设各次采样近似独立。

如果 pass@1 低、但 pass@k 随 $k$ 明显上升，说明正确策略已经处在模型分布里，只是概率质量太小，RL、拒绝采样或蒸馏都有东西可放大。反过来，如果在合理的 $k$、采样温度和任务覆盖下，实测 pass@k 仍接近 0，那么基础模型几乎生成不出成功轨迹。只给终点 0/1 奖励时，GRPO 的一组 rollout 很可能全为 0，组内优势直接消失；PPO 也看不到"应该往哪里移动"的正向样本。把采样量继续放大，只能以约 $1/p$ 的速度等待偶然成功，效率会迅速失去实际意义。

这时要先问缺的是什么：缺领域语言、事实、代码模式或长上下文基础能力，就优先用 Mid-training 补底座；已有能力但不会按接口表达，就先用 SFT；能够局部前进但到不了终点，可以加入可验证的部分奖励或课程学习。这里的总结判断是，**RL 擅长把已有但概率较低的成功行为推高，不擅长从全零奖励中凭空创造模型从未学过的知识和能力。**

这条边界也要说清楚："必须先 SFT"只在输出格式或基本行为尚未建立时成立。实验 8-11 会看到，Llama-3.2-Vision-11B 在严格结构化输出设置中不经 SFT 直接 RL 会失败；但足够强、已经有非零成功率的基模可以跳过 SFT，DeepSeek-R1-Zero 就是这种情形。它后来加入冷启动 SFT，主要是改善可读性与语言一致性，而不是为 RL 注入任务知识。更完整的 Mid-training/SFT/RL 选择流程见后文独立决策小节（即 8.7）。

把这两个前提记成一句话：RL 需要"能打分"和"能撞对"。能打分是奖励工程的活，能撞对是 base model 能力的活，两者缺一，RL 就是在噪声上做优化。

pass@k 这条公式值得亲手算一遍（下面的数值是这里补充的计算，不是这里数据）：若 $p = 0.05$、$k = 10$，则 $\mathrm{pass@}10 = 1 - 0.95^{10} = 1 - 0.5987 \approx 0.401$；若 $k = 50$，则 $\mathrm{pass@}50 = 1 - 0.95^{50} = 1 - 0.0769 \approx 0.923$；若 $p = 0.001$、$k = 100$，则 $\mathrm{pass@}100 = 1 - 0.999^{100} \approx 0.095$。结论一目了然：$p$ 太小的时候，靠增采样把 pass@k 拉到可用区间所需的 $k$ 会爆炸（近似 $k \approx \ln(1-\text{目标})/\ln(1-p)$）。这正是这里说"效率会迅速失去实际意义"的数学依据。

$p$ 很小为什么会让 GRPO 和 PPO 都"看不到路"？**GRPO**（Group Relative Policy Optimization）靠同一题的一组 rollout 之间的相对好坏来算优势，如果一组 8 条 rollout 全错（奖励全 0），组内基线就是 0，每条的优势都是 0，梯度为零，一个字都没学到。**PPO** 依赖优势估计（比如 GAE）来给出哪些 token 该提高概率，如果一整批采样里没有任何正向样本，优势信号里就没有"该往哪走"的方向，更新会把整条轨迹的概率一起压低或几乎不动。

这一节其实是全章的决策骨架，它把 8.7 的表格提前剧透了一半：先诊断缺口类型，再决定用哪个阶段，而不是"效果不好就上 RL"。工程上还有个常见的坑：很多人用 base model 直接做 RL 失败，第一反应是奖励函数写错了，这里指出更常见的原因是格式不可解析（奖励函数拿到的是 NaN／解析失败）或者成功率恒为 0。诊断顺序应该是先量 pass@k（能力有没有），再查解析率（格式有没有），算法超参放到这两步都清楚了再调。

pass@1 低并不等于需要 Mid-training，关键看 pass@k 是否随 $k$ 上升：上升说明"会，但概率低"，RL、拒绝采样、蒸馏都有效；不动或接近 0 才是"不会"，得先补底座。"必须先 SFT"也是有条件的，只在输出格式和基本行为没建立时成立，DeepSeek-R1-Zero 就是足够强的基模跳过 SFT 直接 RL 的反例。

> 先量 pass@k：$k$ 涨得动说明"会但不熟"，交给 RL／拒绝采样；$k$ 涨不动说明"根本不会"，先 Mid-training 补底座；格式不可解析则先 SFT。

### 8.1.5 SFT 与RL 的本质区别

前面用"SFT 记忆、RL 泛化"概括了本章的对照实验，现在解释这种倾向为什么可能出现，关键在于两者的优化目标不同。SFT 最大化标注回答的概率，每个训练样本都用极大似然推动模型复现示范。多样且有代表性的示范可以教会模型可泛化的特征，但示范或 prompt 缺乏多样性时，模型也可能对表面模式或捷径过拟合，GeneralPoints 的有限示范把 J/Q/K 都当作 10，模型因此在测试值变化时性能下降。RL 最大化期望奖励，模型探索多条路径并提高高奖励路径的概率，当奖励忠实反映目标、探索也足够时，模型可能发现示范中没有的可迁移策略。GeneralPoints 中，重新执行计算过程而不是套用固定值，在分布外测试中取得了更好表现。反过来，奖励或环境有偏时，RL 同样可能对捷径过拟合。

表 8-2 给出本质对比。

| 维度 | SFT（监督微调） | RL（强化学习） |
| --- | --- | --- |
| 优化目标 | 最大化标注答案的概率（极大似然） | 最大化期望奖励 |
| 训练信号 | 标注回答的逐 token 监督 | 策略生成的回答或轨迹 + 结果级或步骤级标量奖励 |
| 数据形态 | "输入—输出"示范对 | 任务、环境 + 奖励信号（参考答案可选） |
| 直接优化压力 | 模仿示范中的映射与协议 | 强化能够获得奖励的行为与策略 |
| 分布漂移下 | 取决于示范覆盖和正则化；本章有限示范实验出现过拟合 | 取决于奖励、环境和探索；本章实验中迁移更好 |
| 样本效率 | 高（几千条见效） | 低（常是 SFT 的几十～上百倍） |
| 训练稳定性 | 高、收敛快 | 低、易震荡，需要小心调 |
| 最适合 | 固化格式/风格/流程、有高质量示范、环境稳定 | 需泛化到新场景、探索最优策略、标注成本过高 |

从概率分布看，SFT 与 RL 还有一项重要差别。一个问题往往存在多类合理回答，每一类都对应概率分布中的一个"峰"。极大似然 SFT 逐条学习示范，常表现出 **mass-covering（覆盖式）**倾向，尽量覆盖训练数据中出现过的多个模式；RL 按奖励重新分配概率，配合常见的**反向 KL 约束**时更容易表现出 **mode-seeking（寻峰）**倾向，把概率集中到少数高奖励峰上，不再平均复现所有示范。这一区分解释了两者的典型特点：SFT 擅长覆盖多种已知写法，RL 擅长从候选行为中寻找高奖励策略。最终是保持多样性还是收缩到少数模式，取决于示范分布、奖励函数、KL 方向与系数、熵正则和采样温度。

「多个峰」这个几何图像是本节最值钱的直觉。设想一道题有两类正确解法 $A$、$B$，模型分布 $p(A)=0.45$、$p(B)=0.45$。SFT（极大似然）看到示范里既有 $A$ 又有 $B$，会把两边的概率都往上抬，它不关心奖励高低，只关心别漏掉数据里出现过的模式，所以是 mass-covering；RL 按奖励重分配概率，只要 $A$ 的奖励更高，梯度就会把质量从 $B$ 搬到 $A$ 上，配合反向 KL（把策略往参考策略方向拉、抑制无谓的质量转移）更容易收敛到少数高奖励峰，所以是 mode-seeking。

KL 方向为什么一提再提：正向 KL（$\mathrm{KL}(p\|q)$）倾向覆盖参考分布的所有模式，反向 KL（$\mathrm{KL}(q\|p)$）倾向寻峰，把 $q$ 的质量集中到 $p$ 的某个峰上。这就是这里说"配合常见的反向 KL 约束时更容易表现出 mode-seeking"的原因。最终是覆盖还是收缩，还受熵正则（鼓励多样性）和采样温度（高温采样更发散）影响。

后训练还会塑造模型"何时行动"。以 Coding 模型为例，GPT 系列与 Claude 系列经常表现出不同的默认行动阈值：前者可能先读更多仓库信息再修改，后者可能用较少文件完成定位、先实现再借测试反馈修正。这里强调，这跟把模型拟人化成"谨慎"或"有直觉"无关，真正起作用的是参数中的策略在估计：多读一个文件的预期价值，是否还高于提交当前补丁并验证的预期价值。

若 SFT 示范反复包含广泛调查后才编辑的轨迹，模型就会模仿较高的行动阈值；若 RL 的过程或结果奖励持续认可快速定位、尽早进入可验证循环，概率质量就会向较早行动的轨迹集中。第七章实验 7-9 在完全相同的中性 Coding Harness 中换模，确实测到这种差异随模型变化，说明 Harness 无需强制流程，模型自身也会携带稳定的工具使用策略。Harness 可以调节它，但行为的主要来源可以位于后训练后的模型参数中。由于厂商并不公开完整数据与奖励配方，这个实验能证明的是模型侧的行为差异，不能据此断言某一种具体的私有算法造成了它。

在线反馈给了模型探索示范之外策略的机会。固定数据集上的 SFT 使用示范提供的直接训练信号，但仍可组合预训练知识，对示范中没有的输入进行泛化。在线 RL 则让模型按当前策略生成回答、接收环境反馈，从而直接评估示范之外的候选行为。这里提醒，这并不自动保证更高上限，结果取决于基础模型、示范覆盖、奖励忠实度、探索和优化稳定性。在线／离线与更严格的在轨／离轨（on-policy / off-policy）会在奖励与蒸馏部分用到，这里先看在线反馈提供的三个机会。

固定示范之外的候选第一次变得可评估。SFT 的直接监督来自数据中记录的回答，RL 还可以强化奖励函数能够评分的新行为。实验 8-13（SimpleVLA-RL）中的"推切"动作从未出现在人类示范里，说明模型有机会发现示范之外的策略。但奖励无法识别的质量学不到，探索不到的策略也发现不了。

这类机会在"验证比生成容易"的任务上尤其好用。SFT 需要先写出正确答案或高质量轨迹，RL 只需要可靠地判断答案质量。数学答案可以对照，代码可以测试，定理证明可以由验证器检查。这种不对称是 **RLVR** 的优势，但验证器不完整时也会导致奖励黑客。

还有一层好处是，训练可以发生在当前策略实际访问的状态上。离线模仿存在经典的协变量漂移（covariate shift）：策略偏离示范、进入数据中没有的状态后，可能缺少恢复信号。在特定的序列模仿学习设置中，误差最坏可随轨迹长度 $T$ 近似按 $T^2$ 累积，而在线数据聚合可把它降到约 $T$。本章后面的 On-Policy Distillation（见"蒸馏：提升样本效率"一节）把这种在线匹配与 SFT 的稠密监督结合起来。

协变量漂移的 $T^2$ 与 $T$ 值得单独看一眼。离线模仿学习里，每一步的误差会让策略进入示范没覆盖的状态，而那里没有"怎么纠回来"的监督信号，误差因此复合。经典结论（DAgger 那条线）是，最坏情况下误差随轨迹长度 $T$ 近似按 $T^2$ 累积；如果让专家或环境在你实际访问到的状态上给反馈（在线数据聚合），可降到约 $T$。这解释了为什么"在线"本身就有价值，与奖励信号是否精确无关。

这里的比方：SFT 细致学习已有地图，RL 则可以拿着奖励这枚指南针探索地图外的候选路线，地图或指南针不准都会迷路。因此许多系统先用 SFT 建立稳定起点，再在奖励与环境足够可信时加入 RL。

工程上的坑有一条：把"验证比生成容易"当双刃剑。它让 RLVR 在数学、代码上极其好用，但也会诱发奖励黑客，模型学会的是"让验证器通过"，而不是"做对事"。所以验证器要尽量完整、不可绕过，例如用隐藏测试、多个独立验证器、人工抽检校准。还有一处态度值得学：厂商不公开数据与奖励配方，所以只能观察到模型侧行为差异，不能归因到某个具体私有算法，做研究引用时要保持同样的谨慎。

另外两个容易搞反的说法：mass-covering 与 mode-seeking 描述的是分布形态，不是训练算法的名字，前者指把训练数据里出现过的多个模式都覆盖到，后者指把概率集中到高奖励的少数峰上。"在线 RL 上限更高"也不自动成立，这里明确说取决于基础模型、示范覆盖、奖励忠实度、探索和优化稳定性。至于 RL 的泛化优势，那是特定实验条件下的结论，奖励或环境有偏时 RL 一样会走捷径。

有了这张全景图，后面每一节都能对号入座。紧接着的两节［可选阅读］——"从经典 RL Agent 到现代 Agent"和"模型预训练基础"——为想深入了解的读者补充强化学习与预训练的背景；只想直接上手后训练的读者可以跳过它们，直接从 SFT 一节开始。

> SFT 用极大似然"照着地图走"（覆盖示范里的多个模式），RL 用奖励当指南针"找路"（把质量集中到高奖励峰）；方向对了 RL 能走出示范，指南针歪了它也照样迷路。

## 8.2 从经典RL Agent 到现代Agent [可选阅读]

### 8.2.1 Agent 与环境的交互

**强化学习（Reinforcement Learning, RL）的核心**是学习如何根据当前情境选择动作，以获得最大的累积奖励（Cumulative Reward）。这里的入门例子是一个学下棋的 AI：每走一步就是一个动作，赢棋得到正奖励、输棋得到负奖励，累积奖励就是整盘棋的总收益。

交互循环是这样的：每一步，Agent 观察当前状态，选择一个动作，环境产生新状态并给出奖励。这一串"状态→动作→奖励→新状态→动作→奖励⋯"的完整记录就是轨迹，策略的优劣最终体现在轨迹质量上。

图 8-1 强化学习 Agent-环境交互循环：

> 示意图：左框是 **Agent（探险者）**，内部写着"策略 $\pi$：观察状态 → 选择动作（移动/拾取/攻击）"，以及"$\varepsilon$-贪婪：90% 最优，10% 随机"；右框是**环境（迷宫世界）**，内部写着"5 个房间 · 钥匙/门/守卫"、"转移：$P(\text{储藏室}\mid\text{大厅},\text{东})=1.0$"、"$R(\text{击败守卫})=+50$，$R(\text{移动})=0$"。两框之间有两条箭头：Agent 送出的动作 $A(t)=$"向东移动"指向环境，环境返回的状态 $S(t+1)$ + 奖励 $R(t+1)$ 指回 Agent。图下方给出轨迹的通式：$S(0), A(0), R(1), S(1), A(1), R(2), \ldots$，并列出一次完整示例：$S(0)$ 入口大厅 → $A(0)$ 向东 → $R(1)=0$ → $S(1)$ 储藏室 → $A(1)$ 拿钥匙 → $R(2)=+5$ → $S(2)$ 储藏室 → $A(2)$ 向北 → $R(3)=0$ → $S(3)$ 守卫室 → $A(3)$ 合成银剑 → $R(4)=+10$ → $S(4)$ 守卫室 → $A(4)$ 攻击 → $R(5)=+50$。图右下角给出目标：
>
> $$G = R(1) + \gamma R(2) + \gamma^2 R(3) + \cdots \quad (\gamma = 0.99)$$
>
> 其中 $R(1), R(2), \ldots$ 是各步拿到的即时奖励，$\gamma$ 是折扣因子（这里取 0.99），$G$ 是折扣累积奖励。

价值函数（Value Function）回答的是这样一个问题："如果我现在处于这个状态，按照当前策略一直行动下去，最终总共能获得多少奖励？"这里的类比是，这就像一位经验丰富的棋手看到一个局面时，不需要算到最后一步，凭直觉就能估计出这盘棋的胜率。Agent 与环境的边界遵循一个简洁的原则：凡是 Agent 无法任意改变的，都属于环境。

把 RL 的交互循环和 SFT 对照着看，差别立刻清楚：SFT 的数据是人写好的（输入, 输出）对，RL 的数据是模型自己跑出来的轨迹加环境打的分。前者是静态数据集，后者每一条都是当前策略的产物。这也是 RL 会有"on-policy（在轨）"这个概念的原因，训练用的数据分布会随着参数更新而漂移。

延迟奖励为什么让 RL 难？在迷宫例子里，只有"拿钥匙（+5）""合成银剑（+10）""攻击（+50）"才有奖励，中间"向东""向北"都是 0。模型必须自己归因：这 +50 里有多少功劳属于第 5 步的"攻击"，多少属于前面 4 步的铺垫？这个功劳分配（credit assignment）问题正是价值函数和优势函数要解决的，具体写法见本章后文 RL 算法部分。

边界原则的用处在于，它把"我改了参数/提示词"和"环境变了"清晰分开。写 RL 代码时，环境就是你无法直接改的那部分（工具返回、用户行为、仿真器），Agent 是你能训练的策略。

RL 区别于监督学习（需要标注正确答案）和无监督学习（发现数据中的隐藏模式）的两个特征，是试错搜索与延迟奖励：Agent 必须自己摸索哪些动作好，没有老师直接告诉正确答案；动作的影响可能在多步之后才显现，比如一步好棋的价值要到终局才看得出来。由此还带来探索与利用权衡（Exploration-Exploitation Tradeoff）：一直走熟悉的路，学不到新东西；一直乱试，永远到不了终点。

强化学习系统包含五个核心要素：

1. 动作空间：定义 Agent 可以采取的所有行动集合。动作可以是离散的（如棋类中"走哪一步"，选项有限），也可以是连续的（如机器人"关节转多少度"，是一个连续数值）。
2. 策略：Agent 的行为准则，规定在给定状态下应该怎么做。策略可以很简单（一张查找表：看到状态 A 就执行动作 X），也可以很复杂（一个深度神经网络）。
3. 奖励信号：环境给出的即时反馈。但 Agent 的目标是最大化长期而非即时奖励，这个区别至关重要，就像投资不能只看今天涨跌，要看长期回报。
4. 价值函数：估计从某个状态出发，未来总共能获得多少累积奖励，帮助 Agent 在没有即时反馈时做出明智决策。这里指出，过去六十年 RL 研究最重要的认识之一就是价值估计的核心地位。
5. 环境模型（可选）：预测环境对动作的响应。有环境模型的方法称为基于模型的方法（先学会预测环境怎么变化，再据此规划），没有环境模型的称为无模型方法（不去预测环境，直接从经验中学习）。

五要素里的"策略"在 LLM 场景里就是模型本身：一张查找表对应一个 LLM，"给定状态下怎么做"对应"给定对话上下文下一个 token 生成什么"。理解这个映射，后面看到"策略 $\pi_\theta$"时就不会觉得陌生。图 8-1 里 Agent 侧的"90% 最优 / 10% 随机"来自 $\varepsilon$-贪婪，它也是 8.2.2 实验 8-1 用的探索策略，明确体现了探索-利用权衡的工程折中：大部分时间利用已知的好动作，小部分时间随机试，训练过程中逐渐降低随机比例。

表 8-3 不同 Agent 系统的关键要素对比：

| Agent 类型 | 环境 | 动作空间 | 奖励信号 |
| --- | --- | --- | --- |
| 新生小羚羊 | 地形、重力、身体姿态 | 连续高维（各肌肉群收缩） | 平衡(+)、跌倒(-) |
| 扫地机器人 | 房间布局、电量 | 离散（方向、吸尘、充电） | 清洁面积(+)、电量耗尽(-) |
| 国际象棋大师 | 棋盘状态、时间限制 | 离散有限（合法走法） | 赢棋(+1)、输棋(-1) |
| 客户服务 Agent | 对话历史、知识库 | 变长组合式（思考、说话、API 调用） | 问题解决(+)、处理时间(-) |
| 代码助手 Agent | 需求文档、代码库 | 变长组合式（思考、搜索、编辑、执行） | 测试通过(+)、引入 bug(-) |

这里从表中读出的重要现象是：棋类、Atari 等典型环境使用预定义的有限离散原始动作，机器人控制则使用维度和物理边界确定的连续动作；基于 LLM 的客户服务与代码 Agent 用有限的 token 和工具调用组合出变长动作序列，因此很难一次性枚举所有可能序列，并且可以利用"内部思考"提升能力。

还有几组概念不能混。奖励（reward）与累积奖励（return/累积回报）不同：奖励是环境每一步给的即时标量，累积奖励是把后续所有奖励按 $\gamma$ 折扣后加起来的目标。价值函数与奖励函数也不同：奖励由环境给定，价值是 Agent 估计出来的，在迷宫例子里，价值函数回答的是"站在那里未来能赚多少"，不是"站在那里立刻得多少"。基于模型与无模型的区别只在于有没有显式学一个环境模型，与模型大小无关，LLM 也可以是无模型 RL 的策略网络。

> Agent 每一步"看状态→选动作"，环境回"新状态 + 奖励"，这一串记录叫轨迹；RL 的难点在于奖励往往延迟出现，所以要靠价值函数做功劳分配，并时刻权衡探索与利用。

### 8.2.2 两种动作表示：经典RL 设置与LLM 的变长策略

这里要比较的两类设置，最显眼的差异落在动作的表示方式上。MDP 本身可以表示有限、无限、离散或连续的动作空间，本节挑的例子各有归属：棋类与 Atari 用有限离散的原始动作，机器人控制用有界连续动作，LLM 策略则拿有限 token 词表和工具 schema 拼出变长序列。这种组合式表示会牵动算法设计、样本效率和泛化方式。

## 基础示例：MDP 与表格 Q-learning

这一节的小标题没有编号，内容按这里顺序讲下来。

MDP（Markov Decision Process，马尔可夫决策过程）是强化学习的数学框架，它定义状态、动作、奖励这些核心要素，整个框架立在一条核心假设上，也就是马尔可夫性质：未来只取决于当前状态，而当前状态必须包含决策所需的全部历史信息。

国际象棋是个好例子。状态不能只写棋子位置，还得包括轮到哪方、王车易位权、吃过路兵权，以及五十步规则和重复局面判定所需的信息。状态定义充分时，无需每次重读完整棋谱；反过来，如果观测没有包含必要历史，就该把历史纳入状态，或者改用部分可观测模型。

> 示意图：图中有 5 个房间节点，按路径串联：入口大厅 →（边上标"东/拿钥匙"）→ 储藏室 →（边上标"北(有钥匙)"）→ 北部走廊 →（边上标"北→西"）→ 守卫房间 →（边上标"东"）→ 宝藏室；守卫房间一侧另有"攻击(银剑)"这一动作路径通向宝藏室，并标注奖励 $R=+100$。图底部给出 MDP 五元组与具体取值：
>
> $$M = (\mathcal{S}, \mathcal{A}, P, R, \gamma)$$
>
> $\mathcal{S}=5$ 个状态；$\mathcal{A}=\{\text{东},\text{西},\text{南},\text{北},\text{拿},\text{攻击},\text{合成}\}$；$P(s'\mid s,a)=$ 确定性（即给定状态和动作，下一个状态唯一确定）；$\gamma = 0.99$。
>

本节讨论的典型 RL 环境使用预先定义的动作空间：围棋 361 个落子位置虽大但有限，国际象棋动作仍可枚举，Atari 游戏通常只有几个到十几个离散原始动作。机器人 Agent 用的是连续但有界的动作空间，关节角度、速度、抓取力度都是连续值，但有明确物理边界，维度由机器人自由度决定。

算法选择跟着动作空间走。有限离散动作便于逐一评估候选；状态与动作数足够小时，表格 Q-learning 可以直接存储价值；更大的 Atari 或棋类状态空间，就需要把函数近似与搜索结合起来。连续动作 MDP 不能枚举所有动作，通常用策略梯度或 actor-critic 这类方法近似策略与价值函数。这里还差一处差异没提：经典示例没有预训练知识，只从试错开始学习。

在这个框架下，最基础也最重要的算法之一是 Q-learning。它为每个「状态-动作」组合维护一个价值估计：在状态 $s$ 下采取动作 $a$，之后一直按最优策略行动，总共能拿到多少奖励？直觉上，一个动作好不好，取决于它带来的即时回报，再加上它把你带到的下一个状态有多好。

把这个直觉写成等式，就是 RL 教科书里那个贝尔曼方程（Bellman equation）的核心递归关系：一个动作的真实价值，等于这一步拿到的即时奖励加上到达下一个状态后能拿到的最大未来价值：

$$
Q^*(s, a) = r + \gamma \max_{a'} Q^*(s', a')
$$

其中 $r$ 是即时奖励，$s'$ 是执行动作后到达的下一个状态（这里说明：这里为直觉起见写成确定性形式，随机环境下需对下一个状态 $s'$ 取期望），$\gamma \in [0, 1)$ 是折扣因子，它决定 Agent 有多看重未来：$\gamma$ 越接近 1 越重视长期回报，越接近 0 越只顾眼前。前文反复出现的「累积奖励」，正是各步奖励按 $\gamma$ 逐步折扣后的总和：

$$
\sum_t \gamma^t r_t
$$

逐个符号拆开看会更清楚。$Q^*(s,a)$ 指的是在状态 $s$ 下先执行 $a$、之后一直按最优策略行动能拿到的折扣累积奖励；$r$ 是执行 $a$ 后环境立刻给的奖励；$s'$ 是转移到的下一个状态；$\max_{a'}$ 表示到了 $s'$ 之后挑最好的动作；$\gamma$ 就是折扣因子。一句话，现在这一步的收益，加上未来最好情况打了折的价值。

算法每次行动后，把旧的估计值往「实际发生的结果」方向微调一点。这种用一步实际结果修正旧估计的范式叫时序差分学习（Temporal-Difference Learning, TD learning），经过成千上万次试错，估计值逐渐逼近真实值。再拆一层符号：$\alpha$ 是学习率（步长）；方括号里的 $r + \gamma \max_{a'} Q(s',a')$ 是 TD 目标，也就是用实际发生的一步结果构造出来的、比旧估计更"新"的价值，减去 $Q(s,a)$ 得到 TD 误差；乘上 $\alpha$ 后加回旧值，就是朝目标挪一小步。

> 示意图：这是一个 5×5 的网格世界，格子内标注该状态下最优动作的方向箭头与对应的 Q 值，越靠近右下角的宝藏，数值越高。这里提取出的 22 个"（方向，数值）"对依次为：(→, 0.12)、(→, 0.25)、(→, 0.41)、(→, 0.63)、(↓, 0.85)、(↑, 0.08)、墙、(→, 0.38)、墙、(↓, 0.90)、(↑, 0.05)、(→, 0.10)、(→, 0.30)、(↓, 0.55)、(↓, 0.93)、(↑, 0.02)、(→, 0.06)、(→, 0.20)、(↓, 0.70)、(↓, 0.96)、(↑, 0.00)、(→, 0.03)、(→, 0.15)、(→, 0.80)，最后是宝藏（$V=1.00$）；另有 2 格为墙。按"22 格 + 2 格墙 + 1 格宝藏 = 25 = 5×5"以及"数值向宝藏递增"的规律，这里把网格还原为下面这张表：

>
> $$Q(s,a) \leftarrow Q(s,a) + \alpha\left[\,r + \gamma \max_{a'} Q(s',a') - Q(s,a)\,\right]$$
>
> 并在式子下面标注"TD 目标"（即 $r + \gamma \max_{a'} Q(s',a')$）与"当前估计"（即 $Q(s,a)$）分别指代哪一部分。下半部分是一个具体示例：Agent 在储藏室拿起红钥匙。
>
> | 量 | 取值 |
> | --- | --- |
> | 当前状态 $s$ | 储藏室（持有：空） |
> | 动作 $a$ | 拿红钥匙 |
> | 奖励 $r$ | $+5$ |
> | 新状态 $s'$ | 储藏室（持有：红钥匙） |
> | $\max_{a'} Q(s',a')$ | $0.63$（向北开门） |
>

>
> $$Q(\text{储藏室}, \text{拿钥匙}) \leftarrow 0.25 + 0.2 \times [5 + 0.99 \times 0.63 - 0.25]$$
> $$= 0.25 + 0.2 \times [5.624 - 0.25] = 0.25 + 1.075 = 1.325$$
>
> 并标注 TD 误差 = 5.374 → 正向更新：Q 值大幅上升、奖励向前传播。

把这几个数字按顺序验算一遍：$0.99 \times 0.63 = 0.6237 \approx 0.624$，加 5 得 $5.624$，与这里括号内的数值一致；$5.624 - 0.25 = 5.374$，这就是这里标的 TD 误差；$0.2 \times 5.374 = 1.0748 \approx 1.075$；$0.25 + 1.075 = 1.325$，即更新后的 $Q$。四步合起来说明一件事：在储藏室拿钥匙这一步的旧估计只有 0.25，可实际拿到了 +5 的奖励，估计值于是被一次性推高到 1.325。这里那句"正向更新，Q 值大幅上升""奖励向前传播"，说的就是这个过程。

Q-learning 属于一种离轨策略（Off-Policy）方法：它可以用不同于目标策略的探索策略所生成的数据来学习最优策略，但仍要求充分覆盖相关状态-动作对，并满足适当的学习率与收敛条件，**它并不是对任意数据分布都能自动收敛**。在轨与离轨策略的严格定义，以及它们在 LLM 后训练中的对应关系，后文「RL 算法：从 16 次 rollout 到一次参数更新」一节会讲。

"离轨"这句为什么要带限定语？Q-learning 可以拿行为策略（比如 $\varepsilon$-贪婪）产生的数据去学最优策略，这是它相对在轨方法的样本效率优势；这里同时补了几条限制：必须充分覆盖相关状态-动作对、学习率合适、满足收敛条件。说白了，离轨不等于随便什么数据都能学。这一点是后面理解 GRPO 与 PPO 差异的伏笔。

MDP 的马尔可夫性质在实践中怎么落地，国际象棋那个例子讲得很实在。如果状态只写棋盘上的棋子位置，「该谁走」「还能不能易位」「吃过路兵权」「五十步规则计数」这些信息就丢了，马尔可夫性质不成立，策略不可能最优。这里给了两条出路：把历史纳入状态，或者用部分可观测模型。这个坑在 LLM Agent 里同样存在，上下文窗口里没写进去的历史，对策略来说等于不存在。

两组容易混的式子要分开。贝尔曼方程是真值满足的等式，描述 $Q^*$ 与自身的关系，里面没有学习率；TD 更新式是估计值的迭代更新规则，含学习率 $\alpha$，作用是逐步逼近真值。还有 $\gamma$ 与 $\alpha$：$\gamma$ 由任务定义，决定看得多远，图 8-1、8-2 取 0.99；$\alpha$ 是算法超参的学习率，决定每次更新走多快，图 8-3 取 0.2。两者不能混。

回到 Q-learning 的心跳，其实就一条式子：$Q(s,a) \leftarrow Q(s,a) + \alpha[\text{TD 目标} - Q(s,a)]$，用这一步实际拿到的奖励加上折价后的未来最好价值，去修正旧估计。

### 实验 8-1 ★：Q-learning 在寻宝游戏中的表现

为了验证 Q-learning 的特性与局限，这里设计了一个寻宝游戏环境。这个环境埋了几处关键挑战。隐藏机制要求 Agent 自行发现钥匙和门的对应关系、武器效果和物品合成规则；多步依赖要求任务靠正确的动作序列完成，最优解 11 步；稀疏奖励意味着只有关键动作和最终胜利才有显著奖励，中间大部分步骤得不到任何反馈。

Q-learning Agent 用标准参数配置，采用 $\varepsilon$-贪婪探索策略，大部分时间选当前最优动作，偶尔随机尝试，并且随着训练推进逐渐减少随机探索的比例。学习曲线展现出典型特征（这里说明：episode 指一局完整的游戏，从开局到通关或失败算作一次）：

- 前 1000 episodes：0% 胜率，Q 表仅 124 个状态，Agent 在盲目探索；
- 前 5000 episodes：依然没有稳定胜利，Q 表 133 个状态；
- 7000–8000 episodes：胜率从 34% 逐步升至 96%；
- 10000 episodes：100% 胜率，Q 表 145 个状态，找到 11 步最优解。

这四行数字的看点在于胜率曲线的形状。前 5000 局几乎毫无进展，7000–8000 局之间突然从 34% 冲到 96%，10000 局到 100%。稀疏奖励加试错搜索就是这个曲线：大量时间花在偶然走通一次上，一旦走通，价值信号才开始快速往回传播，这里用"价值信号的传播很慢，必须反复强化"概括得很准。Q 表状态数从 124 涨到 133 再到 145 也说明问题，表格 Q-learning 的"状态"是离散化后的哈希编码，只有被访问过的状态才会出现在表里，Q 表涨得慢，意味着 Agent 探索到的状态空间还很有限。

整个训练仅需不到 10 秒，仿真效率极高，代价是将近 10000 次完整尝试。这里做了对照：在游戏模拟器里，10000 轮试错只要 10 秒，代价微乎其微；搬到真实世界的 Agent 场景，每次打电话有成本、每次操作浏览器有延迟、每次错误决策可能造成不可逆后果，10000 次试错完全不可接受。使用预训练 LLM 策略的理由之一，正是它可以利用已有知识，在更少的环境交互中做出有效决策。

这里还有个容易误读的地方：训练只要 10 秒，说的是仿真成本，谈不到这个方法高效，真实的代价是近 10000 次交互。这里特意点出，现实场景里每次交互都带时间、金钱或不可逆风险成本，所以不能只看 GPU 时间。另外，"样本效率低"属于表格 Q-learning 的性质，跟 MDP 框架本身无关。这里明确把这个无先验表格 Q-learning 实验的三项局限与 MDP 数学框架区分开：简单任务也需要大量交互，样本效率低；一个环境里学到的表格值难以直接迁移到另一个环境；每个新任务都要重新探索。函数近似、迁移学习和基于模型的 RL 可以处理更复杂的状态与知识迁移，不过与预训练 LLM 相比，仍可能需要大量环境交互。

这个实验对本章很重要，它构造了一个"RL 从零学"的极端参照物。后面实验 8-2 会拿同一个寻宝游戏和 LLM Agent 对比，结果是 LLM Agent 第一局就能通关，两边的差距来自先验知识，跟算法关系不大。前面说的主线二"数据和环境比算法更重要"，在这里有个更准确的说法：先验知识比算法更重要。

无先验的表格 Q-learning 在稀疏奖励的寻宝游戏里要近 10000 局才学会 11 步通关，胜率直到 7000–8000 局之间才从 34% 跳到 96%。仿真里 10 秒的代价，放到真实世界里不可接受，这就是要用预训练 LLM 当策略的原因。

#### 基于预训练 LLM 策略的 Agent

这一处小标题同样未编号。

大语言模型在 Agent 的动作表示与初始化方式上带来了重要的实用变化。经典 RL 也可以把内部计算或信息收集建模为状态与动作；LLM 带来的实用变化在于，预训练语言策略能够用变长 token 序列表示内部计算，并且内部计算与外部行动由同一策略生成。思考 token 不直接改变外部世界，却可以提高最终行动质量。于是 Agent 的动作表示不仅包括"做什么"，还包括"想多久、想什么"。

最关键的实用创新，是把思考 token 作为特殊动作纳入策略输出空间。典型传统 RL 环境主要使用移动、攻击、拾取这类改变环境状态的原始动作（内部计算也可以在 MDP 或层级策略中建模）；在 LLM Agent 中，内部思考成为学习到的语言动作空间的核心组成部分。它不直接改变外部环境，也不立即获得环境奖励，却能在 token 成本和上下文上限内表达多种计算路径。

把思考 token 当作动作，究竟改变了什么？经典 RL 里，动作必须由环境定义，移动、攻击、拾取，Agent 的内部计算即使存在，也不会出现在动作空间里。LLM Agent 把"输出一段自然语言"本身当作动作，于是"先想三步再动手"变成了一个环境不惩罚也不奖励、却能改变后续动作分布的动作。这就是这里说的"不直接改变外部环境，也不立即获得环境奖励，但能表达多种计算路径"。

这种变长组合式动作比原始动作拥有大得多的搜索空间，很难在没有先验知识时从零学习。这里的比方是，从零开始的 Agent 就像蒙着眼睛在沙漠里找宝藏。经典环境的动作空间是"几个选项"这个级别，LLM 的动作空间是"词表大小 $V$ 的任意长度序列"这个级别。如果从零学，这个空间的探索成本高到不可行。预训练在这个空间上铺了一层先验，哪些 token 序列像"合理的推理"，绝大多数无意义路径的概率被压得很低，搜索才变得可行。

LLM 从海量文本预训练中学到了人类留下的问题解决模式：数学问题常按"识别条件→回忆公式→逐步计算"展开，编程任务常按"理解需求→设计结构→实现细节"展开。预训练策略给结构化路径更高的先验概率，显著压缩搜索空间。因此即使没有额外 RL，预训练 LLM 也能生成基本的思维链（Chain of Thought, CoT）。这些模式来自数学解题、代码注释、讨论回应等预训练语料，模型通过预测下一个 token 隐式学会"下一步思考应该长什么样"。

RL 后训练再用外部奖励教会 LLM 在特定任务中更有效地利用这些模式。这里的关键表述是：语言结构在训练里扮演的是预训练策略的先验分布（prior），并非一条单独的"内部奖励"。训练数据中一致出现的"因为要把外币换算成美元，所以先查汇率"可能具有较高初始生成概率，而"因为要换算货币，所以先查天气"这类无关路径的概率较低。RL 在这个初始分布上用真实任务奖励重新调整各条路径的概率。

这句话的分量在于，它意味着 CoT 并非靠"给思考过程发奖励"训出来的。预训练数据本身就决定了"先查汇率"比"先查天气"更可能被生成，RL 只是在这个初始分布上按任务奖励做再分配。有了这一层，两件事就有了答案：不做 RL 的基座模型也能输出 CoT；RL 无法凭空创造模型从未见过的知识结构（呼应 8.1.4）。

> 示意图：一张左"经典 RL Agent"、右"LLM Agent"的逐项对照图，共 7 行：

| 对比维度 | 经典 RL Agent | LLM Agent |
| --- | --- | --- |
| 动作空间 | 封闭有限：{东, 西, 南, 北, 拿, 攻击} | 开放无限：自然语言 + 工具调用 |
| 先验知识 | 零先验，从随机策略开始 | 海量预训练知识 + 语言游戏规则 |

预训练语言策略使 LLM Agent 能够理解未见过的指令（零样本泛化），并用少量示范适应新任务（少样本适应），这跟前面无先验知识的表格 Q-learning 设置形成鲜明对比。

从预定义原始动作扩展到变长组合式动作，是 AI Agent 范式的重要转变。LLM 的动作仍由有限 token 词表和工具 schema 定义，但内部思考、自然语言查询、程序代码、复杂 JSON 与多模态内容可以组合成数量爆炸的变长序列。代码解释器和搜索工具把这种表示连接到现实环境中的广泛任务与信息。新的机会与挑战同时出现：Agent 可以组合基础工具处理未见任务，也需要在巨大的组合空间里定义奖励并高效探索。

这里拿两个模型举例。以 Kimi K3 这类面向工具调用和长链思考优化的模型为例，LLM+RL 范式的典型方向是：在大规模语言预训练基础上，通过后训练强化问题分解、工具调用和自我纠错能力。OpenVLA（详见第六章）展示的则是 LLM 时代的 VLA（视觉-语言-动作）架构范式：视觉编码器处理环境观察、语言模型理解指令并推理、动作解码器生成控制信号，实现语言条件控制与跨任务泛化。

这里还专门澄清了一处容易搞错的地方：OpenVLA 本身是在近百万条机器人演示轨迹上通过模仿学习（行为克隆）训练的，属于 SFT 性质，**它不是 RL 训练出来的 VLA**；真正把 RL 引入机器人、在这类 VLA 架构之上用奖励进一步优化的代表，是本章后面实验 8-13 的 SimpleVLA-RL。（脚注 1：Kim, Moo Jin et al., "OpenVLA: An Open-Source Vision-Language-Action Model", 2024. arXiv:2406.09246）

> 来源确认：补充：所引 OpenVLA 的 arXiv 编号 2406.09246 对应论文题名 "OpenVLA: An Open-Source Vision-Language-Action Model"（2024），首这里姓 Kim，与补充：一致。（来源：[OpenVLA: An Open-Source Vision-Language-Action Model](https://scixplorer.org/abs/2024arXiv240609246K/abstract#main-content)）

二手材料里常把"VLA + 机器人"直接说成 RL 训练，这里明确纠正了这一点，并指出真正做"VLA + RL"的是实验 8-13 的 SimpleVLA-RL。

姚顺雨在博客《The Second Half》中回顾了 OpenAI 探索之路的认知演变（脚注 2：姚顺雨（Shunyu Yao），"The Second Half"，2025 年 4 月 10 日）：

- 第一阶段（2015–2016）算法中心主义：相信更好的算法才是关键，在 Atari 等标准环境取得进展，但换一个新环境就得从头训练。
- 第二阶段（2016–2018）环境的重要性：Gym 标准化了各类任务，Universe 和 World of Bits 试图把整个互联网变成 RL 的训练环境，Dota 2 在特定复杂环境中追求超人表现。思路很清晰，但通用计算机使用和网页导航始终无法突破。
- 第三阶段（2018 至今）先验的觉醒：GPT-2/GPT-3 展示了语言预训练的强大力量，WebGPT、ChatGPT 证明这些先验知识可以转化为实用 Agent。最重要的发现是，先验知识可以通过与 RL 完全无关的方式获得。
- 这里的总结判断：这是一个反直觉的真相，几十年来 RL 研究者的优先级可能完全颠倒了，"不是'算法 > 环境 > 先验'，而是'先验 > 环境 > 算法'"。

"先验 > 环境 > 算法"放到工程上怎么用？如果你的 Agent 表现不好，先检查的是基座模型的先验够不够、环境与奖励是否可信，换 RL 算法该排在后面。这与主线二完全一致。

还有三组容易混的说法。CoT 并非 RL 教出来的，这里说即使没有额外 RL，预训练 LLM 也能生成基本 CoT，RL 的作用是在已有先验上重新分配概率。动作空间"开放无限"是相对说法，LLM 的动作仍由有限 token 词表和工具 schema 定义，只是组合出的序列数量爆炸，不等于真的无限。SFT 性质的 VLA 与 RL 训练的 VLA 也要分开，OpenVLA 是模仿学习（行为克隆），SimpleVLA-RL 才是引入 RL 的代表。

LLM Agent 相对经典 RL 的关键变化有两个：动作从"预定义原始动作"变成"变长 token 序列（含思考）"，策略初始化从随机变成"带海量语言先验"。先验把搜索空间压小，这才让 RL 在语言动作空间里可行。

#### 实验 8-2 ★★：传统 RL 与 LLM Agent 的对比研究

通关过程这里分三段描述。前期是有目的的探索：拿起生锈的剑（"武器总比空手好"），系统探索地图，发现北门被锁后推理"需要找钥匙"，转而探索储藏室，先后取得红钥匙与魔法水晶。中期是机制理解与主动合成：理解"钥匙自动使用"规则，并预判生锈的剑不足以对付守卫，于是在第 8 步主动合成银剑。后期是执行与纠错：持银剑向北，第 13 步击败强守卫，其间夹杂一两步无效尝试（重复挥剑或回退），最终在第 18 步取得巨龙宝藏。

三段各自的对应能力值得体会。前期对应探索与信息收集，它先拿武器降低风险，再系统探索，遇到锁门后推理出"需要钥匙"这个子目标，这是任务分解。中期对应世界模型与前瞻，它推断出生锈的剑打不过守卫，于是主动合成银剑，甚至理解了"钥匙自动使用"这条隐式规则；这一步是第 8 步做的准备，为第 13 步的战斗服务。后期对应执行与纠错，中间有一两步无效尝试，说明它不是完美的，但能从环境反馈里恢复，这正是 8.1.5 说的"在当前策略实际访问的状态上训练/推理"的朴素版本。

这里的解读是，这展现了语义理解与符号映射之间的根本差异。LLM Agent 理解了游戏的概念结构，每一步都有目的和逻辑支撑；对 Q-learning 来说，"门""钥匙""剑"只是无意义的符号组合，只能通过大量统计学习慢慢发现它们之间的关系。换成哈希表的说法，这些词对 Q-learning 只是 ID，对 LLM 来说"钥匙能开门""银剑能杀守卫"是语言预训练里就有的概念关系。前者要靠统计慢慢发现关系，后者开局就带着关系。

计算成本上有个悖论：Q-learning 跑 10000 局只需 10 秒，LLM Agent 一局却要 1–2 分钟。但现实任务中每次交互的时间、金钱和风险成本远超纯计算成本，单看 GPU 时间并不公平。如果只比较"找出一条通关路径"这一步，Q-learning 更便宜；把建模成本、交互成本、规则变化后的重训成本都算进去，LLM Agent 往往更划算。这个视角在工业界很实用：环境可以无限免费重放时传统 RL 仍有位置，每次交互都有代价时先验更重要。

两个容易混的点得说清。"样本效率高"不等于"计算成本低"，LLM Agent 1 局通关但每局要 1–2 分钟，Q-learning 只要 10 秒却能跑 10000 局，这里比较的是交互次数，不是 GPU 时间，两者结论相反，不要混用。"经验缓冲区"也不等于参数更新，实验里的 LLM Agent 维护最多 50 条经验的缓冲区，**这是上下文内适应（in-context），并没有把经验写进权重**；本章的主线（后训练）才是改参数。

更关键的洞察在于，LLM Agent 能赢靠的是携带海量先验知识，它的"学习算法"本身并不比 Q-learning 高明。游戏规则变化时，Q-learning 需要完全重新训练，LLM Agent 却能通过推理直接适应。由此得出实用的设计原则：在仿真成本低、可大量重复的场景中，传统 RL 仍然有价值；在交互成本高、需快速适应的现实场景中，LLM Agent 的样本效率更为实际。

不过这组结论不宜推广过头。这里说的是"本章实验中"的对比，Q-learning 只是一个无先验的表格方法参照物，现代深度 RL（函数近似、迁移学习、基于模型的 RL）在不少任务上仍然很强。

同一款寻宝游戏，Q-learning 要 ~7000 局才首次通关（最终 100% 胜率，10 秒 / 10K 局），LLM Agent 第 1 局就通关（~90% 即时胜率，1–2 分钟 / 局）。差别来自是否携带海量先验知识。

至于上下文适应、外部产物更新与参数更新如何协同，第一章已经给出概念地图，本章末尾的"完整图景"还会回到这个话题。本章的主线是其中的后训练，也就是把难以由外部规则完整表达的能力写进模型参数。

## 8.3 模型预训练基础 [可选阅读]

要理解后面的训练技术为什么有效，得先知道预训练建立了什么。这里在这一节开头的核心论断是：**SFT 与 RL 本质上是在基础模型已有的表征空间内做优化**，预训练奠定的知识结构决定了后续阶段的上限。落到工程上，SFT 和 RL 干的是在已有表征空间里挑路，造路这一步在预训练阶段就做完了。所以当你发现无论怎么调 SFT 数据都学不会某件事时，问题多半出在基座上，那里压根没有对应的表示（诊断方法回到 8.1.4 的 pass@k）。

本节用两个实验考察预训练的核心环节：从头训练一个小规模语言模型，以及扩展视觉能力。这里明说这两个实验属于辅助性内容，作用是帮读者建立对预训练（Pretraining，在大规模数据上做初始训练，让模型学会语言的基本规律和世界知识）的直觉；而在已有基础模型上注入新语言知识的实验 8-5，被放进了紧随其后的 Mid-training 独立小节。

图 8-8 是这条路径的最小图示：

> 示意图：一条从左到右的流程。左侧是输入文本，示例开头为"Agent 需要在真实环境中执行任务……"，中间是模型输出的概率分布 $P(x_t \mid x_{<t})$，候选词依次为"中"（42%）、"里"（28%）、"下"（15%）、……（15%）。下方给出损失：
>
> $$\text{损失} = -\sum \log P(x_t \mid x_1 \ldots x_{t-1}) \;\to\; \text{最小化交叉熵}$$
>
> 图底部一句总结："看似简单的目标驱动模型学习：语言规律 → 世界知识 → 基本推理"。

词元化那一段常被跳过，但它解释了损失公式为什么长这样。语言模型的训练一般走"词元化—预训练（含按需 Mid-training）—后训练"这条流程。词元化（Tokenization）把文本切成离散单元，"我喜欢编程"可能被切成"我""喜欢""编程"三个 token，这些 token 就是模型处理文本的最小单位。正因为模型处理的单位是 token，"预测下一个词"就变成对词表的一次分类，损失自然是对每个位置的负对数似然求和，也就是图 8-8 里那条式子：$x_1 \ldots x_{t-1}$ 是前文（上下文），$x_t$ 是待预测的下一个 token。这里把这条式子标成"最小化交叉熵"，交叉熵衡量的是真实分布与预测分布之间的差距，逐 token 累加。

预训练的任务在概念上简单得离谱：给模型看一段文本的前半部分，让它预测下一个 token。模型比较自己的预测与正确答案的差距，这个差距叫损失（Loss），损失越小说明预测越准，然后它按这个差距不断调整自身参数。在海量文本上反复做这件事，模型逐渐学会了语言规律、世界知识与基本推理能力。

图 8-8 里那个分布值得多看一眼。给定前文，模型给出"中 42%、里 28%、下 15%……"这样的概率分布，训练做的事就是把真实那个 token 的概率往上推。这正是 8.1.1 说的"训练就是调整概率分布"的图形化版本。

预训练做完，模型能生成流畅文本，但输出缺乏结构，也难遵循指令。后训练用 SFT（拿标注好的输入—输出对训练）和偏好优化（如 DPO，让模型学会生成人类更偏好的回答）把它转成实用助手。

## 实验 8-3 ★★：从头训练 LLM——算法改进的威力

案例是 MiniMind 2（一亿参数），在消费级 GPU 上跑完了完整训练流程。引入两项算法优化（QK Norm 和 Muon 优化器）之后，收敛速度提升 3 倍，生成质量也明显改善。成本是这个实验最反直觉的地方：总训练约 14 小时，花费约 34 美元。

各阶段的效果变化很清楚。预训练后，模型可以回答"世界上最高的山峰"这类事实性问题，但格式不规范；SFT 之后，指令遵循与输出格式显著改善，能按期望方式组织答案；再做偏好优化，事实错误与不自然表达进一步减少。

局限也摆在那里，一亿参数的模型在复杂问题上容易出错。这里从这个实验里得到的启示是，在固定的小规模预算下，算法改进比单纯堆规模更具性价比。这条经验对中小团队很实用：先用小模型把配方跑通，再放大。

### 实验 8-4 ★★：自己训练 VLM

图 8-9 给出了视觉语言模型（VLM）的架构：

> 示意图：从左到右三个组件加一条训练策略。① 视觉编码器（CLIP ViT）：参数固定（不训练），输入 224×224 图像，输出 196 个视觉 token，维度 768。② 投影层（全连接）：唯一从头训练的部分，做 Linear(768, 512)，作用是"对齐视觉→语言空间"，参数量 ~400K。③ 语言模型（MiniMind 100M）：SFT 阶段解冻，hidden_dim=512，自回归生成描述，并使用 Muon 优化器加速 3×。流程下方标注：输入图像（瀑布/城市/自然）→ 输出描述"巨大的瀑布旁悬挂着彩虹"。图底部的训练策略是："冻结 LLM + 训练投影层 → SFT 解冻 LLM（避免灾难性遗忘）"。

VLM 把视觉感知与语言理解放进同一个模型，核心挑战在跨模态对齐，也就是让"看到的"和"说出来的"对应起来。架构由三块构成：视觉编码器（如 CLIP，参数固定）提取图像的语义特征；投影层是轻量级的那一块，也是唯一从头训练的部分，它充当视觉特征与语言模型之间的翻译官，把视觉特征映射到语言模型能理解的表示空间；语言模型负责生成描述文本。

训练顺序是这一节最值得记住的工程细节：先冻结 LLM 只训投影层，再解冻 LLM 做 SFT。为什么必须分两步？刚初始化时投影层输出的向量对 LLM 来说完全是噪声，这时候就解冻 LLM，LLM 会被噪声梯度带偏，也就是**灾难性遗忘**；等投影层学会了把视觉特征翻译成 LLM 认识的语言空间向量，再解冻 LLM 用高质量图文对做 SFT，LLM 只需要学习如何利用已经对齐好的视觉信息，改动小得多。这里把这个策略的目的写得很直白：避免灾难性遗忘（Catastrophic Forgetting，即学了新技能后把旧技能忘了）。解冻之后描述的详细程度与准确性显著改善。

这也揭示了预训练实验的一个范式：复用单模态预训练成果，通过训练一个轻量投影层实现跨模态对齐，高效且可扩展。代价是投影层的表达能力有限，一个 400K 参数的 Linear(768, 512) 要承载全部视觉语义的转换，容量不够时就会成为跨模态深层理解的瓶颈。如果任务需要细粒度视觉理解（数数、读小字、空间关系推理），单层投影往往不够用，这也是后续多模态架构不断加大视觉-语言连接器、甚至直接做跨模态注意力的原因。同样的"视觉编码器 + 投影层 + LLM"骨架再往前延伸一步、让模型输出动作，就是第六章介绍的 VLA（视觉-语言-动作）模型。

两个预训练实验共同揭示的规律有三条。预算受限时，算法改进与架构创新比单纯扩大规模更具性价比。更关键的是，预训练赋予模型的是描述性知识与语言建模能力，缺乏结构化的指令遵循和任务导向行为。还有一条容易被忽略：如果通用预训练本身没有覆盖目标语言或领域，直接进入 SFT/RL 也绕不过这个缺口，这正是 Mid-training 要解决的问题。

几个定义别弄混。词元化（Tokenization）只是把文本切成 token 的预处理步骤，预训练才是"在海量数据上做初始训练"，两者不是一回事。预训练产出的是能续写的博学者，后训练（SFT + 偏好优化）才把它变成能听话的助手。至于"冻结"与"解冻"的顺序，反过来的代价就是灾难性遗忘。

## 8.4 Mid-training：补知识与基础能力

本章所说的 Mid-training，是从已有基础模型出发，在目标数据分布上继续开展一个阶段的语言模型训练。它通常仍采用与预训练相同的"预测下一个词"任务，对文档、代码或推导的全部 token 计算损失。名称里的"Mid"描述的是它在能力开发流水线中的位置，数据格式和损失函数与预训练相同。

这条路线不是新发明。经典的 DAPT/TAPT 研究已经表明，在领域语料或任务相关的无标注语料上做第二阶段预训练，可以继续改善下游任务表现（脚注 3：Gururangan, Suchin et al., "Don't Stop Pretraining: Adapt Language Models to Domains and Tasks", ACL, 2020）。

> 来源确认：该脚注所指论文即 "Don't Stop Pretraining: Adapt Language Models to Domains and Tasks"（Gururangan et al., ACL 2020），其预印本编号为 arXiv:2004.10964，与这里、会议、年份一致。（来源：[Don't Stop Pretraining: Adapt Language Models to Domains and Tasks](https://arxiv.org/abs/2004.10964)）

Mid-training 主要解决两类缺口。一类是知识缺口：通用预训练没有充分覆盖目标语言，或者没覆盖金融、医疗、法律领域、企业内部文档、某类代码库，模型连概念与术语都不能理解。另一类是基础能力缺口：目标任务要求基础模型尚未形成的长上下文、代码模式、数学推导或跨模态表征，此时问题已经超出回答格式不对的范围，在足够多次采样下模型也几乎得不到正确解。后者的症状更接近 8.1.4 里"pass@k 接近 0"的判据，也提示你多给几个示范解决不了问题。

这两类缺口也说明了为什么不该把 SFT 当成主要的知识注入工具。SFT 当然可以记住少量事实，也常被放在 Mid-training 之后教模型如何回答领域问题；但少量 QA 对只覆盖有限问法，更擅长训练"如何访问与表达"，不适合承载大规模、相互关联的原始知识。

反过来，Mid-training 降低了领域文本的语言模型损失，也不保证模型会自动按用户问题取出知识。已有研究发现，继续预训练与指令训练的顺序和数据组织会显著影响知识能否被问答形式访问（脚注 4：Jiang, Zhengbao et al., "Instruction-tuned Language Models are Better Knowledge Learners", ACL, 2024）。所以"降低损失 ≠ 会答题"是这一节最该记住的一句话：把知识存进参数和能在被问到时取出来是两件事，先做指令训练再做继续预训练，和反过来做，效果可能不同。

这里给出的稳健配方是一条三步顺序：通常先用 Mid-training 吸收知识与能力，再用小规模 SFT 建立输出格式，等有了非零成功率再上 RL 提升成功率和泛化性。落到具体选型上，用户的问题需要频繁更新事实（比如今天的产品价格）就用 RAG；稳定的领域体系（医学指南、公司协议这类）走 Mid-training；只是想让模型按固定格式作答，SFT 就够了。

几个名字要能对上号。有些团队把 Mid-training 称为继续预训练（CPT）、领域自适应预训练（DAPT）或任务自适应预训练（TAPT），它们是同一件事的不同叫法或细分。损失函数相同也不代表目的相同，Mid-training 与预训练用同一个损失，但目的从建立通用表征变成了把目标分布写进参数。

### 8.4.1 Mid-training 数据如何构造

这里给出五步构造法。

第一步，从失败分布反推数据。先按主题、语言、文档类型、代码模式与上下文长度切分评估，确认低 pass@k 来自哪类底座缺口，再只针对知识和能力缺口补数据，避免把输出格式错误误诊成知识不足。

第二步，构造高密度目标语料。原始文档适合建立术语和事实关联，代码仓库适合学习结构与依赖，教材式推导、合成释义和跨文档关联样本适合把隐含关系写得更明确。数据还要做去重、质量过滤和评估集污染检查。

第三步，按能力进行数据配比。数据里需要包括三类：自然长文本（书籍、长文档和代码仓库等）；长文本原子能力的思维链数据，体现长文本检索、多跳推理、指令遵循、信息聚合与统计等能力；Agent 必需能力的 Agent 执行轨迹，体现规划、工具选择与调用、长程状态跟踪和错误恢复等能力。思维链和 Agent 执行轨迹这两类可以从较强的开源模型蒸馏，也可以使用现有数据集。

第四步，在每个阶段做"双重回放"。一类回放的是原始短文本和通用数据，用来保留语言、知识与短上下文能力；另一类回放的是"长度提升后的旧任务"，把模型已经会做的短任务放进当前长度的上下文，在不同位置加入相关信息和干扰项，检验同一能力在更长窗口中是否仍然成立。通用数据最好来自基模的原始预训练集，无法取得时可以用 FineWeb-2 等开源预训练语料替代。

第五步，用多维门禁决定何时停止。除训练 loss 外，同时跟踪留出领域任务、通用能力、原有指令遵循和目标任务的 pass@1/pass@k。领域指标上升而通用保留集下降，说明混合或学习率过激；loss 下降而 pass@k 不动，则要检查数据是否真正覆盖所需能力，以及后续是否缺少访问知识的 SFT。

第 1 步是整套流程的灵魂，它要求先把评估做细，再决定喂什么数据：按主题、语言、文档类型、代码模式、上下文长度切分，看清楚低 pass@k 到底出现在哪一类上。这样补进去的数据才是针对缺口的，而不是把通用语料再灌一遍。这里特意加了一句"避免把输出格式错误误诊成知识不足"，这正是最常见的误诊：模型答得乱七八糟，团队以为它不懂，于是猛灌领域文档，其实它只是不会按格式输出，该做的是 SFT。

第 4 步的双重回放是很多人会漏掉的工程细节。混通用与短文本数据那一路是在防遗忘；把旧任务放进长上下文、并在不同位置插入相关信息与干扰项那一路，检验的是能力在更长窗口下是否仍然成立。上下文变长之后，模型会出现"中间信息丢失"这类失效，短任务做得好不代表长上下文里做得好。这是一个可执行的测试设计，不是泛泛的建议。

第 5 步的门禁把"什么算训练到位"讲清楚了，两条对照关系值得背下来。领域涨、通用掉，说明混合比例或学习率太激进（回放数据不够或步长太大）；loss 掉、pass@k 不动，说明数据没有覆盖到能力，或者缺"访问知识的 SFT"。第二条尤其反直觉，loss 下降是必要而不充分的，这和 8.4 正文那句"降低损失 ≠ 会答题"是一件事。

依赖链要按这里记：长上下文能力 → 长思维链能力和指令遵循能力 → Agent 工具调用等多项高阶能力。长上下文基础能力一旦退化，后面所有高阶能力都会跟着塌。这里因此给了明确的验证要求，Mid-training 后需要用 LongBench v2、IFEval、第七章所述的端到端 Agent 等评估数据集，验证模型在不同上下文长度下的长上下文基础能力没有丢失。

这里列出的长上下文原子能力清单覆盖六类：位置与检索（单针、多针、不同位置的关键信息提取）；关系与推理（跨段落、多文档、多跳关系追踪，矛盾消解和证据组合）；聚合与统计（从长表格或长日志中汇总信息，如计数、分组、排序、比较、趋势归纳）；指令遵循（复杂指令的遵循能力，包括多指令遵循、矛盾消解、思考流程遵循、输出格式遵循等）；长链思考（解决复杂的数学、逻辑推理、代码生成问题）；Agent 原子能力（任务分解、计划生成、工具选择、参数构造、状态记忆和失败后的恢复）。

RAG 与 Mid-training 的分工也在这节给了：事实需要频繁更新或必须给出原始出处时，RAG 仍优于把知识写进权重；Mid-training 更适合稳定、规模较大、需要形成内部表征的领域知识与能力。风险提示同样明确，对大模型做全参数 Mid-training，计算和遗忘风险都明显高于小规模 SFT，所以要先用小规模实验验证数据配比，再扩大训练预算。

#### 实验 8-5 ★★：继续预训练学习新语言

基础模型选的是 Mistral 7B v0.3，它主要用英语预训练，对韩语几乎没有理解能力，实验用韩语维基百科继续预训练来注入韩语能力。这里的关键在于成本：在已完成预训练的模型上用新语言数据继续做语言模型训练，模型已具备通用表征，只需适应新的数据分布，成本远低于从头训练。

数据配比是约 80% 韩语 + 20% 英语，用来缓解灾难性遗忘，这里特别声明这只是该实验的选择，不是通用默认值。随后用韩语指令数据做 SFT，得到实用的韩语对话能力。这里对分工的总结是：Mid-training 先补韩语知识与语言能力，SFT 再教模型如何用韩语接受指令和组织回答。

实验也暴露了继续预训练的代价，韩语最终阶段的盲评分改善，英语能力却有下降。继续预训练可以把目标分布写进参数，但免不掉保留集、事实评估和数据质量审计。本节收尾那句是：具备足够的知识与基础能力后，才能使用下面的 SFT、RL 等后训练方法构建实用的 Agent。

"双重回放"里的回放有两种含义，通用数据回放用于防遗忘，长上下文下的旧任务回放用于验能力留存，只记住前者会漏掉一半。训练 loss 下降也不等于任务成功率上升，第 5 步明确把二者分开看，loss 掉了但 pass@k 不动，要到"数据覆盖"和"后续 SFT"上找原因。至于那个 80% 韩语 + 20% 英语，这里专门做了免责说明，它是一次实验选择，不是可以照抄的通用配比。

## 8.5 SFT（监督微调）

图 8-10 是这一节的骨架：

> 示意图：一条三段式流水线，外加一个"协议类型"清单。
>
> ① 数据准备：输入-输出对 $(x, y)$；并列举三类来源，语音为参考音频 → 风格 token，蒸馏为教师输出 → 学生目标，多语言为思考模板示范。
>
> ② 训练优化：损失
>
> $$L = -\sum \log P(y_i \mid x_i)$$
>
> 目标是"最大化条件对数似然"；规模为"数千~数万条样例"，耗时"数小时收敛"。
>
> ③ 效果评估：格式遵循 ✓、指令理解 ✓、风格一致 ✓、分布外泛化 ✗。
>
> ④ SFT 固化的"协议"类型（四类）：语音 SFT → 风格控制协议（音色 + 副语言标记）；多语言 SFT → 思考组织模板（"分析→假设→验证→总结"）；Prompt 蒸馏 → 教师输出映射（长提示 → 无提示直接输出）；工具调用 SFT → 接口格式协议（JSON schema + 错误处理）。
>
> 关于损失写法：这里图中记为 $L = -\sum \log P(y_i \mid x_i)$，其中 $i$ 为样本下标，$x_i$ 是该样本的输入（问题），$y_i$ 是标注回答。这是样本级的写法：$P(y_i \mid x_i)$ 本身是回答各 token 条件概率的连乘，取对数后即展开为逐 token 的负对数似然之和，所以它与"逐 token 计算"是同一个损失，不是两种算法；这里按。

这里说明，"四阶段全景"一节已经讲了 SFT 的本质（换了数据、只在回答上算损失的"预测下一个词"），这一节用四个实验，看这套"把稳定映射与协议写进参数"的机制在不同任务上具体固化了什么。

SFT 固化的是输出格式：把映射关系、交互格式、风格规范写入参数，使推理时无需冗长提示即可产出符合预期的输出。代价是高效率可能以依赖训练分布为代价，在需要探索多种正确策略、或部署分布偏离示范数据的任务中，SFT 容易偏向复现示范模式，在新场景中性能下降。

数据从哪来，工业界的答案基本就三条路。人工专家示范的质量天花板最高，但贵且慢，适合用来定义格式与风格的种子数据；教师模型生成就是合成数据，让强模型批量产出"输入—输出"对，过滤后再蒸馏给学生，详见实验 8-8、8-9；拒绝采样让模型自己对同一问题采样多条候选，用验证器筛出正确样本再反过来训练自己，详见实验 8-9。三条路经常组合使用。无论走哪条，构造流程都大同小异：先定义任务分布与输出 schema，再批量生成候选，然后用规则校验、格式检查加人工抽检做质量过滤，再去重、平衡配比、保证多样性。

数据不必贪多。数千到数万条高质量样本通常就足以固化输出格式。与其堆十万条脏数据，不如精修一万条干净数据：数据里的每一处噪声，SFT 都可能忠实地写进参数。

### 实验 8-6 ★★★：语音 SFT——从"声音复制"到"副语言建模"［扩展实验］

对象是 Orpheus（语境提示 voice cloning）与 Sesame（副语言标记建模），展示如何把"声音风格与表达习惯"写入参数。两者的思路不同。Orpheus 把声音波形压缩为 token 序列，通过拼接同一说话者的参考音频，让模型学会"用这个人的声音说话"，实现跨句音色一致。Sesame 把笑声、叹气等副语言现象抽象为 `<laugh>`、`<sigh>` 等特殊标记，训练模型学会"看到标记就发出对应的声音"。

结论是，SFT 在表达型任务中固化的是风格控制协议与结构化表达习惯，而非事实知识或复杂思考，关键在于训练数据的多样性和标注质量。两个失败模式很典型。训练数据中说话者过少，会导致所有人听起来一个腔调，模型学到的是训练集里那几个人怎么说话，而不是如何用某个参考音色说话。标记过拟合（Overfitting，即模型死记硬背了训练样本的细节，遇到新情况反而表现更差）会产生"机械笑"：如果 `<laugh>` 在数据里总是出现在某些固定位置，模型就会在该出现和不该出现的地方都塞标记。

### 实验 8-7 ★★★：多语言思考——让模型用任意语言思考［扩展实验］

问题在于大多数思考模型只会用英语"思考"，不管你用什么语言提问，模型内部的思维链几乎都是英文的，因为训练数据中高质量的思考示范基本都是英语写的。本实验的目标很简单，让模型能够用指定的语言进行思考。

做法是对 gpt-oss-20b 进行 SFT，在系统指令中加一句 `reasoning language: German`（或其他语言），然后用英语、西班牙语、法语等几种语言的思考样例进行训练。发现很有意思：训练数据中完全没有中文，但训练完成后，只要把 `reasoning language` 设为 Chinese，模型就能用中文进行完整的思维链思考。这种零样本的跨语言泛化是本实验最有意思的发现。

限定条件也是最容易被误读的地方。这里专门提醒，这并非 SFT 本身的泛化能力：多语言预训练已经在模型中建立了跨语言的共享表征空间，SFT 只是激活了这种预训练时已有的跨语言能力。换句话说，SFT 只能点亮预训练已有的能力，不能凭空创造。这和 8.1.4"RL 不擅长从零创造"是同一条原理，只是主体从 RL 换成了 SFT。

### 实验 8-8 ★★：Prompt 蒸馏——以更小开销复现可用能力

动机很实际：为了让模型完成复杂任务，常常需要设计冗长的系统提示（数千甚至上万 token），每次调用都会增加延迟与费用；使用思考型大模型时，内部思考 token 进一步放大成本。思路是把"长提示 + 思考型教师"的行为压缩到"短提示/无提示 + 非思考学生"中。做法上，教师在完整提示与思考模式下生成高质量答案，训练数据只保留用户输入与最终结论，丢弃冗长提示与中间思考过程。学生因此学会直接给出结论，蒸馏后在相同输入上接近教师的输出质量，同时因为不需要处理冗长提示和思考 token，延迟与费用显著降低。

两个维度可以分别用。大到小，是用中小模型替代大模型，在成本和质量之间取得折中；思考到非思考，是同等规模下把显式 CoT 折叠为隐式参数化知识，获得 20–30 倍的响应速度提升。两者并不冲突，在生产环境中经常同时使用。

风险也要说清楚。蒸馏会继承教师的边界：教师在长尾分布上有系统性错误，学生会进一步硬编码这些错误；教师依赖工具来确保正确性时，单纯的输出蒸馏会失去工具带来的鲁棒性。这里给的工程判断是一条清晰的分界线：产品形态稳定、输入分布可预期、成本约束明显时，Prompt 蒸馏是很好的优化手段；而在探索期或任务尚未定型的阶段，保留显式思考与可编辑的提示工程仍是快速试错的核心。

### 实验 8-9 ★★★：思维链（Chain of Thought, CoT）蒸馏

这个实验与 Prompt 蒸馏的方向相反：Prompt 蒸馏丢弃思考过程，CoT 蒸馏把强教师模型的完整思考轨迹转移给学生模型。效果上，对能力较强的教师模型做 CoT 蒸馏，在同等参数量下可恢复教师 70%–80% 的能力。这里的评价是，对于不追求刷新前沿能力边界、但寻求自主可控模型的团队，这是最务实的跟随者策略。代表案例是 DeepSeek-R1 发布时同步开源的一系列蒸馏小模型，用 R1 的思考轨迹对 Qwen、Llama 系列做 SFT。

背景里有个"思维围墙"现象。一些闭源思考模型（如 OpenAI o 系列、Gemini 系列）在思考时会生成内部思维链，但用户看到的并非原始思考过程，厂商出于防蒸馏、安全和产品体验等考虑，通常会在输出前对 CoT 做改写或摘要，最有价值的原始思考过程被隐藏在 API 之后。所以这个实验选择开源思考模型作为教师：DeepSeek V4、Kimi K3、GLM 5.2 等模型直接公开完整思维链，蒸馏在技术与许可上都可行。这里提醒，使用前仍应确认模型许可证对蒸馏产物的授权条款。

实验现场发生的事很值得记下来：模型会写代码，不代表它愿意帮助你蒸馏模型。这里最初使用由 GPT-5.6-Sol 驱动的 OpenAI Codex 编写实验代码，但当任务明确涉及模型蒸馏时，Codex 拒绝继续执行；随后切换到由 Claude Opus 5 驱动的 Claude Code，也遇到了同样的拒绝；最终用 Kimi K3 完成了实验代码和后续运行。

对这两次拒绝，这里的解释是：拒绝针对的对象既不是普通数学推理，也不是简单地要求模型公开内部思维链，它落在实现一个使用强教师数据训练学生模型的完整蒸馏实验上。模型蒸馏与正常的监督微调在技术上高度相似，但在厂商的安全与产品策略中，它也可能与模型提取、能力复制和知识产权保护联系起来，因此成为一个敏感类别。这里的实用建议是，对绝大多数做后训练的人来说，根本不需要去蒸馏闭源模型的思维链：当前最先进的开源模型与 SOTA 闭源模型的差距并没有想象中大，教师模型只需要"明显高于学生"，不需要"全球第一"；如果你要后训练的是 200B 及以下规模的模型，用开源 SOTA 模型当教师已经完全够用。这句话把"要不要追最强的教师"从面子问题拉回到性价比问题。

实验设计分三步。

采集轨迹。从目标任务分布（如数学、代码）采样问题，用开源教师模型生成完整的"思考 + 答案"轨迹，并用规则验证器过滤掉最终答案错误的轨迹，否则错误的思考过程会被学生一并模仿。这里指出，这一步"生成候选—验证过滤—只留正确轨迹"的做法有个专门的名字：拒绝采样（Rejection Sampling）。用它构造的数据做 SFT，就是**拒绝采样微调**（Rejection Sampling Fine-Tuning, RFT）。RFT 介于纯 SFT 与 RL 之间：不训奖励模型、不做策略梯度，只靠"从多条采样中拒绝错的、留下对的"来提升数据质量，是可验证任务上性价比极高的数据构造手段。它本质上是用采样算力换数据质量，所以天花板就是验证器的可靠性。

SFT 训练。以"问题 → `<think>` 思考轨迹 `</think>` + 最终答案"为训练对，对小模型（如 7B 量级）做标准 SFT。

对比评估。在同一基准上对比蒸馏前后的学生模型与教师模型，衡量能力恢复比例。验收标准是蒸馏后的学生模型在数学/代码基准上相对蒸馏前显著提升，且思考轨迹中出现教师式的反思、回溯与验算行为。同时注意蒸馏的代价：学生会继承教师的系统性错误和冗长思考习惯，后者可结合实验 8-10 的 AdaptThink 思路做二次优化。

四个实验有一个共同特征，都是"把稳定的映射与协议写进参数"：语音 SFT 固化风格控制协议，多语言 SFT 固化思考组织模板，蒸馏 SFT 固化输入到输出的直接映射。目标越明确、格式越清晰、评估标准越稳定，SFT 越能以很高的样本效率提升性能。

回到选型上，Prompt 蒸馏与 CoT 蒸馏的区分很好记：前者丢弃思考过程学结论，能拿到 20–30 倍加速；后者转移思考轨迹学过程，能恢复教师 70%–80% 的能力。两者面向的是不同的成本-能力点，谈不上谁替代谁。拒绝采样与 RFT 也不等于 RL，RFT 不训奖励模型、不做策略梯度，只是筛出对的样本再做 SFT，所以它介于纯 SFT 与 RL 之间。另外，SFT 表现出的跨语言或新任务泛化要谨慎归因，实验 8-7 的跨语言能力来自预训练已有的共享表征，SFT 只是激活，同理它不会凭空创造新知识。"蒸馏会继承教师的边界"也值得写在工程规范里：教师的系统性错误会被学生进一步硬编码，教师依赖工具获得的鲁棒性，在纯输出蒸馏中会丢失。

## 8.6 SFT 数据合成：从示范到可训练轨迹

SFT 的上限由数据决定。实际项目很少能靠人工逐条写出足够多的示范，通常要把少量人工种子、教师模型生成和验证器筛选组合起来：人工示范定义格式与边界，教师模型放大规模，规则验证或人工抽检守住质量。模型自举时可以针对同一题采样多条候选，只保留验证通过的轨迹，这就是拒绝采样微调（RFT）。

合成数据的落点是把日志里可复用的任务结构提炼出来，而不是复述线上日志，任务结构包括用户意图、初始状态、可用工具、业务约束、常见失败方式和成功条件。直接拿线上日志做 SFT 有三个问题：含隐私或凭据、分布偏斜（少数高频任务占绝大多数）、以及模型会背下具体内容而不是学会任务结构。这里给的解法是把日志抽象成蓝图，再去掉身份信息，为每种任务重新生成虚构人物、订单、文件和状态，放进可重置的隔离环境。这样既保留真实难点，也避免模型记住客户数据或内部凭据。

一条稳妥的流水线是：线上数据 → 任务蓝图 → 合成任务 → 多次候选轨迹 → 任务验证与轨迹验证 → SFT 数据。任务验证检查题目本身是否可完成、难度是否合适、参考结果是否正确；轨迹验证检查最终状态、工具调用和业务约束。能写成单元测试、数据库断言或状态差异检查的条件，优先使用确定性代码；开放式的沟通质量再由模型评价器补充，并用人工抽样校准。技能图、可执行环境和独立验证器可以进一步扩大任务覆盖并过滤无效轨迹（脚注 5–9）。

这两类验证必须分开看，这是很实用的工程经验：任务本身不可完成或难度不合适时，再好的轨迹也是噪声；任务没问题但轨迹走偏了，这条轨迹也不能进 SFT 集。规则能判的优先用确定性代码，开放式质量才交给模型评价器加人工抽样校准，验证成本和噪声都能明显降下来。

同一套任务和验证设施之后还可以转成 RL 环境，但两阶段的用法不同。SFT 只保留验证通过的成功轨迹，学习稳定的格式、流程和基本动作；RL 让当前策略重新 rollout，利用环境奖励探索示范之外的路径。失败轨迹不应直接当作正确示范，可以用来构造偏好对、发现任务覆盖缺口，或补上诊断与修复后再加入训练。它也不是废料：哪些任务根本没有成功轨迹，往往说明任务太难或底座能力不足。

数据合成的关键指标是覆盖面、多样性和准确性，数量排在后面。训练集还应按任务模板、客户或时间段去重划分，评估集必须来自不重叠的任务类型。这里有三条红线，值得直接抄进工程规范：参考解法、隐藏测试和验证器反馈不能泄露给模型。违反任何一条，评估分数都会虚高。

### 把第七章的问题案例转成训练数据

以 Coding Agent"过早结束"为例，做法是先把"准备宣称完成"的轨迹前缀截出来，再把当时的过早宣称作为 rejected，把"先运行测试、逐条核对验收条件，再下结论"作为 chosen。这类数据适合做 DPO 或决策边界示范，而不是直接当作正确的 SFT 轨迹。把"过早宣称完成"整条轨迹当作正样本会教坏模型，正确的用法是截出决策点，用 DPO/偏好对告诉模型哪种收尾方式才是 chosen。失败原因、适用条件和验证器应随样本保存，方便追溯和复查。实验 8-17 的 `build_preference_data.py` 提供了确定性模板和教师模型两条构造路径，训练数据与后面的评估集分开保存。这里对意义总结得很简洁：这样，问题案例不只是被"记住"，还可以用来定义模型需要改进的决策边界。

本章新增的两个问题案例实验分别展示了两种不同的监督目标。中文弯引号案例先把反馈提炼成作用域敏感的文档 Skill，再用结构化合成数据做 SFT；特殊字符串案例把 old_string mismatch 转成 byte-exact 复制任务，重点训练逐 token 的保真度。二者共享第七章的失败归因和训练/评估隔离协议，但评分标准不同：前者测"该改才改、该留则留"，要求的是克制，评分看作用域正确；后者测"必须逐字复制"，要求的是精确，评分看 byte-exact。同一个失败归因流程能导出两种完全不同的监督目标，这说明合成数据的关键在于先把评分标准想清楚，再决定怎么造数据。

这里还有一个容易混的地方：用验证器筛不等于 RL。RFT 只做筛选加 SFT，没有奖励模型、没有策略梯度；RL 才会让策略重新 rollout 并按奖励更新参数。任务验证与轨迹验证的分工也别混，前者验题对不对（可完成性、难度、参考答案），后者验这条解法对不对（最终状态、工具调用、业务约束）。合成数据也不等于复述线上日志，先抽象出任务蓝图、再重新生成虚构实例，目的是保留难点、去掉真实数据与身份信息。

## 8.7 何时选择Mid-training、SFT 与RL

这里说，"四阶段全景"一节讲清了三种训练的机制，这一节给出实操诊断：先判断缺的是底座、协议，还是策略，不要把"模型做不好"统一归因成需要 RL。

图 8-11 是这张诊断图：

> 示意图：一张两阶段流程图，箭头从"阶段一"指向"阶段二"。
>

> - 目标：输出可解析（JSON/工具调用）

这段诊断流程是全章的收口，把它压成一句可执行的口诀就是：先看 pass@k（会不会），再看解析率（说不说得清），策略（走不走得远）排在第三位。pass@k 接近 0 说明缺底座，走 Mid-training，动态事实改用 RAG；能对但格式或流程不稳说明缺协议，走 SFT 或约束解码；格式稳了要泛化到新场景说明缺策略，才轮到 RL。

图 8-11 里那条"为什么不能跳过 SFT 直接 RL"的失败链值得逐环理解：输出无结构 → 无法解析 JSON → 奖励函数返回 NaN → 梯度全零 → 训练完全失败。每一环都是可观测的工程现象，所以实践中应当先量解析率再决定要不要开 RL，这与 8.1.4 的两个前提完全对应。

两个公式的对照是本节最凝练的一行。SFT 是 $\max \sum \log P(y \mid x)$，拟合训练分布，把示范的概率推高；RL 是 $\max \mathbb{E}[R(\tau)]$，优化任务目标，把高奖励轨迹的概率推高。前者只看数据，后者只看奖励。这就解释了为什么"无论增加多少示范，新场景仍不佳"是转向 RL 的临界点：SFT 的优化目标里根本没有"新场景"这个量，继续堆示范只是在同一个目标上加码。

"过度训练 → 模型塌缩到训练分布"对应 8.1.5 的 mass-covering/过拟合。SFT 训练太久或数据太窄，模型会收缩到示范的少数模式上，多样性下降、泛化变差。所以阶段一的停止条件是格式稳定、能力初具，而不是把训练 loss 降到最低。

表 8-4 的"门槛"列是这张表最有价值的部分，它要求你为每个阶段定义进入下一阶段的准入条件。Mid-training 之后看领域留出集改善、通用保留集可接受、目标任务开始出现可验证的正确或部分正确轨迹；SFT 之后看解析成功率稳定、关键动作和输出协议可被验证器可靠评分。说白了，能不能进 RL 不取决于你的意愿，而取决于奖励能不能被可靠计算，这也是 8.7 的结论与 8.1.4 完全一致的原因。

几个容易混的点：模型做不好不等于需要 RL，这里反复强调不要把底座、协议、策略这三类缺口混为一谈，三者的修法完全不同；约束解码是 SFT 之外的另一条路，第二阶段判据里写的是"SFT 或约束解码"，如果问题只是格式，可能根本不需要训练；SFT 的停止条件也不是 loss 最低，练过头会塌缩到训练分布。

### 上接 8.7 收尾：表 8-4 的剩余内容与决策顺序

四行表其实是一张"症状 → 病根 → 药方 → 出院标准"的对照表。第三列回答怎么治，第四列回答治到什么程度算好、能不能进下一步。读表时最容易被忽略的正是第四列，它把"要不要进入下一阶段"从主观判断变成了可测量的准入条件。四行的递进关系可以这样记：底座（会不会）→ 协议（说不说得清）→ 数据（有没有得学）→ 策略（走不走得远）。第三行"只有少量稳定示范，尚无可交互环境"是一种很常见的中间状态：有少量示范，但没有可以反复试错的环境，此时既不够做 RL，也不该硬做 RL，正确动作是先把评估体系建起来，再判断这个环境值不值得投工程资源去造。

这里紧接着给出实际决策的顺序，这是 8.7 的方法论落点，共四步。

先排除不需要改权重的方案。Prompt、工具、代码约束、上下文管理能解决行为问题时不必训练；事实需要频繁更新、引用或删除时优先 RAG。

在目标留出集上测能力支持。不只看贪心的 pass@1，还要在固定采样配置下看 pass@k、部分进展率、格式解析率，并人工审计失败原因。若 pass@k 仍近零且失败集中在知识或基础能力，先做 Mid-training，重新评估后再决定后续步骤。

用 SFT 立协议，不拿它硬塞知识库。当模型「会做但不会按要求做」时，用高质量示范固化 JSON schema、工具调用、术语用法、流程和风格。少量事实可以随示范学入参数，但大量事实知识不应让少数 QA 对承担。

只在有探索空间时上 RL。当前策略已经能产生可评分、偶尔成功的 rollout，奖励又能忠实反映部署目标时，RL 才适合把低概率成功策略推高、探索示范外路径。pass@k 近零时先补 Mid-training/SFT 或设计可达的课程与部分奖励；全零 rollout 上直接加 PPO/GRPO 通常只会消耗采样预算。这句警告是本章反复出现的一条，它会在 8.9（GRPO 的相对优势需要组内差异）、8.12.4（RLVP 恢复组内差异）与 8.15（陷阱 4）三处再次出现，值得现在就记住。

这里随后强调，这个流程不是要求每个项目都依次跑完三种训练。强基模可能直接进入 RL，格式型任务可能只需 SFT，稳定领域知识可能只做 Mid-training 后再复用原有对齐能力。关键是每一步都有可测的进入条件，而不是把「Mid-training → SFT → RL」当作仪式化流水线。

回头看表 8-4 的第四列：pass@k 近零就去补底座，输出不可解析就固协议，有示范无环境就先建评估，奖励可靠又有组内差异才轮得上 RL。

## 8.8 单轮强化学习：记忆与泛化的对照

单轮的意思是任务在一次交互里就完成：模型接收输入、产出输出、拿到奖励，中间不需要维护跨步骤的状态。这里从这个简化设定讲起，理由是它能让人盯住 SFT 与 RL 在学习机制上的差别，不被多轮交互的复杂度分散注意力。它给这件事起的名字是「清晰的对照实验条件」：相同任务、相同基础模型、相同计算预算，唯一的变量是训练方法。

这一节安排了两个实验。实验 8-10（AdaptThink）看的是 RL 怎么学会「何时该思考」这条元策略；实验 8-11（GeneralPoints）用一个算术推理卡牌游戏，把「SFT 记忆、RL 泛化」这件事量化出来。

进实验之前，这里只要求记住一条直觉：「奖励高的方向多走，奖励低的方向少走」。本章的 RL 训练大多基于**策略梯度**，做法是让模型对同一个问题多生成几条回答，奖励高的那条把出现概率抬上去，奖励低的压下去。读成公式就是 $\theta \leftarrow \theta + \alpha \nabla_\theta \log \pi_\theta(a\mid s) \cdot A$。$\log\pi$ 的梯度只负责指出往哪个方向调概率，优势 $A$ 负责指出该加还是该减、加减多少。伪代码里那些看起来复杂的东西，价值网络、组内归一化、裁剪，服务的都是同一件事：把 $A$ 估得更准，把步子踩得更稳。

围绕稳定性有两处补充。为抑制单次更新把模型带偏，主流的 PPO 算法会在概率比超出指定区间时，裁掉代理目标里的那部分额外收益，也就是 clipping。这里特别点了一句：clipping 会抑制大幅更新，却不是对策略变化的硬约束。后文说的「带价值网络的 PPO」就是这种，价值网络用来估计基线、算出更细的优势。另一种 GRPO 不训练价值网络，靠「同一问题的多条回答互相比较」判断每条相对好坏。

第一段伪代码是 GRPO 视角的，省略了采样并行、KL 正则和优化器细节，只标出一次 rollout 到参数更新的因果链：

```python
for prompt in batch:
    group = [rollout(policy, env.reset(prompt)) for _ in range(G)]
    rewards = [verify(trajectory) for trajectory in group]
    advantages = normalize_within_group(rewards)   # GRPO baseline
    update(policy, group, advantages)
```

第二段是 PPO 的价值网络与裁剪目标：

```python
for trajectory in rollouts:
    returns = discounted_returns(trajectory.rewards)
    values = value_model(trajectory.states)
    advantages = returns - stop_gradient(values)
    ratio = exp(policy.log_prob(trajectory.actions)
                - old_policy.log_prob(trajectory.actions))
    policy_loss = -mean(min(
        ratio * advantages,
        clip(ratio, 1 - epsilon, 1 + epsilon) * advantages
    ))
    value_loss = mean((value_model(trajectory.states) - returns) ** 2)
    update(policy, value_model, policy_loss + value_coef * value_loss)
```

两段伪代码后面有三点说明。GRPO 的「相对」来自同一 prompt 的组内比较。PPO 里的 `old_policy` 是生成这批 rollout 时冻结的策略快照，概率比用它衡量当前策略已经移动了多远。裁剪抑制大步更新，同样不是对策略变化的硬约束。两者都仍然依赖可靠的环境与奖励，具体训练适配放到对应实验里讲。

把两个算法放在一起看，差别可以归结为「基线从哪来」。GRPO 的基线是同组其它 rollout 的平均奖励，不需要额外一个神经网络去学「这个状态通常能拿多少分」，代价是同一个 prompt 必须采一组（G 条），而且组内必须有奖励差异。PPO 的基线是价值网络对当前状态的估计，也就是伪代码里的 `values`，因此它能给同一条轨迹的每一步算出优势（`returns - stop_gradient(values)`），适合长轨迹的细粒度信用分配；代价是要多训一个价值网络，而这个价值网络自己也可能崩（8.15 的陷阱 8）。

`ratio = exp(policy.log_prob(...) - old_policy.log_prob(...))` 里的 `exp(新对数概率 − 旧对数概率)` 就是重要性比率，衡量同一个动作现在比生成数据时被选中的概率高了多少倍。PPO 用 `min(ratio*A, clip(ratio,1-ε,1+ε)*A)` 让这个比率在超出区间时的收益不进梯度，从而限制单次更新的幅度。伪代码里 `stop_gradient(values)` 的意思是价值网络的估计只当参照，不通过优势反向传播去训练策略，价值网络自己有 `value_loss` 单独训练。

这个 `ratio` 是在整条输出序列上做的，伪代码写的就是 `trajectory.actions` 级别。一条几千 token 的轨迹，序列级比率是逐 token 比率相乘的结果，单 token 对上一点点偏差，在长序列上会被放大。8.9.1.1 要展开的数值误差问题，物理来源正是这里。

## 实验 8-10 ★★：AdaptThink——学会「何时不思考」

背景直觉是这样的：大型思考模型（OpenAI o1、DeepSeek-R1 这类）对所有问题都会生成冗长的思维链，简单问题上这笔开销纯属浪费。实验先验证了一个直觉，NoThinking 模式（用 `<think></think>` 跳过思考）在简单问题上性能相当甚至更好，只有面对困难问题时 Thinking 的优势才显现。

AdaptThink 用 RL 训练模型自己选模式，两个核心组件。一个约束优化目标，鼓励 NoThinking 的同时确保整体性能不下降。一个重要性采样策略，平衡 Thinking/NoThinking 样本，解决初始模型几乎总选 Thinking 带来的**冷启动**（Cold Start）问题。这里的冷启动要跟前面 DeepSeek-R1 的用法分开：这里限定它特指训练初期模型几乎只产生 Thinking 样本、NoThinking 分支样本极少而学不起来；而 DeepSeek-R1 的「冷启动 SFT」是用少量示范数据把模型拉进可用状态，属于不同语境。

关于重要性采样，这里的解释是统计学里的常用方法：采样分布偏向某一类样本时，给样本加权来「纠正」分布，让学习信号公平覆盖所有类别。它还指出，这里后面讨论的 PPO、DAPO 等 RL 算法都会反复用到这个思想。

这次历史训练在这里的规范记录是 checkpoint-free 训练报告，关键数字如下。公开的 W&B 主运行 `wubbn5tj`，机器是 8×NVIDIA H100 80GB。step 0→300 之间：MATH500 准确率 0.8100→0.8180（+0.80 pp），响应长度 4911.46→1576.62（−67.90%）；GSM8K 是 0.796816→0.818802（+2.20 pp），长度 1025.24→477.33（−53.44%）；AIME mean@16 则为 0.314583→0.310417（−0.42 pp），长度 12119.51→6402.23（−47.17%）。对应的 NoThinking 比例是 83.80%、84.15%、56.25%。这里对这三组比例的判读是：数据集汇总层面存在与难度一致的路由信号，但不能叫逐题「完美难度感知」，也不能声称准确率普遍提升。

三组数字里真正巨大的变化是响应长度掉了 47% 到 68%，MATH500 只涨了 0.80 pp，AIME 反而跌了 0.42 pp。这个实验的收益主体是同等准确率下大幅省算力，读 W&B 曲线时别被「+2.20 pp」这类单点数字带跑。

数字本身可以复算，下面这些是我按这里数值自己算的，这里只给结论。MATH500：$0.8180-0.8100=0.0080$，即 +0.80 pp；长度 $(1576.62-4911.46)/4911.46=-3334.84/4911.46\approx-0.6790$，即 −67.90%。GSM8K：$0.818802-0.796816=0.021986$，即 +2.1986 pp ≈ +2.20 pp；长度 $(477.33-1025.24)/1025.24=-547.91/1025.24\approx-0.5344$，即 −53.44%。AIME mean@16：$0.310417-0.314583=-0.004166$，即 −0.4166 pp ≈ −0.42 pp；长度 $(6402.23-12119.51)/12119.51=-5717.28/12119.51\approx-0.4717$，即 −47.17%。三组的百分比都能由给出的首末值精确复现，说明它们是同一批日志的直接换算，没经过四舍五入凑口径。

报告的边界，这里专门澄清过。报告选取的 step 300 之后，训练继续跑到 step 410，累计 36.92 小时，随后 W&B 状态变成 crashed，配置的 10 epochs / 3,140 steps 并没有完成。Step 300 有 checkpoint 计时事件，但 checkpoint 不随书分发，也没有独立回执证明它经 `run_eval_verl_hf.sh` 成功评估或重跑 MMLU。历史源码提交是 `9e588202⋯`，未来复现固定到它的直接子提交 `0033ad172⋯`，三个入口文件保持不变，但训练脚本生成的 `-fl-` 路径与评估脚本硬编码的 `-fl4096` 路径不兼容，需要手工修正。

AdaptThink 还可以和 Prompt 蒸馏互补，形成「快—慢双系统」：蒸馏降低需要思考的任务比例，AdaptThink 优化剩余任务的触发策略，两者共同提高思考效率。

### 实验 8-11 ★★：GeneralPoints——单轮 RL 的「记忆与泛化」对照

图 8-12 画的是这个实验的架构，GP-L 与 GP-VL 两个变体的训练与测试设计都在里面：

> 示意图：一张「训练集 → 测试集（OOD）」的对照图，上下两条路线分别是纯文本版 GP-L 与视觉—语言版 GP-VL。

> GP-L（纯文本）：训练集用 J/Q/K = 10；测试集（OOD）把 J=11, Q=12, K=13。训练输入示例：`"用 [7, J, 3, 5] 计算 24"`，输出示例：`"(J-7)×(5+3) = 3×8 = 24"`；图中标注 OOD 时 J=11 会让同一条式子变成 `"(11-7)×(5+3)=32≠24"`。
>
> GP-VL（视觉—语言）：训练集用黑色花色 ♠♣，测试集（OOD）用红色花色 ♥♦；输入是扑克牌图像，处理链为「视觉编码器 → 数字识别 → 思考」；图中标注 OOD 的意思是花色外观变化测试视觉鲁棒性。基础模型为 Llama-3.2-Vision-11B。
>
> 图中间给出两条训练路径的目标式对照：SFT 路径 $\max \sum \log P(y\mid x)$，标注「记忆训练分布」；RL 路径（PPO）$\max \mathbb{E}[R(\tau)]$，标注「探索泛化策略」。
>
> 图底部是 OOD 测试结果（相对于 SFT Init 基线的变化）：
>
> | 测试项 | SFT 扩展 | RL 扩展 |
> | --- | --- | --- |
> | 规则 OOD（GP-L） | −8.1%（11.5→3.4） | +3.5%（11.5→15.0） |
> | 规则 OOD（GP-VL） | −5.6% | +3.0% |
> | 视觉 OOD（GP-VL） | −9.9%（23.6→13.7） | +17.6%（23.6→41.2） |
>
> 图内结论行：SFT 在分布外一致下降，RL 一致提升 —「SFT 记忆，RL 泛化」；关键前提行：未经 SFT 的端到端 RL 完全失败（输出无结构，奖励无法计算）。

GeneralPoints 是 Chu 等人提出的算术思考卡牌游戏（脚注 a：Chu, Tianzhe et al., "SFT Memorizes, RL Generalizes: A Comparative Study of Foundation Model Post-training", 2025. arXiv:2501.17161），专门用来评估模型的泛化能力。任务目标类似「24 点」游戏：使用四张卡牌上的数字，通过加减乘除运算，每个数字恰好用一次，凑出目标数字 24。

两个变体是纯文本 GP-L 与图像 GP-VL，使人在同一框架下分别考察规则泛化与视觉泛化。规则变体训练时 J/Q/K 都计为 10，测试时分别计为 11/12/13，确保测试集出现训练未见的数字组合（含 11、12、13 的运算），严格评估泛化能力。视觉变体训练用黑色花色（♠♣），测试用红色花色（♥♦），评估视觉外观变化下的鲁棒性。

训练流程基于 Llama-3.2-Vision-11B，遵循标准后训练流程：先 SFT 初始化使其具备基本指令遵循能力，然后在相同计算预算下分别扩展 SFT 与 RL 训练（RL 部分采用带价值网络的 PPO 算法），用单一规则（J/Q/K=10）数据训练，在分布内（ID）与分布外（OOD）测试集上评估。

结果差异在这个受控设置里很显眼。规则 OOD：RL 在 GP-L 上 +3.5%（11.5%→15.0%），SFT 下降 8.1%（11.5%→3.4%）；GP-VL 上 RL +3.0%，SFT 下降 5.6%。视觉 OOD：RL 在 GP-VL 上 +17.6%（23.6%→41.2%），SFT 下降 9.9%（23.6%→13.7%）。

视觉识别准确率另外单独追踪过。RL 通过结果导向的优化改善了底层视觉编码器，且这种改善与整体性能提升高度相关；SFT 因为过度拟合思考过程中的 token 模式，忽视了对视觉 token 的学习，识别准确率反而下降。

这些百分比同样能复算：$15.0-11.5=+3.5$，$3.4-11.5=-8.1$；$41.2-23.6=+17.6$，$13.7-23.6=-9.9$。图里的百分比就是两个百分点之间的差，跟相对提升率无关。把「+17.6%」读成「提升了 17.6% 的相对幅度」是错的，它是**绝对百分点差**。

SFT 初始化的必要性在这里带着限定。在本实验的设定下（Llama-3.2-Vision-11B 这个量级的基础模型，加上严格的结构化输出要求），RL 需要先用 SFT 初始化。未经 SFT 直接做端到端 RL 完全失败，因为基础模型无法产生结构化输出，奖励根本无法计算。这里明确提醒，这个结论只在特定设定下成立，不能当普适规律：足够强的基础模型可以跳过 SFT 直接 RL 成功（见前文对 DeepSeek-R1-Zero 的讨论）。

另一个发现是，验证迭代次数越多，测得的泛化越好：10 次 +5.99% vs 1 次 +0.48%，说明增加测试阶段的计算量是泛化提升的重要因素。这条发现提示测试阶段的算力也是能力的一部分。评测时只跑 1 次采样，可能严重低估一个模型的真实能力，尤其是 RL 训练出来的模型，这跟前文「看 pass@k 而不只看 pass@1」是同一个道理。

机理解释是这里给出的、与观察相符的一种解释，不是定论：有限的 SFT 数据强化了「遇到 J/Q/K 就当 10 用」的固定模式，测试时 J=11，模型仍按 10 计算；结果导向的 RL 分支则更可能强化「重新计算直到得到正确答案」的策略，因而在 J 变成 11 时仍能应用。这里强调这解释了本实验中的记忆与泛化对照，但不等于 SFT 只能记忆、RL 必然学会通用算法。

本实验的核心贡献是在有限的 GeneralPoints 设置中系统量化了 SFT 的过拟合倾向与 RL 更好的分布外表现，并在纯语言和视觉—语言两个变体中都观察到同一模式：SFT 稳定格式，RL 在此基础上探索策略，两者形成互补。

那为什么「SFT 记忆、RL 泛化」不能当定理用？SFT 的目标函数里根本没有「测试集」这个量，它只把示范的概率推高；如果示范恰好覆盖了 OOD 情况，SFT 也能泛化。RL 的目标函数里有奖励，但奖励与真实目标错位时，RL 会泛化到错误的策略上，8.12.1 的 reward hacking 就是这么来的。这里最后那句「不是说 SFT 必然只能记忆，或 RL 必然学会通用算法」，可以当作读本章全部实验的总提醒。

还有几处容易混。GRPO 的「组」和 PPO 的「批」不是一回事：GRPO 的组是同一个 prompt 的 G 条 rollout，组内比较；PPO 的批是多个 prompt 的若干轨迹，用价值网络做逐状态基线。前者靠同题对比，后者靠自身预期对比。`clip` 也不是硬约束，这里两次强调过：裁剪只是让超出区间的比率不再贡献梯度增量，策略依然可以移动很远，真要限制移动幅度得靠 KL 正则、学习率、更新轮数。AdaptThink 的冷启动跟 DeepSeek-R1 的冷启动 SFT 更是两回事，一个是训练初期某类样本稀缺导致学不起来（采样分布问题），一个是用少量示范数据把模型拉进可用状态（数据准备问题），这里专门划清过这两个语境。

单轮对照实验给出的结论是「SFT 记忆、RL 泛化」：同一任务、同一基模、同一预算下，OOD 上 SFT 一致下降、RL 一致提升。这两个方向都不是定律，RL 能否泛化取决于奖励是否忠实、探索是否足够。

## 8.9 RL 算法：从16 次rollout 到一次参数更新

GRPO（Group Relative Policy Optimization）是 DeepSeek 提出的算法，也是今天 RL 训练最常用的算法之一。这里用一个例子把它讲透：假设 SWE-bench 里有一条任务，某个 Python 项目的 `parser.py` 在输入为空时会触发 `IndexError`，要求 Agent 修复代码，并且不能修改测试。训练系统走四步。

第一步，让策略模型重复尝试。策略模型就是当前正在训练的语言模型。系统把同一份初始代码、同一条问题描述分别复制到 16 个相互隔离的沙箱中，让模型独立解决 16 次。每一次都包含完整的「阅读代码 → 修改文件 → 运行测试 → 提交结果」，这整条过程就叫一次 **rollout**。问题和初始环境完全相同，但采样具有随机性，所以 16 次尝试可能走出不同路径：有的正确补上边界检查，有的只捕获异常掩盖问题，有的改错文件，还有的试图修改测试。

第二步，计算奖励。每条 rollout 结束后，验证器在干净环境中应用补丁并运行测试。假设 16 次尝试中有 4 次通过全部测试且没有修改测试文件，另外 12 次失败，那么前 4 条得到奖励 1，后 12 条得到奖励 0。这里强调，在这种 coding 任务里，奖励计算并不神秘，就是用测试和规则判断这次修复到底对不对；只有开放式任务没有确定测试时，才需要人类偏好或奖励模型来评价。

第三步，计算相对优势。奖励只说明单条轨迹成功或失败，**相对优势**说明它相对于同组其他尝试有多好。这一组的平均成功率是 4/16，通过测试的 4 条高于组内平均，得到正优势；失败的 12 条低于平均，得到负优势。GRPO 的核心就是这种组内比较。如果 16 条全部失败或全部成功，大家的奖励完全一样，就比较不出谁更好，相对优势也会消失；RLVP 的路径信号、过程奖励和部分进展奖励，解决的正是如何在这些组里恢复有意义的差异。

第四步，用梯度下降更新策略。训练程序把相对优势转成训练损失，计算梯度，再由优化器（如 AdamW、Muon）执行梯度下降，提高正优势轨迹中模型所做选择的概率，降低负优势轨迹中选择的概率。这里说明它的做法是在许多任务和 rollout 上逐步调整，并不把某个成功补丁原样背下来。以后遇到类似错误时，「先复现问题、检查边界条件、修改实现并运行测试」会更容易出现，「掩盖异常、改测试、没有验证就提交」会更少出现。

图 8-13 把这一整套走了一遍：

> 示意图：一张从上到下的流程图，展示「一个 step」的完整因果链。
>
> 顶部（任务与初始化）：同一 SWE-bench 任务 + 初始代码 `parser.py`；两行约束标注：「空输入触发 IndexError」、「不能修改测试文件」。
>
> 第二层（采样）：策略模型 → 独立采样 16 条 → 每条都是一次完整执行；下方注明「16 个相同沙箱中的 rollout（采样不同，初始状态相同）」，并逐条列出结果：

>
> 第四层（组内比较 → 相对优势）：4 条成功高于平均 → 正优势；12 条失败低于平均 → 负优势。
>
> 第五层（策略更新）：Gradient Descent + Optimizer → 成功路径 ↑、失败路径 ↓ → 下一 step。
>
> 图底总结行：一个 step：rollout → 验证 → 比较 → 梯度下降更新；粗略量级：rollout ≈ 2,000 s + update ≈ 600 s → step ≈ 2,600 s（约 43 分钟）。

这四步读成一条数据流，就是采样（16 个隔离沙箱的 rollout）→ 判分（验证器跑隐藏测试）→ 组内归一化（相对优势）→ 更新（优化器改参数）。链上任何一环失效，后面的都不成立：采样没有隔离，rollout 之间会互相污染；验证器不干净（比如模型能改测试），奖励就是假的；组内没有差异，优势全为零；更新太大，策略会崩。这里把**组内必须有奖励差异**单独强调，因为这是整条链上唯一一个「看数据就能发现」的失效点。拿到一批 rollout 先看奖励的分布，比调算法参数有用得多。

这四步合起来构成一次训练迭代，也就是一个 step。第 $k$ 个 step 用当前策略生成一批 rollout，完成奖励、优势和梯度计算，再由优化器更新参数；第 $k+1$ 个 step 随即使用更新后的策略重新 rollout。训练 100 steps，就是把这个闭环重复约 100 轮。这里提醒，具体 RL 训练框架可能把内部的多个 minibatch 更新另行计数，看训练日志时仍需确认它的 step 定义。跨框架对比训练速度或者「训练了多少步」之前，得先把 step 的定义对齐，否则「100 steps」在两边可能相差一个数量级。ReTool 那种「每步 512 条 rollout」的规模描述也要配套看。

时间估算方面，复杂 Agent rollout 会生成数十轮工具调用，即使 16 条并行运行，一个 rollout 阶段的墙钟时间也由最慢的那条决定。假设最慢 rollout 用时约 2,000 秒，随后梯度下降和优化器更新用时约 600 秒，那么

$$
T_{\text{step}} = 2{,}000\ \text{s} + 600\ \text{s} = 2{,}600\ \text{s} \approx 43\ \text{min}
$$

$T_{\text{step}}$ 是一个训练 step 的墙钟时间，单位为秒；2,000 s 是受最慢 rollout 支配的采样时间（不是 16 条的平均时间），600 s 是梯度下降与优化器更新时间。这里接着给出：连续训练 100 steps 就接近 72 小时。

由此还能再推两步，这部分是我按这里数值自己算的。采样阶段占了约 $2000/2600\approx77\%$ 的时间，所以优化训练速度的第一优先级是采样，也就是环境交互，不是优化器；更新只占约 23%，在更新阶段继续压效率对总时长的影响有限。100 steps 的理论耗时是 $100\times2600=260{,}000\ \text{s}$，换算成小时是 $260000/3600\approx72.2$ 小时，与这里「接近 72 小时」对得上。

**最慢的那条 rollout 决定墙钟时间**这件事值得单独看一眼。16 条 rollout 并行跑，只要有一条第 30 轮才结束，整批就得等它。这也是思考题 12 的源头（长尾响应拖低 GPU 利用率）。这里明写「一个 rollout 阶段的墙钟时间也由最慢的那条决定」，所以只看平均响应长度的优化目标可能对墙钟时间无效，得看尾部。

PPO 与 GRPO、DPO 的分工是这样的。PPO 与 GRPO 都遵循同一个闭环，区别主要在「拿谁来比较」。GRPO 直接比较同一问题的多条 rollout，不需要额外的价值模型；PPO 会训练一个价值模型，估计轨迹的每一步「通常能做到多好」，再判断当前动作是否比这个预期更好，因此更适合需要细粒度信用分配的长轨迹。两者都会限制单次更新幅度，避免模型因为一小批样本突然改变过多。DPO 则不同，它直接学习事先收集好的「较好回答—较差回答」偏好对，不让当前策略在线生成这组 rollout。

选型上可以这么记：需要细粒度信用分配、轨迹长，选 PPO（有逐状态价值基线）；同题能多采样、想省一个价值模型，选 GRPO；只想要离线偏好对齐、不想在线采样，选 DPO。DPO 与另两者的根本差别在数据从哪来。PPO/GRPO 的数据是当前策略现场生成的 rollout，所以能探索；DPO 的数据是事先收集好的偏好对，便宜但不能探索新路径。

本章各实验的算法归属，这里明确列过：AdaptThink 使用自定义约束目标；GeneralPoints 与 V-IRL 使用带价值模型的 PPO；SimpleVLA-RL 与 RLVP 使用 GRPO；ReTool 使用 PPO。这份归属说明的是适配，跟算法优劣无关：长轨迹需要价值网络（PPO），同题多采样适合组内比较（GRPO）。这里的总结句是：算法决定如何比较轨迹和更新参数；奖励决定「什么算成功」；环境和数据决定模型能经历哪些问题。这三条线的修改成本是递增的，换算法改几行配置，换奖励要重写验证器，换环境要重建整个仿真世界；收益往往也是递增的。这正是本章反复强调「数据和环境比算法更重要」的原因。

剩下几处容易混。一个 step 在某些框架里不等于一次参数更新，这里明确提醒要确认日志里 step 的定义。GRPO 的组不能被拆散，同一个 prompt 的 G 条 rollout 必须放在一起算优势，把 16 条拆到不同 batch 里，组内比较就不存在了。DPO 里的 `chosen/rejected` 也不是「对/错」，它是偏好对（较好 vs 较差），两者可能都不完美。

一个 step 就是「16 条 rollout → 验证器判分 → 组内相对优势 → 梯度更新」的闭环，墙钟时间由最慢的那条 rollout 决定，约 2,000 s 加 600 s，合计 43 分钟左右。算法只管拿谁和谁比，真正决定学到什么的仍是奖励、环境与数据。

### 8.9.1 为什么 LLM RL 通常优先 On-Policy

有两个容易混用的词要先分清。Online（在线）只表示数据在训练过程中不断通过与环境交互产生。On-policy（在轨）要求生成 rollout 的行为策略 $\mu$ 与当前要优化的策略 $\pi_\theta$ 相同或足够接近。

异步集群有个陷阱：即使持续在线生成，只要 rollout worker 落后了几个 checkpoint，数据就已经陈旧，训练在统计意义上也已经带有 off-policy（离轨）成分。回放旧轨迹、使用旧模型数据或教师完整生成的数据，则是更明显的 off-policy。

本章配方的定位是：PPO/GRPO 配方通常每个 step 都用最新策略重新生成 rollout，因而以近似 on-policy 为目标；但 PPO 在同一批数据上做多轮 minibatch 更新时，后几轮已经开始偏离生成数据的 `old_policy`，这正是它需要概率比与 clipping 的原因。

重要性比率的公式是

$$
\rho_t = \frac{\pi_\theta(a_t \mid s_t)}{\mu(a_t \mid s_t)} = \exp\left(\log \pi_\theta(a_t \mid s_t) - \log \mu(a_t \mid s_t)\right)
$$

其中 $\rho_t$ 是第 $t$ 步动作的重要性比率（无量纲，正数）；$\pi_\theta(a_t\mid s_t)$ 是当前要优化的策略在状态 $s_t$ 下选择动作 $a_t$ 的概率；$\mu(a_t\mid s_t)$ 是实际生成这批数据的行为策略在同一状态下选择同一动作的概率。右边写成对数的差再取指数，是为了在数值上把「概率相乘」变成「对数相加」，训练框架里算的通常就是这个 $\log$ 形式。

判别 on-policy 的办法很直接：真正新鲜的 on-policy rollout 在参数更新之前应满足 $\pi_\theta=\mu$，所以 $\rho_t=1$。这使训练集中在当前模型实际会进入的状态上，也避免为分布错位付出高方差修正。

off-policy 有代价也有收益。好处是旧数据可复用、采样与训练可以异步，吞吐量更高；代价是策略越陈旧，$\rho_t$ 的分布越重尾。对自回归长序列，严格的前缀或轨迹修正还会连乘许多 token 比率，少量偏差可能累积成极大或极小的权重。

clipping 的边界也在这里。PPO 的 clipping 能限制离群更新，却不能无损恢复丢失的分布覆盖；裁得太多会丢梯度，不裁又可能被少数样本主导。

这里的结论带着限定：「On-policy 更好」不是普遍定理，在当前 LLM 策略梯度中，它通常意味着更低的分布偏差和更稳定的优化。稳定大模型 RL 的实证研究也发现，减少策略陈旧度与训练—推理差异是代理目标有效的重要条件（脚注 10：Zheng, Chujie et al., "Stabilizing Reinforcement Learning with LLMs: Formulation and Practices", 2025. arXiv:2512.01374）。

**重要性比率**可以想成汇率。你在 A 国（行为策略 $\mu$）赚到的钱（轨迹），要换算成 B 国（目标策略 $\pi_\theta$）的购买力。汇率恰好是 1 时账目最干净；汇率偏离 1 越多，同样的样本在目标策略眼中的权重就越离谱。一本账里出现几百倍的汇率，很容易被少数样本主导。公式写成 `exp(log 新 − log 旧)`，不只是为了数值稳定，它也在提醒偏差是指数级的。

### 8.9.1.1 看似On-Policy，为什么仍会被数值误差拖垮

工程事实是：大规模 LLM RL 往往用 vLLM/SGLang 一类推理引擎生成 rollout，再用 FSDP/Megatron 一类训练引擎重算 log probability 和梯度。即使两边加载同一份权重，浮点精度、归约顺序、张量并行方式、批大小、KV cache 与 fused kernel 的差异，也可能让同一 token 的 log probability 略有不同。

后果是，更新前本应为 1 的 $\rho_t$ 已经偏离 1。系统名义上同步了权重，数值上却把 on-policy 训练变成了 off-policy。已有受控实验表明，单独存在的微小 token 级训练—推理差异就可能引发训练崩溃（脚注 11：Zhong, Tianle et al., "Diagnosing Training Inference Mismatch in LLM Reinforcement Learning", 2026. arXiv:2605.14220）。

放大链条是这里给出的因果链：log probability 小误差 → 指数化的概率比偏差 → 长前缀上的累积 → clipping/优势加权改变 → 梯度方向与有效样本数改变。

数值例子里，若 4,000 个 token 的 log ratio 都有同方向的 $10^{-3}$ 偏差，轨迹级比率会累积到 $e^{4} \approx 54.6$。这里同时说明，真实误差未必同号，但这个例子说明了长序列为什么会把「每个 token 看起来很小」的误差放大。这笔账可以自己算一遍，下面是我按这里数值复算的：轨迹级比率是各 token 比率的乘积，取对数就是求和，$\sum_{t=1}^{4000}\left(\log\pi_\theta-\log\mu\right)=4000\times10^{-3}=4$，所以 $\rho_{\text{traj}}=e^{4}\approx54.6$。每个 token 在 log 空间只差千分之一，整条轨迹就差 54 倍。例子强调「同方向」也是因为这个：误差不同号时求和会互相抵消，实际累积通常远小于 4，而最坏情况的上界正是这个 54.6。

更隐蔽的后果是，早期 token 的微小概率差还可能改变实际采样出的 token，使后续整条状态轨迹分叉。最终表现不只是「同一提示偶尔生成不同答案」，还可能是重要性比率尖峰、大量 token 被裁剪、梯度或响应长度突变，继而奖励和熵一起坍塌。

长序列在 RL 里比在 SFT 里更危险，原因在这里：SFT 只用固定的标签做似然最大化，数据的分布不依赖模型当前的输出；RL 用模型自己的输出去生成训练数据，一旦某个早期 token 因为数值误差被换掉，后面每一个状态都跟着变，整条轨迹就成了另一条路径。**状态轨迹分叉**改的是训练用的状态分布本身，跟「答案偶尔不同」不是一回事。

「奖励和熵一起坍塌」这句话值得单独记住。熵衡量策略输出的多样性，奖励坍塌是学不到好东西，熵坍塌是策略变得千篇一律。两者同时出现，通常意味着有效样本数被少数极端权重的样本吃掉了，这也是建议里要求监控有效样本数的原因。

**batch invariance** 是一条独立的证据：批大小改变计算归约方式，破坏数值的 batch invariance，已经直接被观察到会把本应 on-policy 的 RL 变成隐式 off-policy。使用匹配的采样—训练数值，或者加显式的 off-policy 修正，都能改善稳定性（脚注 12：He, Horace and Thinking Machines Lab, "Defeating Nondeterminism in LLM Inference", 2025）。

工程上得把它当核心问题，不能当成普通的浮点噪声。这里给了四条做法：

1. 在任何参数更新之前，用同一批轨迹比较 sampler 与 trainer 的 token log probability，监控 $\rho_t$ 的均值、分位数、最大值、近似 KL 和被裁剪比例。这是最直接的 on-policy 单元测试。
2. 同步的不只是权重，还包括 LoRA adapter、tokenizer、chat template、模型 revision 和位置编码配置；rollout 应保存生成时的 behavior log probability，不能事后拿当前模型冒充。
3. 尽可能对齐采样与训练的精度、并行布局和关键计算内核；若做不到，就把差异明确视作 off-policy，采用重要性修正并监控有效样本数，不要假设 PPO clipping 会自动兜底。
4. 保持 rollout 新鲜，限制每批数据上的更新轮数和异步 staleness。重用旧数据能换吞吐，但应作为经过测量的偏差—效率取舍，不能当成免费的加速。

第 1 条实际上就是一个可自动化的单元测试：固定一批轨迹，在参数更新前算 sampler 与 trainer 的 log prob 差，如果 $\rho_t$ 的中位数明显偏离 1，或者分位数尾部很重，就不要开始训练。大多数「RL 训练不稳定」的排查应该从这里开始，别急着先去调学习率。第 2 条那句「不能事后拿当前模型冒充」在实践中非常常见：不少框架为了省显存，在 rollout 结束后用当前（已经更新过的）模型重新算一遍 log prob，这在数值上就是制造 off-policy 数据。

还有几处容易判反的地方。Online 不等于 On-policy：在线只保证数据是边跑边生成的，不保证生成数据的策略就是当前要优化的策略；异步 worker 落后几个 checkpoint，就已经在线但离轨了。离轨有两种来源，一种是架构性的（异步、回放、教师数据），另一种是数值性的（同一份权重在推理引擎和训练引擎里算出不同的 log prob）。第二种更隐蔽，因为配置里看不出任何「离轨」的字样。

$\rho$ 偏离 1 有两个含义，判读完全相反。训练故意做多轮 minibatch 更新时，$\rho_t\ne1$ 是设计的一部分，所以要 clip；而更新前就该检查 $\rho_t$ 是否等于 1，此时它偏离 1 是故障信号。

clipping 不是数值误差的解药。它处理的是比率偏大时不要过度更新，没法把已经错掉的状态分布还原回来。这里那句「不能无损恢复丢失的分布覆盖」就是这个意思。

On-policy 的判据只有一条，**更新前 $\rho_t$ 应该等于 1**；而长序列会把每 token 千分之一的数值差放大成 $e^4\approx54.6$ 的轨迹级比率。所以「sampler 与 trainer 的 log prob 是否一致」应当和奖励曲线一起监控。

## 8.10 RL 环境：从评估到仿真

RL 训练的瓶颈往往不在算法，而在环境是否足够真实、可重置、可并行。真实 Agent 打电话、付款或修改文件，代价高而且不可逆，一次错误没法靠无限重试抹掉；第七章那套评估环境能提供验证器，但训练还要求 Agent 反复试错、承受动作的副作用，并在数百万次交互中保持稳定。这里由此给出结论：环境工程是 RL 的前置条件，训练跑完再来补环境，顺序就反了。

## 8.10.1 环境：模型练习的场地

RL 的本质是试错学习，试错必须有一个场地，也就是仿真环境（simulation environment）。模型在这个场地里一遍遍执行任务、拿到反馈、调整策略。环境与真实部署场景有多相似，这一点叫保真度，它直接决定训练出来的策略能不能用。这里把保真度展开成三点。

环境一旦失真，策略就会失效。仿真里的客服要是总按固定套路回话、错误信息又跟生产环境对不上，模型学到的就是一套只在仿真里管用的「应试策略」，一上线立刻暴露。这里称为 RL 项目最常见的失败方式：算法本身没问题，问题出在练习场与考场并不相同。

构建高保真环境常常比训练本身更贵、更难。一个能大规模并行、可复现、反馈真实的环境，投入的工程资源往往比调模型多得多。本章后面的工具调用实验（AWorld 的 MCP 沙盒、ReTool 的代码解释器沙盒）之所以花大力气搭环境，原因就在这里：真实 API 有速率限制、会封号、有副作用，根本没法直接用于训练，必须先造一个稳定、可控、可重放的「影子世界」。

环境的另一半是奖励函数。它不只要模拟世界怎么变，还要判定做得好不好，这就是后面奖励设计的输入。

这里的收束句是这么问的：在动手调算法之前，先问自己，我的仿真环境真的像真实世界吗？这个问题的答案，比选 PPO 还是 GRPO 重要得多。

说「环境比算法重要」并不只是口号。算法决定的是怎么把已有的奖励信号变成参数更新，环境决定的却是模型能经历什么问题、能拿到什么反馈。环境里的奖励与真实目标不一致时，再好的优化器也只是更快地朝错误方向收敛。这里那个「练习场与考场并不相同」的比方讲得很准：算法是教练，环境是训练场，训练场选错了，教练再强也没用。

### 8.10.2 造不出环境怎么办：让模型扮演环境

问题还可以更根本一些。有些场景里高保真环境根本造不出来，贵都算不上主要障碍：真实 API 有副作用不能乱调，真实用户不能拿来试错，物理世界更没法快进。这里设问，如果连一个可用的「影子世界」都搭不起来，RL 是不是就做不成了？它给出的思路越来越主流：用模型来模拟环境，让一个 LLM 扮演环境，生成 Agent 交互所需的反馈。这条路线有两个层次。

第一个层次是让模型合成工具调用的返回值。以 ZeroSearch 为例（脚注 13：Sun, Hao, et al. "ZeroSearch: Incentivize the Search Capability of LLMs without Searching", 2025. arXiv:2505.04588）：训练「会搜索的模型」通常离不开真实搜索引擎，而搜索 API 有成本、有速率限制，返回结果还不可控。ZeroSearch 直接用一个 LLM 扮演搜索引擎，学生模型发出搜索 query，由这个「模拟引擎」生成并返回检索结果。它还采用了课程式设计：训练初期让模拟引擎返回高质量、强相关的文档，随着训练推进逐步掺入噪声、降低返回质量，促使学生学会从真实搜索引擎那种不完美的结果中提取有用信息。最终，训练全程没见过真实搜索引擎的模型，直接对接真实搜索时依然表现良好。

这个课程式设计是本节最值得学的一个技巧，它的本质是让训练分布从「理想」逐步过渡到「真实」，一次解决掉「用真实搜索引擎太贵」和「用理想模拟器学不到鲁棒性」这对矛盾。前期用理想结果快速把基本功练出来，后期掺噪声补上「从脏结果里提信息」的能力。这与本章 8.4 的 Mid-training、以及 8.16 小结强调的长度课程、混合数据和逐级门禁在方法论上是同一招：课程就是把一步到位做不到的事拆成可达的台阶。

第二个层次是让模型仿真整个环境的动态。替换的已经不只是单个工具的返回值，连「执行动作后世界会变成什么样」也交给模型。DreamGym 把环境动态蒸馏进一个推理式的「经验模型」（脚注 14："DreamGym: Scaling Agent Learning via Experience Synthesis", 2025. arXiv:2511.03773）：给定当前状态与 Agent 的动作，它逐步推理出状态转移和反馈信号，从而在不访问真实环境的情况下批量合成 rollout 用于在线 RL。客服、销售类 Agent 的训练则普遍用 LLM 扮演用户，也就是用户模拟器，τ-bench 系列评测正是建立在这个思路上：同一个模型模拟器，既能当考场，也能当练习场。

「用户模拟器既能当考场也能当练习场」这句话有两层含义，别只读一层。好的一面是同一套模拟器可以低成本地同时支撑训练和评测；危险的一面是，如果训练和评测用的是同一个模拟器、同一批行为模式，那么评测结果测量的就只是模型拟合这个模拟器的程度。所以工程上必须让校准用的真实交互独立于训练回路。

模型模拟环境的两层也不要混。第一层只替换工具的返回值，属于数据层面；第二层替换的是整个世界动态，属于状态转移层面。第二层的风险更大，状态转移错了一整条轨迹就都错了，而工具返回值错了往往只影响下一步的观察。

这里明确要求指出风险：模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收。如果模拟的客服比真实用户更有耐心、模拟的搜索引擎从不返回垃圾结果，学生学到的就是一套只在「模型扮演的世界」里成立的策略。更糟的是，RL 会主动寻找并利用模拟器的漏洞，进行 reward hacking。

「模拟器的世界知识就是训练的天花板」这句话可以这么理解：学生模型能学到的最优策略不可能超过它在模拟器里见过的世界规律，因为它的全部经验都来自模拟器。模拟器不知道的漏洞、不建模的边界情况，学生永远学不到；反过来，模拟器里系统性的错（比如「客服永远耐心」）会被学生当作世界的规律去优化。把环境保真度放在算法选择之前，原因正在这里。

工程上的稳妥做法是混合：用模型模拟承担大部分交互量，辅以真实环境的交互，并用真实环境交互定期校准模拟器的偏差。

### 8.10.3 环境、任务分布与评估隔离

环境本身决定了 RL 能学到什么，它必须可重置、可并行、可复现，并在状态转移后给出可信的验证结果。

训练任务的来源与前文 SFT 数据合成一致：从真实业务日志提炼任务蓝图，去除身份信息后重新生成虚构的人物、订单、文件与状态。

隔离要求也相同，但 RL 场景多了一条：训练环境和评估环境可以共享任务生成器与验证代码，却不能共享同一批任务。SWE-Gym、τ²-bench、AndroidWorld 都说明了这一点（脚注 15：Pan, Jiayi et al., "Training Software Engineering Agents and Verifiers with SWE-Gym", 2024. arXiv:2412.21139；Barres, Victor et al., "τ²-Bench: Evaluating Conversational Agents in a Dual-Control Environment", 2025. arXiv:2506.07982；Rawles, Christopher et al., "AndroidWorld: A Dynamic Benchmarking Environment for Autonomous Agents", 2024. arXiv:2405.14573）；测试用例、隐藏状态和参考解法应留在验证器一侧。

共享生成器与共享任务要分开看：前者是复用工程资产，后者是泄漏。

验证习惯是先小后大。应先用少量 rollout 检查任务是否可完成、验证器是否能区分对错，再扩大采样规模。验证器本身有系统性偏差的话，RL 只会更快地利用它。

环境工程的顺序，这里给出五步：任务蓝图 → 可重置模拟器 → 确定性验证器 → 训练/评估隔离 → 少量真实交互校准。两者分工的解释是：SFT 数据合成放在前文，是为了构造稳定的示范；这里的环境服务于 RL，让当前策略反复试错并探索示范之外的路径。这个顺序不能颠倒。任务蓝图决定问题空间；可重置模拟器保证同一任务能被反复试；确定性验证器保证奖励可复现，不确定的验证器等于噪声奖励；训练/评估隔离保证度量的是泛化而不是记忆；少量真实交互校准保证前四步造出来的世界没有系统性漂移。少任何一步，后面都会以「训练不收敛」「上线就失效」的形式还债。

「可重置」和「可复现」是两个要求。可重置指环境能被恢复到初始状态，同一任务可以重跑；可复现指同样的动作序列得到同样的反馈，奖励可比较。仿真里只做到重置、做不到复现（比如模拟用户带随机数且不设种子），奖励就会抖。

确定性验证器的成本，这里专门提醒：「便宜」不等于「没有成本」。Lean kernel、测试运行器或容器执行可能让 CPU 验证速度远慢于 GPU 生成速度；这时吞吐量取决于并行的验证器 worker，而不是继续堆 GPU（这里此处标注脚注 16）。

这条提醒有个可以直接算的含义（推算是这里补的，这里只给了结论）。设一条 rollout 的生成需要 $T_{\text{gen}}$ 秒、验证需要 $T_{\text{ver}}$ 秒，整个训练回路的吞吐大致受 $\max(T_{\text{gen}}, T_{\text{ver}})$ 支配。$T_{\text{ver}}$ 成为瓶颈时，多买 GPU 只会让它们排队等验证器；正确的扩容方向是并行验证器 worker 的数量。这也是为什么本章多处实验都把「沙箱并行数」当成关键超参，比如 ReTool 的 128 并行 worker，见 8.11.2。

把这一节收在一句话上：RL 的前置条件是环境工程，顺序就是上面那五步；造不出真环境时可以让模型扮演环境，但模拟器的世界知识就是训练的天花板，必须用真实交互定期校准。

## 8.11 从单轮到多轮：任务场景与信用分配

### 8.11.1 多轮任务的核心挑战

从单轮到多轮，复杂性发生了质的跃迁。策略不只要选择当前最优动作，还要考虑未来的状态价值；不只要处理即时反馈，还要在延迟奖励下进行信用分配（Credit Assignment），也就是判断多步序列里到底哪一步对最终结果贡献最大。这里举的例子很日常：一个客服 Agent 用了 10 轮对话解决了用户问题，最终获得好评，这个好评该归功于第 2 轮的精准提问，还是第 7 轮的耐心解释？

这里讨论的多轮交互，正是第一章和第四章描述的 ReAct 循环，每一轮就是一次思考→行动→观察的迭代。奖励延迟来自一个结构性约束：最终结果的好坏要到多轮之后才能判断。

图 8-14 单轮 RL 与多轮 RL 对比：

> 左栏「单轮（Single-turn）」，代表任务为 GeneralPoints / AdaptThink：`Prompt: "用 [7,J,3,5] 算 24"` → LLM 一次性生成思考 + 答案 → 验证答案 → $R \in \{0,1\}$ → 策略更新；栏下三行小结：无状态维护 · 即时奖励 · 信用分配简单。

实验 8-12 ★★★：V-IRL-VL，多轮视觉导航。V-IRL 让 Agent 在真实城市街景中连续导航：训练使用纽约路线，测试迁移到不同城市，并同时改变方向表达和视觉外观。RL 在规则和视觉 OOD 上都明显优于 SFT，说明在多轮任务中，策略需要学会根据当前观测重新规划，而不是复现训练轨迹。实验使用带价值网络的 PPO，并观察到逐步反馈能缓解长时序信用分配。（脚注 a：Yang, Jihan et al., "V-IRL: Grounding Virtual Intelligence in Real Life", 2024. arXiv:2402.03310）

实验 8-13 ★★★：SimpleVLA-RL，结果奖励下的开放探索［扩展实验］。SimpleVLA-RL 在 LIBERO 机器人任务中只使用成功/失败结果奖励。每个任务仅用一条演示轨迹做 SFT 冷启动，随后 RL 将成功率从 17.3% 提升到 91.7%，并发现演示中没有出现的「推切」动作。它与 V-IRL 形成对照：过程信号容易定义时能加速学习，最优路径未知时稀疏结果奖励反而保留更大的探索空间。

信用分配之所以被称为「质的跃迁」，是因为单轮的信用分配是平凡的：一个输出对应一个奖励，直接把奖励乘到这条输出的每个 token 上就行。多轮里一条轨迹上有几十个决策点、每个决策点又有几百个 token，终点的一个标量要摊回到所有这些位置上，而「哪一步真正起了作用」在数据里没有任何标注。本章从 8.9（PPO 的价值网络、GRPO 的组内比较）到 8.12（过程奖励、RLVP 路径信号）反复回到同一个问题：怎么把稀疏的终点信号变成可用的位置信号。

两种奖励设计的取舍可以画成一条轴。左端是「密集但受限」，每步都给分，学得快，但把模型按在设计者的路径上；右端是「稀疏但自由」，只有终点成败，探索空间最大，训练慢、信用分配难。V-IRL-VL 与 SimpleVLA-RL 恰好站在这条轴的两端。这里的结论是没有普适答案：过程信号容易定义时能加速学习，最优路径未知时稀疏结果奖励反而保留更大的探索空间。

SimpleVLA-RL 的「推切」动作是本章最漂亮的一个证据：这个动作从未出现在人类示范里，却因为只给终点奖励、保留最大探索自由度而被模型自己发现。它同时说明了 RL 的价值边界：奖励无法识别的质量学不到，探索不到的策略也发现不了（这两句是 8.1.5 的原话，本章后面的实验正是它的实证）。

### 8.11.2 工具调用：把环境带进Agent

多轮任务一旦接入外部工具，动作就不再只是「移动或回答」，而是搜索、执行代码、修改文件、查询数据库和组合多个 API。信用分配、环境工程和安全约束于是都成了工具调用中的核心问题。

图 8-16 工具调用 RL 奖励循环：

> 示意图：一个五点闭环，从策略模型出发绕回策略更新：
>
> 策略模型 $\pi_\theta$ → 生成 action：思考/搜索/代码/回答 → 工具执行：API 调用 / 代码沙箱 → 结果解析：成功/失败/错误信息 → 奖励计算：正确 +1 / 错误 −1 → 策略梯度更新 →（回到策略模型）。
>
> 图右侧另列工具使用 RL 的三层挑战：
> - 第一层：单工具掌握（何时调用 + 如何调用 + 错误处理）；
> - 第二层：多工具选择（搜索 / 代码 / 文档解析 三选一）；
> - 第三层：工具链编排（依赖管理 + 互斥约束 + 成本优化）。

三条代表路线：Search-R1 代表检索增强路线，模型自主决定何时搜索、搜索什么，并利用返回结果继续推理（脚注 17：Jin, Bowen et al., "Search-R1: Training LLMs to Reason and Leverage Search Engines with Reinforcement Learning", 2025. arXiv:2503.09516）；ReTool 把代码解释器嵌入思考循环，模型需要学会何时执行代码、如何读取反馈、如何根据报错修正；AWorld-train 提供 MCP 多工具沙盒，进一步引入工具选择、依赖管理、状态重置和可重放性问题。

工具轨迹有一个关键实现细节，这里特别标出：环境返回的 token 不是策略生成的，计算策略梯度时应屏蔽这些反馈 token，只对模型自己的思考和工具调用参数回传梯度。否则模型会被训练去预测沙盒输出，而不是学会如何使用工具。

这条实现细节值得单独记住。一条工具调用轨迹里的 token 其实来自两个不同的分布：模型自己生成的（思考、工具名、参数）和环境返回的（API 结果、报错、解释器输出）。一视同仁地做策略梯度，模型会被推着去提高「预测沙盒输出」的概率，比如学会猜测 `[-4, 2]` 这种具体结果，而不是学会正确地调用工具。屏蔽这些 token 等价于告诉优化器：这些位置不是模型的选择，不该由它们负责。它与 SFT 里「只在回答 token 上算损失」是同一个思想的延伸。

实验 8-14 ★★★：ReTool，代码解释器增强数学解题：

> 图 8-17 ReTool 交织文本-代码思考与沙盒执行反馈循环：
>
> 循环链条为：文本思考₁（"需要求解方程 $x^2+2x-8=0$，先用 sympy 求解…"）→ 代码生成₁（`<code>` `from sympy import *` / `x=symbols("x")` / `solve(x**2+2*x-8,x)` `</code>`）→ 沙箱反馈₁（`<interpreter>` `[-4, 2]` `</interpreter>`）→ 文本思考₂（"解为 $x=-4$ 或 $x=2$，验证：$2^2+2\times2-8=0$，成立"）→ 最终答案（`\boxed{-4, 2}`）。
>
> 图侧标注的执行环境是 SandboxFusion：128 并行 worker、Python 沙箱执行、sympy/numpy/scipy、超时控制 + 内存限制；标注的箭头是「代码」下行、「结果」上行，整体属于 PPO 训练循环。
>
> 图底给出训练配置与结果：基础模型 Qwen2.5-32B；SFT 冷启动 ~1 小时；RL 训练 ~9 天 / 400 步；每步：32 题 × 16 候选 = 512；平均 7–9 轮交互/响应；AIME 2024 准确率：SFT 基线 25% → 110 步后 52% → 400 步后 67%。

这里正文里补充说，ReTool 在 SFT 预热后，用交织的文本思考、代码执行和解释器反馈进行 PPO 训练。它展示了工具反馈如何改变思考策略：模型逐渐学会主动执行、读取错误并自我修正。训练数据来自 DAPO-Math-17k，但优化算法仍是标准 PPO。（脚注 a：Feng, Jiazhan et al., "ReTool: Reinforcement Learning for Strategic Tool Use in LLMs", 2025. arXiv:2504.11536；脚注 b：Yu, Qiying et al., "DAPO: An Open-Source LLM Reinforcement Learning System at Scale", 2025. arXiv:2503.14476）

结果是：在 AIME 2024 上，训练从约 25% 提升到 67.0%；相比纯文本 RL，代码反馈让模型更快学会精确计算和纠错。详细的训练动态与沙盒配置见实验配套说明。

ReTool 的数字可以互相验算（验算是这里补的，这里只给了结论）。每步 $32\ \text{题} \times 16\ \text{候选} = 512$ 条 rollout。RL 与 SFT 的耗时比：SFT 冷启动约 1 小时，RL 约 9 天，$9\ \text{天}=9\times24=216\ \text{小时}$，即 216 倍；这里在 8.13 的说法是「ReTool 的 RL 训练时间是 SFT 的 200 倍以上（9 天 vs 1 小时）」，与这个 216 倍一致，「200 倍以上」是保守说法。AIME 2024 的进度是 25% →（110 步）52% →（400 步）67%，从基线到 110 步涨了 27 个百分点，从 110 步到 400 步又涨了 15 个百分点，收益前快后慢，这和大多数 RL 曲线的形状一致。

实验 8-15 ★★★：AWorld-train，在沙盒中学习使用工具：

AWorld-train 的 14.6× 也可以复算（复算是这里补的）：$7\ \text{天}=168\ \text{小时}$，$168/12=14$ 倍。这里写 14.6×（7 天 → 12 小时），若要精确等于 14.6，起点约为 $14.6\times12=175.2$ 小时 ≈ 7.3 天，可见「7 天」与「12 小时」都是约数，这是这里的表述方式，不算矛盾。

AWorld-train 强调「不是刷新 GAIA 指标」是一条方法论提醒。开放式工具任务的绝对分数受评测环境影响极大（GAIA 的参考线是「大模型约 32%」），用一个小模型（Qwen3-4B）去刷分意义有限；真正有价值的是验证「可重置、可重放的多工具训练链路」能不能跑通，也就是 8.10 讲的环境工程。在能力尚未形成规模时先验证基础设施、再谈指标，这个态度值得学。

这一节的收束句说的是：这些场景共同说明，多轮 Agent 的训练难点落在环境反馈是否可靠、动作链是否可验证，以及最终奖励该如何归因到中间决策上，而不在「有没有一个更复杂的优化器」。

工具调用为什么比「移动/回答」难一层，看图 8-16 右侧的三层挑战就清楚了，它其实是组合复杂度的递增：单工具是「会用」，多工具是「会选」，工具链是「会编排」。其中最容易被低估的是第三层。依赖关系（B 必须在 A 之后）、互斥约束（两种工具不能同时用）、成本预算（API 调用要花钱）都是跨步骤的约束，不能靠单步奖励表达，只能靠路径信号或额外的规则验证，这正是 8.12.4 的 RLVP 要处理的问题。

几个容易混的地方顺手理一遍。「回合（turn）」与「step」不是一回事：一个 step 是一次参数更新，包含一批 rollout；一个 turn 是多轮任务里的一次「思考→行动→观察」。一个 rollout 可能包含几十个 turn，而一批 rollout 才构成一个 step。

过程奖励不是中间步骤奖励越多越好。它解决的是信用分配的难度，代价是限制探索（这里图 8-15 里标为缺点的那一项），而且标注和验证成本更高。加过程奖励之前要先问：中间步骤的「对」有公认标准吗？没有标准的过程奖励，等于把设计者的偏好写进训练。

环境返回的 token 要不要算损失，答案是不算，屏蔽。这与「多轮任务里模型也说了很多话」不矛盾：算的是模型自己生成的 token，不算的是环境的回声。

Search-R1 / ReTool / AWorld-train 三者的层次也值得分清：Search-R1 是单工具（搜索）；ReTool 是单工具（代码解释器）但嵌进了思考循环；AWorld-train 是多工具沙盒（26 个服务器、126 个函数）。前两者验证「会不会用」，后者验证「会不会选和编排」。

多轮的难点是延迟奖励下的信用分配，过程奖励换收敛速度、结果奖励换探索空间（V-IRL-VL vs SimpleVLA-RL）；接上工具后还有一条实现铁律，环境返回的 token 必须屏蔽，只对模型自己的输出回传梯度。

## 8.12 奖励设计：如何把任务目标变成学习信号

前面的单轮、多轮和工具调用场景说明了「要训练什么」，这一节回答「环境应该怎样告诉模型做得好不好」。

奖励设计可以沿三个互补维度展开：奖励来自哪里、什么时候给、要表达多少信息。此外还要讨论一个额外问题：结果正确时，路径是否也合规。它们依次对应 8.12.1、8.12.2、8.12.3、8.12.4。

这三个维度的顺序，其实就是先想清楚奖励从哪来、再想清楚什么时候给、然后才想清楚给多少信息。三个问题的难度是递减的：来源决定奖励可不可信（最根本），时机决定信号密不密（影响样本效率），表示决定信号里能装多少内容（影响可控性）。实践中最常见的错误是跳过前两个问题，直接去设计一个复杂的三维奖励函数。这里在 8.12.3 对此有一句很直接的警告：「不要为了『奖励更丰富』而堆叠不可验证的维度」。

### 8.12.1 奖励来自哪里：规则、人类偏好与模型评判

最可靠的来源是可验证奖励（RLVR）：用测试用例、数据库断言、状态差异或格式检查直接判断结果。数学答案、代码测试和结构化工具调用都适合从二元结果奖励开始。规则越确定，奖励越便宜、可复现，也越不容易被模型钻空子。

说 RLVR「最可靠」而不是「最好」，是因为它的强项和弱项都很清楚。它便宜、可复现、难钻空子，却只能表达能被规则判定的目标。开放式任务（写一段有说服力的文案、做一个好的设计）无法用测试用例判定，才不得不退回到偏好或模型评判；而一旦退回，奖励就从「事实」变成了「代理」，hacking 与 seeking 的风险随之回来。所以能用 RLVR 就用 RLVR，用不了时要额外花成本做校准，比如人工抽检和事实校验。

RLHF 在这里只作为背景。InstructGPT 的基本流程是人工比较回答、训练奖励模型，再用 PPO 优化策略（脚注 18：Ouyang, Long et al., "Training Language Models to Follow Instructions with Human Feedback", OpenAI, 2022）。奖励模型只是偏好的代理，过度优化会导致 reward hacking（脚注 19：Gao, Leo, John Schulman, and Jacob Hilton, "Scaling Laws for Reward Model Overoptimization", OpenAI, 2023），因此通常用 KL 正则把策略锚定在 SFT 参考模型附近。DPO 跳过显式奖励模型，直接从偏好对做离线优化（脚注 20：Rafailov, Rafael et al., "Direct Preference Optimization: Your Language Model is Secretly a Reward Model", 2023）；这些方法不是本章 Agent RL 的主线。

KL 正则的作用对象是「策略离参考模型多远」，不是「奖励高低」。它防止策略为了拿高分而漂移到奖励模型的盲区之外，属于抑制 reward hacking 的手段，而不属于奖励本身（虽然它通常会以惩罚项形式进入目标函数）。

目标难以完全规则化时，可以使用模型评判。生成式奖励模型（GRM）不只输出一个分数，还生成「哪里做得好、哪里需要改」的诊断；它既可以作为奖励来源，也可以把诊断转成后续蒸馏或偏好数据。DeepSeek-GRM 的核心思路是让模型先归纳任务评价原则，再按原则评价轨迹，最后用可验证事实检查评价是否正确（脚注 21：Liu, Zijun et al., "Inference-Time Scaling for Generalist Reward Modeling", 2025. arXiv:2504.02495）。这样得到的反馈更透明，但仍需抽样人工校准，防止评判器形成新的偏差。

GRM 这个「先归纳评价原则、再评价、再用可验证事实检查」的三步设计很聪明。第一步把隐含的评分标准显式化，可被人审阅、可复用；第二步用这个标准去评价轨迹；第三步用可验证的事实反过来检查评价本身对不对。第三步是关键的防退化机制：评判器出现系统性偏差时，这一步能捕捉到。这里仍然要求抽样人工校准，因为第三步只能检查「事实类」的错，检查不了「口味类」的偏好偏差。

这里专门区分了两个容易混淆的概念。reward hacking 是钻规则或实现漏洞拿高分；reward seeking 则是模型先在心里建立一个「评判器会看什么」的模型，再按这个猜测调整行为。后者不一定篡改测试或伪造结果，却可能在长程任务中自行设置一个过于简单的检查，刚好通过就提前结束，交付物因此只满足代理指标而没有满足真实意图（脚注 22：storm，"长程智能体自我检查与早停行为：Reward Seeking 现象及其缓解措施"，青稞社区，2026 年 8 月 6 日）。

拿个例子就分得清这两者。hacking 的样子是：测试文件可以被改写，模型就把断言删掉，这是攻击规则或实现。seeking 的样子是：模型没动任何测试，只是自己判断「跑一个最简单的检查就够了」，然后据此提前收尾，这是猜测评判器的偏好并迎合它。seeking 更隐蔽，因为它产生的东西看起来完全合规，只是交付物只满足了代理指标。

这里的结论句是：所以「通过了 grader」不能自动等价于「任务完成了」，评判器是意图的代理，训练越强，模型越可能把代理当成目标本身。这句话值得当成一条原理来记：它讲的是优化压力的必然结果，与模型的道德无关。只要代理指标与真实意图之间存在缝隙，优化就会往缝隙里钻。

### 8.12.2 奖励在什么时候给：结果还是过程

结果奖励（ORM）只在 episode 结束时判断任务是否完成，它最简单，也给策略最大的探索自由度。当中间路径没有公认标准、最优解尚未被人类发现时，SimpleVLA-RL 的稀疏成功/失败奖励就是合适的起点。代价是稀疏反馈让模型难以判断多步轨迹中的具体错误，这也是长期以来 RL 样本效率受限的原因之一（脚注 23：Silver, David and Richard S. Sutton, "Welcome to the Era of Experience", 2025）。

ORM 里带「模型」二字只是历史叫法，本章语境下它的实际操作往往是规则或测试判定，不一定真有一个模型。

判定权不能交给模型自己。在长程 coding 或 cowork 任务中，还应把「是否完成」的判定交给模型写不了的隐藏测试、状态断言或外部终止钩子，而不能只依赖模型自己声称完成。

「过早结束」是一个具体例子。模型说任务完成时，Harness 在隔离工作区运行模型看不到的验收测试；通过才给正奖励，未通过则给负奖励。测试必须读取真实文件或环境状态，不能只检查模型是否说了「已完成」，否则模型可能学会口头承诺验证而不真正验证。评估时还要把任务未完成的边界集和确实已经完成的保留集分开：前者观察过早结束率，后者观察模型是否仍然能够正常收尾，避免把模型训练成永远不敢结束。

过程奖励（PRM）在中间步骤提供反馈，例如检查身份验证、工具参数、测试通过数或导航动作。OpenAI 的《Let's Verify Step by Step》展示了逐步验证在数学推理中的价值（脚注 24：Lightman, Hunter et al., "Let's Verify Step by Step", OpenAI, 2023）。过程奖励能缓解长时序信用分配，却可能把模型限制在设计者预设的路径上，而且标注和验证成本更高。

所以「过程奖励更好」是有条件的：只有当中间步骤的「对错」有公认标准且可验证时（例如「是否先做了身份验证」），它才划算。路径本身没有公认标准时，过程奖励会把设计者的路径偏好固化进模型。

两种奖励的对照实验是现成的：V-IRL-VL（实验 8-12）采用逐步导航反馈，SimpleVLA-RL（实验 8-13）保留终点奖励，两者构成「密集反馈换收敛速度、稀疏反馈换探索空间」的对照。工程建议是，可以先用结果奖励建立可靠基线，再只为真正可验证的中间事件加入过程信号。

折扣因子与信号摊分随后登场。多轮 LLM RL 通常将折扣因子设为 $\gamma=1$；PPO 的价值网络或 turn-level 优势负责把终点反馈归因到较早的动作，GRPO 则把轨迹级优势均摊到生成 token，长轨迹上需格外注意信号稀释。

$\gamma=1$ 这条配置值得单独记。折扣因子 $\gamma$ 决定未来的奖励在当下值多少钱，$\gamma=1$ 表示未来奖励不打折。多轮 Agent 任务通常只在终点给一次成败奖励，如果 $\gamma<1$，越早的动作分到的信号越弱，信用分配会更难；所以这里取 $\gamma=1$，把「该不该早点行动」这类时间偏好交给奖励设计本身（比如给拖延加惩罚），而不是交给折扣因子。这也是多轮 Agent RL 与经典 RL 的一个显著差别：经典 RL 常见 $\gamma=0.99$，多轮任务更常见 $\gamma=1$。

信号稀释可以算一下（这个推算是这里补的，这里只给了结论）。GRPO 把整条轨迹的优势（一个标量）均摊到所有生成 token 上。假设一条轨迹有 10,000 个 token、优势为 1，每个 token 分到的信号量级是 $1/10{,}000$；轨迹长到 100,000 token，每 token 信号就只有 $1/100{,}000$。轨迹越长，单位 token 上的学习信号越弱，这就是这里所说「长轨迹上需格外注意信号稀释」。PPO 之所以在长轨迹上仍有优势，正因为它有逐状态的价值基线，能给不同位置算出不同的优势，而不是均摊同一个数。

### 8.12.3 奖励需要表达多少信息：标量、向量与生成式诊断

这里先把一件事切干净：奖励的密度和表示形式是两件事。

表示形式有四种。标量只回答「总体多好」；半标量先给简短理由再给分数；向量按准确性、完整性、成本和安全等维度分别打分；生成式奖励则给出自然语言诊断，并可多次采样后汇总。

选择原则，这里给了三条：

1. 有确定答案或测试：优先二元标量；
2. 有多个相互独立的质量目标：使用向量，或将各维度加权成标量；
3. 开放式、难以穷举规则：使用生成式诊断，但要配合事实校验和人工抽检。

警告也随之而来：不要为了「奖励更丰富」而堆叠不可验证的维度。每增加一个评价维度，就增加一种被策略钻空子的可能。先确认这个信号能在少量 rollout 中产生有意义的组内差异，再决定是否加入训练。

这一节的核心是一句反直觉的话：维度越多不等于信号越好。原因在 GRPO/PPO 的机制里。策略只需要「组内谁更好」这一个排序信息，多出来的维度如果区分度低（同一个组里所有 rollout 在这个维度上都拿满分），它就只增加了被钻空子的表面积，没有增加学习信号。这里给的判据是「先确认这个信号能在少量 rollout 中产生有意义的组内差异」，这与 8.9 第三步、8.12.4 的「恢复组内差异」是同一把尺子。

四种表示形式可以按「信息量 vs 可验证性」排成一排（这张表是这里补充的整理，这里只列出四种形式的定义与选择原则）：

| 形式 | 信息量 | 可验证性 | 典型用途 |
| --- | --- | --- | --- |
| 标量 | 最低（只有总体好坏） | 最高（通常来自测试/规则） | 数学答案、代码测试、结构化调用 |
| 半标量 | 低（一句话理由 + 分数） | 中 | 需要一点解释但不想引入复杂评判 |
| 向量 | 中（分维度） | 中（各维度仍需可验证） | 准确性/完整性/成本/安全等多目标 |
| 生成式诊断 | 最高（自然语言） | 最低（需事实校验 + 人工抽检） | 开放式任务 |

奖励「密度」与奖励「表示」要分开：密度是多久给一次（结果 vs 过程），表示的是一次给多少信息（标量/半标量/向量/生成式）。这里开头那句「奖励的密度和表示形式是两件事」，防的就是这两个概念被混为一谈。

向量奖励与过程奖励也不在同一个轴上：向量奖励是在同一个判定点上给多个维度（比如「这次回答的准确性 0.8、完整性 0.5」），过程奖励是在多个判定点上各给一次。两者可以叠加，比如每一步都给一个多维分数。

### 8.12.4 结果正确还不够：路径约束与RLVP

结果奖励解决了「事情有没有办成」，却表达不了「是否按规定办成」。真实 Agent 可能通过改测试文件、跳过身份验证或执行破坏性命令获得表面成功。

RLVP（Reinforcement Learning with Verified Penalty）的原则是：奖励结果，惩罚路径（脚注 25：Li, Bojie, and Noah Shi, "RLVP: Penalize the Path, Reward the Outcome", 2026. arXiv:2607.07435）。它针对的是可机器判定的、与最终成败无关的结果中性约束，不能替代对语义意图、交付完整性和早停行为的独立检查。

真实环境通常是非对称验证器：检测「做了一个坏动作」便宜而可靠，证明「这一步确实朝着目标取得了有意义的进展」却很难。

总奖励的公式是

$$
R = O + \beta\,\Phi
$$

其中 $R$ 是每一步（或每条轨迹）最终用于训练的总奖励；$O$ 是任务结果（outcome），即最终状态是否达成目标；$\Phi$ 是由确定性规则逐动作计算的路径信号（path signal）；$\beta$ 是路径信号的权重系数（无量纲，用来调节路径项相对结果项的分量）。两路的用法是：对可验证的违规动作扣分，对可验证的合规动作或可达子目标给少量部分奖励；两路归一化后再合并，避免路径信号淹没主目标。

RLVP 不改变 PPO/GRPO，只改变每一步看到的奖励。实现层面的伪代码，这里给出的是：

```python
outcome = verify_final_state(trajectory)      # result, not self-report
path_signal = 0
for step in trajectory:
    path_signal += deterministic_path_signal(step)   # penalty or reachable progress
reward = normalize(outcome) + beta * normalize(path_signal)
```

伪代码里的三个细节值得注意。`verify_final_state(trajectory)` 的注释写着 `# result, not self-report`，意思是用最终状态判定，而不是模型的自我报告；`deterministic_path_signal(step)` 的注释写着 `# penalty or reachable progress`，要么惩罚、要么可达进展；最后 `normalize(outcome) + beta * normalize(path_signal)` 里的两次 normalize 是为了避免量纲差异让路径信号淹没主目标。

边界说明也要带上：路径信号中的允许动作、可达子目标、隐藏测试和证据记录依赖具体环境；正文只说明「结果奖励」和「路径约束」如何合并，避免把某个环境的规则误当成通用算法。

RLVP 的关键落在能否恢复组内差异，而不在把奖励铺得更密。纯结果奖励在全败组和全胜组都会产生零方差、没有梯度；违规动作通常容易检测，惩罚几乎总能恢复差异；进展奖励只有在部分进展可达时才有效。

这里给了四点设计原则：

1. 只惩罚具体动作，不惩罚「不够努力」；
2. 结果奖励始终保留，避免模型学会什么都不做；
3. 每个惩罚最好配一条可达的合规路径；
4. 规则必须确定、难以钻空子。

冷启动路径是：如果基础策略根本不会采样合规动作，应先用少量示范把这条路径「种」出来，待合规行为稳定后再逐步减弱路径塑形。这里的收束句是，惩罚是通常可达的那一半，进展奖励是受可达性门控的那一半。

公式与「非对称验证器」是配套的。因为坏动作好检测、好进展难证明，所以 $\Phi$ 里惩罚项是主力、进展项是辅助。设计路径信号时应当先做惩罚（几乎总有效），只有在确认「部分进展可达」之后才加进展奖励。

「全败组」和「全胜组」为什么致命，值得想清楚。GRPO 的相对优势来自组内比较，组内奖励全相同时方差为零，优势全部为零，梯度为零，这个 step 的采样预算就白花了。RLVP 的违规惩罚之所以有效，是因为它几乎在任何一组里都能区分出「有违规」与「没违规」；进展奖励则只有在有一部分 rollout 完成了部分子目标时才能区分。这里要求「先测信号可达性」，原因就在这里：所有 rollout 都通不过任何测试时（软件修复的例子），进展信号不可达，加了也白加。

实验 8-16 ★★★：RLVP，奖励结果、惩罚路径。在 GRPO 上加入结果奖励 $O$ 与路径信号 $\Phi$，对比纯结果奖励。TerminalBench 上违规次数由 3.71 降至 0.66，而成功率基本持平；miniF2F 上可达的部分奖励把达到 0.9 成功率所需迭代从 7.0 降至 4.4。软件修复中若所有 rollout 都无法通过任何测试，进展信号不可达，加入它不会带来收益。这个实验提醒我们：先测信号可达性，再决定是否增加奖励维度。

两组数字说明了两种信号的不同作用（解读是这里补的）。TerminalBench 上违规 3.71 → 0.66 而成功率基本持平，说明路径惩罚几乎不改变「办没办成」，只改变「怎么办成的」，这正是 RLVP 想要的效果，它只针对与最终成败无关的结果中性约束。miniF2F 上达到 0.9 成功率所需迭代 7.0 → 4.4，是进展奖励加速收敛的证据，降幅约 $1-4.4/7.0\approx37\%$（复算是这里补的）。两个环境的差别正好对应「惩罚通用、进展受可达性门控」这句话：TerminalBench 上有效的是惩罚项，miniF2F 上有效的是可达的进展项。

RLVP 的 $\Phi$ 与 PRM 的过程奖励不是一回事：$\Phi$ 由确定性规则逐动作计算，属于可机器判定、与最终成败无关的结果中性约束；PRM 通常是一个学出来的评价模型。前者不需要训练评判器，成本低且难钻空子；后者表达力强，但引入新的评判器偏差。

$\beta$ 也不是越大越好。$\beta$ 太大会让模型只顾守规矩而忘记完成任务（这里第 2 条原则「结果奖励始终保留，避免模型学会什么都不做」正是这个风险的解药）；$\beta$ 太小则路径信号不起作用。这里没有给 $\beta$ 的推荐值，这属于具体环境的调参问题。

工程落点上，RLVP 只改奖励、不改优化器，因此它是本章里最低风险的一个改进方向，可以在不改动 PPO/GRPO 代码的前提下，把验证器的输出拆成两路再接进去。

外推的限度也要说清楚：这些数字来自可控的代理环境，不能直接外推为线上 Agent 也会获得同等提升。更稳妥的结论是机制性的：只要路径信号能在同一组 rollout 中区分行为，且规则不易被策略钻空子，它就能补上终点奖励看不见的那部分信息。对于真实部署，还需要把隐藏验证、轨迹监控和外部终止条件一起纳入 Harness。

奖励来源的可信度排序是：规则/测试（RLVR）高于模型评判（GRM，需校准），模型评判又高于人类偏好（RLHF，仅作背景）；时机上，结果奖励建基线，过程奖励只加在真正可验证的中间事件上；同时记住「通过 grader」不等于「完成任务」。表示形式上，能用二元标量就别上向量和生成式，每多一个维度就多一个被钻空子的入口；路径约束上记住 $R=O+\beta\Phi$ 与「奖励结果、惩罚路径」，而它成立的关键前提是先把组内差异找回来。

## 8.13 蒸馏：提升样本效率

前面的实验已经系统展示了 RL 在 Agent 训练中的核心价值，但都付出了高昂的样本成本。

这里的「样本效率」有特定含义：每次昂贵的环境交互，能带来多少有效的参数更新，而不只是训练步数或 GPU 时间。ReTool 的 RL 训练时间是 SFT 的 200 倍以上（9 天 vs 1 小时），减少环境采样因此尤其重要。

RL 样本效率低的根本原因，除了高方差和在轨数据难复用，更根本的是反馈太稀疏。主流 model-free RL 通常只在一条 rollout 结束时得到一个成败标量，中间的错误原因、缺少字段、流程提示都没有直接的学习信号。这里的例子很具体：客服说「需要信用卡后四位」，模型却只能从最终的 0/1 结果反复试错，可能要数百次交互才偶然学会这一步，而人类听到一次就能记住。

蒸馏的作用就是把一次 rollout 变成密集的监督信号：不必额外探索更多环境轨迹，同一条轨迹就能贡献大量梯度，这是它提升样本效率的关键。

### 8.13.1 在轨蒸馏：让一次rollout 产生密集监督

在轨蒸馏（On-Policy Distillation）由 Thinking Machines Lab 于 2025 年系统整理并推广（脚注 26：Thinking Machines Lab, "On-Policy Distillation", 2025）。这里的「policy」指谁生成学生将要学习的状态前缀，不是指谁提供监督。

三者的互补逻辑，这里的推理链是这样的。SFT 的监督很密集，却主要覆盖教师会走到的状态；学生部署后若在早期犯了教师不会犯的错误，就会进入训练数据没有覆盖的前缀，后续每一步都在陌生状态上预测，误差可能沿长序列累积。On-policy RL 直接在学生自己的状态分布上训练，相关性更高，却常常只在轨迹结束得到一个成败信号。On-policy Distillation 把两者组合起来：学生决定走到哪里，教师负责在学生已经走到的位置告诉它下一步的完整概率分布。

三种方法的分工可以用一句话概括：「谁走路径」和「谁给监督」是两件独立的事。SFT 是教师走路径、教师给监督，所以密集但会偏离学生实际状态；On-policy RL 是学生走路径、奖励给监督，所以贴合学生但稀疏；On-Policy Distillation 是学生走路径、教师给监督，既有相关性又有密度。这里那句「这里的 policy 指谁生成学生将要学习的状态前缀，不是指谁提供监督」强调的就是这个二维拆解。很多人误以为 on-policy 指的是教师和学生同步更新，其实它指的是训练状态来自学生自己的采样。

为什么「在学生走到的状态上给监督」这么关键，可以拿开车做比方。教师给的示范地图只覆盖教师走过的路线，学生一旦在第一个路口就拐错，后面的每一步都在地图之外，误差沿着长序列滚雪球，这正是暴露偏差的直觉。On-Policy Distillation 的做法是让学生自己开，教师在每一个学生实际到达的位置告诉他这里下一步该怎么走：路线是学生的，指导是教师的。

收益的量级很实在：一条长度为 $T$ 的 rollout 不再只产生一个 0/1 信号，而能产生约 $T$ 组逐 token 监督。它比离轨 SFT 更贴近学生实际会犯的错，比纯 RL 的反馈更密集、方差更低；教师推理增加的是计算，却不需要再采一批环境轨迹。

逐 token 分布与二元奖励差在哪里，这里那个 80%/15%/5% 的例子值得细看。学生生成「先查询 API，再解析返回值……」时，教师可以在「查询」这个 token 的位置给出「查询」80%、「调用」15%、其余 5% 的 token 分布。二元奖励只说这句话最终对不对；教师分布说的是在这个位置应该用「查询」，而不是「调用」，并且给出 80% 与 15% 这样的程度。后者不但告诉你对错，还告诉你对错的程度和方向，它是一个完整分布而不是一个标量，所以一条 200 token 的输出能提供 200 组监督，而不是 1 个 0/1。这就是「一条 rollout 产生约 $T$ 组监督」的由来。

它也不是万能的。这里的限定是：它同样不是「从零创造能力」的办法，学生至少要能进入教师可纠正的有效状态，教师策略也不能离学生的有效支持太远。基模连目标语言、领域概念或基本动作都没有时，仍应先 Mid-training 或用离轨示范冷启动，再切换到在轨蒸馏。

与 8.9.1.1 数值问题的衔接是：在轨蒸馏优化的是「学生当前策略所访问状态上的教师 KL」；如果 rollout 引擎实际从 $\mu$ 采样，而 trainer 计算的是另一个 $\pi_\theta$，即使不显式使用 PPO 的概率比，训练状态也已经离轨。实现时仍应做「更新前 sampler/trainer log probability 是否一致」的检查，否则名义上的 On-policy Distillation 也会退化成带分布错位的训练。

具体做法是让学生的预测分布贴近教师分布，通常最小化两者的 KL 散度。代价是教师推理成本，因此在环境交互昂贵时尤其划算。

在轨蒸馏的基本伪代码（这里给出）：

```python
student_trajectory = rollout(student, task)
loss = 0
for state in student_trajectory:
    teacher_logits = teacher(state)
    loss += KL(student_logits(state), teacher_logits)
update_student(loss)
```

效率数字是这样的：在数学等任务上，达到同等性能所需的训练步数约为纯 RL 的 1/10。在多轮 Agent 中，成败信号更晚、更稀疏，逐 token 的教师分布能直接指导中间决策；但前提是仿真环境足够真实，让学生探索到的状态接近部署分布，否则教师对陌生偏差状态的评分也不可靠。

顺带把两个容易摆错坐标系的倍数说清楚：样本效率的「1/10 步数」与「200 倍耗时」并不矛盾。ReTool 的 200 倍说的是 RL 相对 SFT 的墙钟时间，环境交互贵；1/10 说的是在轨蒸馏相对纯 RL 的步数，同样的环境交互预算下更快达到目标。前者比的是训练范式之间的成本，后者比的是在 RL 范式内部换监督信号的收益。

一个纯 Agent 场景的验证值得一提：「稠密信号胜过稀疏信号」在一个纯 Agent 场景中也得到过验证。笔者和合这里曾在「时间感」任务上比较 DPO、四种 RL 与 On-Policy Distillation：前者分别受到稀疏奖励、目标错位、rollout 形状不匹配和策略崩溃的限制；换成冻结的 Qwen3-32B 教师，在学生自己的多轮轨迹上逐 token 对齐后，训练平滑收敛，四种条件下通过率比同源 SFT 基线高出 23 到 47 个百分点（脚注 27：Li, Bojie, and Noah Shi, "Agents That Sense Physical Time: Urgency, Persistence, and Vigilance as Missing Controls for LLM Agents", 2026）。这说明瓶颈多半出在每次交互提供的信号不够密，而不在奖励函数不够复杂。

「训练平滑收敛」这件事本身也是信息。它提示：当 RL 曲线剧烈震荡时，问题可能不在优化器，而在每条轨迹提供的监督信号太稀。这与 8.9.1.1 的数值问题、8.15 的陷阱 8（价值函数崩溃）构成三类不同的失稳原因，排查时要分开看。

几个容易混的地方：在轨蒸馏的 on-policy 指数据来源，不指教师更新，教师通常是冻结的（这里例子直接用「冻结的 Qwen3-32B 教师」）。离轨蒸馏（SFT 式）与在轨蒸馏都用教师监督，区别在状态前缀由谁产生，前者由教师或人类产生，后者由学生产生。

OPSD 与自我训练、自我提升不是一回事，它需要特权信息（标准答案等）作为教师的额外输入；没有特权信息，同一个模型无法比自己给出更好的分布。它也不创造新知识。这里说得很明确：「如果模型拿着答案也讲不清过程，自蒸馏就没有额外信号」。它提高的是样本效率，把已有能力更快地压进参数，不抬高能力上限。

### 8.13.2 没有更强的教师怎么办：On-Policy 自蒸馏

On-Policy Distillation 的威力来自教师，也因此背上了一个硬前提：必须有一个明显强于学生的教师模型。这在很多场景里并不成立。要训练的是垂直领域模型、而现有模型的能力都存在不足时，就没有教师模型可用。这里设问：没有更强的教师，稠密信号的红利就与我们无缘了吗？

一个巧妙的破题思路是 On-Policy Self-Distillation（OPSD，在轨自蒸馏）（脚注 28：Zhao, Siyan, et al. "Self-Distilled Reasoner: On-Policy Self-Distillation for Large Language Models", 2026. arXiv:2601.18734）：同一个模型分饰教师和学生两角，但看到的上下文不同。教师版能看到「特权信息」，比如标准答案或已验证的正确解答；学生版只看到问题本身，却在自己采样的轨迹上向教师版的逐 token 分布对齐。对着答案解释学生刚走过的路径，通常比独立探索更容易，因此一条 rollout 仍能产生密集监督。

OPSD 的关键机制就是「同一模型、两种上下文」：学生的上下文是问题本身，教师的上下文是问题加已验证的答案。为什么这能产生有用的信号？因为对着答案解释自己刚走过的路比独自探索容易得多，模型在知道答案的情况下能给出一个更靠谱的下一步分布，这个分布可以反过来指导学生。伪代码里的 `stop_gradient` 要注意：教师那一路不参与训练，只有学生那一路的参数在更新，否则就变成了「同时把学生拉向自己」，是个退化解。`task_without_answer` 与 `add_verified_answer(state)` 的写法也明确了一件事：答案只在训练侧注入，部署时不可见。

OPSD 是上一段伪代码的一个受限变体（这里伪代码）：

```python
student_trajectory = rollout(model, task_without_answer)
loss = 0
for state in student_trajectory:
    privileged_state = add_verified_answer(state)
    teacher_logits = stop_gradient(model(privileged_state))
    loss += KL(model(state), teacher_logits)
update(model, loss + retention_regularizer)
```

这里对两个符号的说明：`privileged_state` 只能在训练侧构造，不能泄露给部署时的 Agent；`retention_regularizer` 代表保留集或风格约束，而不是某个固定超参数。训练流程还必须检查数据权限、答案遮蔽和遗忘风险。

与 RLVR 的对比可以看出定位差别：OPSD 不要求奖励一定能被自动验证，特权信息可以是标准答案、人工示范或领域文档，它用这些信息替代更强的外部教师，同时保留「在轨采样 + 逐 token 监督」的样本效率优势。两者的定位差别可以这样记：RLVR 需要「能自动判定的奖励」，OPSD 需要「有可用的特权信息」。两者都要求有东西能告诉模型什么是对的，只是一个用测试或规则表达，一个用标准答案或文档表达。在垂直领域里（现成模型都不够强、但领域里有标准答案），OPSD 是比 RLVR 更现实的路线。

它的边界也要看清：它不会凭空创造新知识。如果模型拿着答案也讲不清过程，自蒸馏就没有额外信号；朴素 OPSD 还可能让模型丢失原有思考风格，需要额外正则稳定（脚注 29：Shen, Ziqi, et al. "Purified OPSD: On-Policy Self-Distillation Without Losing How to Think", 2026. arXiv:2607.02234）。

蒸馏提升样本效率的关键是「学生走路径、教师给监督」：一条长度 $T$ 的 rollout 从 1 个成败信号变成约 $T$ 组逐 token 监督；没有更强教师时用 OPSD（同模型、教师侧带特权答案），但它不创造新知识，也不会白送思考风格。

## 8.14 从问题案例到后训练

这一节回到第七章留下的问题：基于生产问题案例构建的评估数据集，如何真正变成后训练的输入。第七章结尾把评估环境和验证器比作后训练的基石。

核心映射是：失败归因记录、端到端回归任务、轨迹前缀回归任务、Rubric 评分各自对应不同的训练用法。

### 8.14.1 案例1：Coding Agent 过早结束

8.14 铺完映射表之后，这里用三个真实问题案例把「评估数据怎么变成训练信号」演了一遍。三个案例的写法是同一套骨架：问题描述、失败归因、训练数据构造，各配一个实验。所以读的时候，重点可以放在每一段里「归因结论把错定在哪一步」以及「这笔数据最后喂给了谁」。

前面表 8-5 的四行映射值得逐行读一遍，它其实是第七章与第八章之间的接口定义。端到端回归任务对应 RL 任务、RLVR 奖励和 RFT 采样池，原因是这类任务自带验证器，所以它既能当 RL 的环境，也能当拒绝采样的筛子，同一份数据的两种用法只取决于要不要重新采样。轨迹前缀回归任务对应 DPO 偏好对、决策边界 SFT 和在轨蒸馏的教师状态，它的价值在于「同一个前缀、不同后续」的对照，这正是偏好对天然的形状（chosen/rejected），也是「决策边界」这个说法的来源。失败归因记录对应过程监督的负标签（PRM）和 RLVP 路径惩罚的规则来源，因为归因已经指出「第一个错在哪一步、属于哪一类错」，它天然就是负标签（这一步是错的）和规则（这类动作要扣分）；要留意它是负标签，失败案例多、成功案例少，而「这里错了」比「这里对了」更容易确认。Rubric 评分与人工金标则对应向量奖励的各维度和 GRM 的训练与校准数据，多维 rubric 直接就是向量的各维度，人工金标是校准 GRM 的锚点，这与 8.12.1「GRM 仍需抽样人工校准」和 8.12.3「向量按准确性、完整性、成本和安全等维度分别打分」完全对应。

Coding Agent 最常见、也最难根治的失败之一是过早结束。测试还没跑就宣称「已完成」；用户要求改三个功能，改完两个就收尾；遇到两次失败就宣布「这个任务不可能完成」。按第七章的错误分类，这属于「任务完成度与逻辑判断问题」，生产侧的三类信号都能捕获它：用户纠正（「你根本没跑测试」）、点踩、事后审计（宣称完成的轨迹里没有任何测试工具调用）。

归因记录把首个错误定位在「准备宣称完成」的那个决策边界上。在此之前，读代码、改代码可能都没错，错的是「在缺乏证据时下结论」这一步。这里和前面奖励设计一节讲的 reward seeking 是同一类行为：自行设置一个过于简单的检查，刚好通过就提前结束。

训练数据有两条构造路线。端到端回归任务把「宣称完成前必须跑通验收测试」写成可验证奖励：测试对模型不可见，模型宣称完成时才运行，通过 +1、不通过 −1。这就是「判定交给模型写不了的隐藏测试」的直接应用，也是本案例可选的 RL 分支。轨迹前缀回归任务则在「准备宣称完成」的决策边界上截一刀，造出偏好对：被拒绝的样本是过早结束的错误行为，被选中的样本是「先运行测试、逐条核对验收条件，再下结论」的期望行为。被选中的样本由教师模型生成，再经过规则验证器过滤（拒绝采样），得到一批 DPO 训练对。问题案例太少就做数据扩充，换任务类型、换缺失的验证项、换完成措辞，凑出数百条偏好对，再按小配比混入通用任务数据做 LoRA 微调，免得把「逢收尾必验证」学成新的过拟合，灾难性遗忘的风险也能降下来。

评估这一步用了第一章命名的那个模式：边界集与保留集缺一不可。轨迹前缀边界集检查「任务未完成时，模型是否选择继续验证而非宣称完成」，保留集则负责另一面，任务确实已完成时，模型应该正常宣称完成。只盯前一个指标，会把模型训练成永远不敢收尾的过度矫正状态，每个任务都无限验证下去，延迟与成本崩溃。第七章反复强调的「改动不能破坏既有行为」在这里有了参数层面的版本，而这次的「既有行为」就是模型的收尾能力。评估还应抽查通用能力，确认 LoRA 补丁没有把别的能力一起改坏。

实验 8-17 ★★：从「过早结束」问题案例到 DPO 修复。目标是跑通从生产问题案例到参数更新的完整链路，失败归因 → 轨迹前缀回归任务 → DPO 偏好对 → 7B 模型 LoRA 训练 → 边界集与保留集双集验证。配套仓库提供 24 条写实的过早结束问题案例，覆盖四类失败（未跑测试就宣称完成、多目标只完成一部分、验收条件未满足、遇错放弃并宣称不可能，含删除失败测试这类更恶劣的 reward hacking 变体），以及与训练数据严格隔离的 held-out 评估集（boundary 12 条 + retention 8 条）。这里对它的限定说得很清楚：这是教学实验。生产中偏好对要覆盖更多任务族，保留集要覆盖更多「正常收尾」的场景，还要警惕奖励作弊的新形态，模型可能学会「口头声称去验证」而不真的验证。这也是端到端数据集的奖励必须依赖模型无法编写或修改的隐藏测试，而不是依赖模型自己的声明的原因。

## 8.14.2 案例2：中文引号

第二个案例的用户反馈只有一句话：「中文文章中的直引号应统一为弯引号。」它描述了期望，却没有给出可以直接训练的规则。同一个引号，在中文自然语言、英文示例、Markdown 行内代码、代码块、代码注释、JSON 或路径中承担的角色完全不同。

正确的修复是作用域敏感的最小编辑。中文自然语言中的引用可以转换为“”，嵌套引用按中文标点规则处理；英文示例、可执行代码、JSON/schema、路径、标识符和 Markdown 反引号中的内容必须原样保留；无法判断作用域时应保留这里。

训练数据的构造方式是把引号的使用规则写成 Skill。正例覆盖中文段落、嵌套引用以及代码注释中的中文自然语言，反例覆盖英文示例、字符串/字符字面量、JSON、路径、行内代码和整段代码。这样教给模型的是「先判断作用域，再做最小编辑」，而不是「看到直引号就替换」。

实验 8-18 ★★：作用域敏感的中文弯引号 SFT。目标是验证 LoRA SFT 能否让模型在混合中文、英文、Markdown、代码和 JSON 的文档中，准确执行「该改的引号改弯、受保护的引号不动」，并在未见过的上下文组合上保持这一边界。设置上以 Qwen/Qwen3-8B 为基座，使用 bf16 LoRA 训练 2 个 epoch（256 次更新）。`SKILL.md` 的作用域规则同时作为生成标签、质量门禁和回归规范；模型只负责选择作用域和生成最小编辑，生产侧的解析器与语法检查不被移除。数据按 16 类片段、10 种文章体裁和 9 种编程语言渲染 1024 条训练样本、256 条留出样本和 256 条边界样本。样本成对保存这里与目标文本，中文自然语言和中文代码注释提供需要转换的正例，英文示例、字符串字面量、JSON、路径、行内代码、代码块及嵌套结构提供必须保护的反例。

这个「Skill 同时是标签、门禁和回归规范」的设计很省成本：同一份规则文件既用来生成训练标签、判定样本是否合格，又当改完之后的回归规范，把规则变成唯一的真相源，三处规则不一致的问题自然消失了。这里还明确划了边界，模型只负责「选择作用域 + 生成最小编辑」，解析器和语法检查不由模型负责。本章反复出现的分工原则在这儿又出现了一次：确定性的部分交给程序，判断的部分交给模型。

### 8.14.3 案例3：编辑文件经常失败

第三个案例来自第五章讲过的工具。Coding Agent 常用 `edit_file(path, old_string, new_string)` 这样的接口，模型把要替换的 `old_string` 抄写到工具参数里，而编辑工具通常按精确字符串匹配，哪怕只差一个空格、换行、反斜杠、Unicode 组合字符或低频 token，都会返回失败。

这里的归因是一条逐层对比的链路：文件原始字节 → 工具返回 → Harness 序列化 → 模型上下文 → 模型 token 输出 → 解码字符串 → JSON/tool-call 解析 → 工具匹配。规则也按这条链路排开：若文件读取或工具返回已经改变字节，归因给工具；若序列化、转义或提示词拼装改变了内容，归因给 Harness；如果 tokenizer encode 后再 decode 发生变化，归因给 tokenizer；只有模型收到的上下文与原始字符串完全一致，而模型输出是链路上首个出现差异的位置，才能把它标为模型的精确复制能力问题，作为后训练候选。

这段流程大概是本章最有实操价值的一段。很多人一看到「模型抄错了」就直接去做 SFT，可这条链路上有 7 个可能出错的位置，其中最容易被忽略的是 tokenizer。某个字符串经过 `encode`→`decode` 之后不再等于这里（Unicode 组合字符被规范化、低频 token 无法表示），那任何模型都不可能抄对，这时候做 SFT 是白费力气。实验 8-19 特意加了独立 tokenizer 审计，就是为了排除这种假象。

训练数据的做法是把复制任务抽象成三个可验证任务：直接逐字复述；在相似且等长的多个字符串中选择完全相同的目标；把指定字符串完整抄写到 `old_string` 的工具 JSON 参数。样本特意包含真实编辑最容易损坏的空格、真实换行、反斜杠、Unicode 等内容。

实验 8-19 ★★：特殊字符串的精确复制 SFT。目标是在已确认差异来自模型抄写错误的前提下，测试 LoRA SFT 能否提升模型对随机字符串的精确抄写，并用独立 tokenizer 审计排除词元化造成的假象。设置以 Qwen/Qwen3-8B 为基座，使用 bf16 LoRA 训练 2 个 epoch，训练脚本只对目标字符串或 `old_string` JSON 字段提供逐 token 监督。结果是留出集 byte-exact accuracy 从基座的 37.5% 提升到 78.9%，独立边界集为 80.1%，平均首次字节分歧位置分别为 54.0 和 54.2。另用留出与边界共 512 条探针比较三个开源 tokenizer，Qwen3 与 Qwen2.5 的无损 round-trip 均为 80.1%，因此这个 80.1% 同时反映了模型复制和 tokenizer 上限。

这组数字要连起来读才不会误读。留出集 37.5% → 78.9%，涨了 41.4 个百分点，边界集 80.1%，而 tokenizer 的无损 round-trip 上限也是 80.1%。SFT 之后的模型已经基本顶到了 tokenizer 的天花板，剩下约 20% 的失败来自词元化的无损性上限，不是模型能力不够。模型分数和 tokenizer 上限撞在同一个数上，正是这里强调「80.1% 同时反映了模型复制和 tokenizer 上限」的原因。另外「平均首次字节分歧位置 54.0 和 54.2」说明分歧发生在字符串中段而不是开头，和「长字符串越容易错」的直觉对得上。

三个案例放在一起看，共同的方法论是先确认差异到底出在哪一环，再把期望翻译成可判定的规则，最后才决定这笔数据喂给谁。案例 1 的期望是「别过早宣称完成」，可判定形式是隐藏验收测试通过或不通过，数据用法是偏好对加 DPO（或端到端 RL）；案例 2 的期望是「中文引号要统一」，可判定形式是作用域分类加最小编辑是否与目标文本一致，数据用法是带正反例的 SFT；案例 3 的期望是「准确抄写」，可判定形式是 byte-exact 匹配，数据用法是逐 token 监督的 SFT 加 tokenizer 审计。三个答案分别是 DPO、SFT、SFT，选哪个由「期望能不能写成可验证的奖励」决定：能写成奖励且需要探索的走 RL/DPO，只能给出示范的走 SFT。

这里还有几处容易混。失败归因记录给的是**负标签**，它标出「这一步错了」，不是「这一步对了」，不要指望从失败案例直接得到正例，正例需要教师生成或人工示范，案例 1 的做法就是让教师模型生成被选中的样本，再过一遍规则验证器。端到端回归任务和轨迹前缀回归任务也不是一回事：前者是整条任务做完、看最终状态对不对，可以当 RL 环境和 RFT 采样池；后者是同一个前缀、比较不同的后续分支，适合造偏好对、定位决策边界。「数据扩充」同样不等于「造新任务」，案例 1 的扩充是换任务类型、换缺失的验证项、换完成措辞，保持失败模式不变，只换表面形式，扩出来的样本覆盖的是同一个决策边界的多种表象。另外，byte-exact 和语义等价是两类评分标准：案例 3 要求逐字节相同，因为编辑工具就是按精确字符串匹配的，语义上「看起来一样」不算通过；案例 1、案例 2 判的则是语义和规则。

## 8.15 后训练实践要点

这一章从预训练的「预测下一个词」出发走了很长一段路。Mid-training 在目标分布上补知识与基础能力，SFT 高效学习格式与协议，结果导向的 RL 在本章的对照实验中改善了分布外泛化；多轮任务引入信用分配难题，奖励设计从结果奖励延伸到「奖励结果、约束过程」的路径信号，工具使用则带来组合爆炸。贯穿其中的线索只有一条：模型学到什么，取决于训练信号教了它什么；而信号的质量主要由数据和环境决定，不是由算法决定。

这里列出了 11 个常见陷阱，并且说识别这些问题往往比掌握技术细节更能避免资源浪费。

1. 用 SFT 硬塞知识库，或把所有知识都交给参数。大量稳定领域知识与基础能力可以用 Mid-training 写入参数，SFT 再教模型如何访问和表达；需要动态更新、引用、权限控制或删除的事实应由 RAG 管理。
2. 格式未稳定就引入 RL。模型不能稳定生成奖励计算所需的 JSON，训练信号就会变得稀疏或失真。可接受的解析失败率取决于任务与奖励设计，不应把固定阈值当作普遍标准；先用小规模评估设定格式稳定性门槛，必要时通过 SFT 或约束解码稳定输出后再应用 RL。
3. 把标称窗口当成有效窗口。位置编码允许 128K 输入，不代表模型在 128K 上仍会检索、推理和规划。扩窗前应完成当前长度的能力门禁，每个阶段保留短数据和前序阶段 replay，并用「能力 × 长度」矩阵检查退化。
4. pass@k 近零仍直接上 RL。全失败的 rollout 没有正向轨迹，GRPO 组内优势也会消失。先用 Mid-training 补能力、用 SFT/蒸馏扩大有效支持，或构造与最终目标一致且可达的课程和部分奖励。
5. 奖励函数设计不当导致奖励黑客。模型学会钻奖励的漏洞来获得高分，而非真正完成任务，比如只看回复长度就生成冗长无意义的文本。应该评估最终目标而非中间指标。
6. 忽视仿真保真度。若仿真过于简化（客服总按固定模式回复）或环境响应不真实（错误信息与生产环境不一致），训练出的策略在真实场景中会完全失效。高保真仿真环境的构建成本可能高于训练本身。
7. 过度训练导致泛化下降。训练损失持续下降但验证集性能反而恶化时，模型正在死记训练细节。Mid-training 会造成通用能力遗忘，SFT 会过拟合示范，RL 过度优化也会让策略过拟合当前奖励与任务分布，三者都需要独立保留集和早停。
8. 价值函数崩溃与探索不足。PPO 中价值估计不准确会导致优势计算出现偏差，表现为训练曲线剧烈震荡。温度参数过低或随机性不足会使 Agent 陷入局部最优。
9. 把训练—推理数值失配当成小噪声。更新前 sampler/trainer 的概率比已经偏离 1，会把 on-policy 训练悄悄变成 off-policy。应监控 log probability 差异、近似 KL、裁剪比例和策略 staleness。
10. 低估 RL 的计算成本。SFT 上表现良好的任务转 RL 可能需要 10–100 倍训练时间。如果测试分布与训练高度一致，SFT 可能已经足够。
11. 训练数据质量低下。Mid-training 会吸收语料中的错误关联，SFT 会直接学习示范噪声，RL 的奖励若有系统性偏差则会把策略朝错误方向放大。

这 11 条按「发生在哪个环节」重新分组，记起来省力得多。数据和底座层面是陷阱 1 与 11；阶段切换层面是陷阱 2、3、4；奖励与环境层面是 5、6；优化动力学层面是 7、8、9；资源规划层面只剩 10。分完组会发现，11 条里有 4 条（2、3、4、10）在讲同一件事：别在不该训练的时候训练，别用太贵的方式训练。这和 8.7 那张选型表是同一个主题，也说明全章最大的浪费来源往往出在阶段判断上，算法调不动反倒是次要的。

陷阱 3 是本章唯一一次集中讲「有效上下文」。位置编码允许 128K，不等于模型在 128K 上会检索、推理和规划，这就是标称能力与有效能力的差别。这里给的三条做法连起来是一条长度课程：先把短上下文的能力门槛守住，再逐级放长，每一级都要回头检查短程能力有没有退化。这种「扩窗就遗忘」的现象，和 8.4 讲过的「继续预训练不是免费的」是同一种代价。

陷阱 8 值得与 8.9.1.1 对照看。两者都会表现为训练曲线剧烈震荡，病因却完全不同：价值函数崩溃是优势估计不准，训练—推理数值失配是同一份权重算出两个 log prob。前者的诊断线索是「价值估计不准确导致优势计算出现偏差」，后者的诊断线索是「监控 log probability 差异、近似 KL、裁剪比例和 staleness」。排查顺序建议先查数值一致性，它便宜且能自动化，再查价值函数。

核心原则是在投入大规模资源前，先用小规模实验验证关键假设，快速失败比大规模失败更可接受。落实下来，就是每一种训练都先用最小规模验证「这一步有没有意义」：Mid-training 用小批语料看知识/能力增益与遗忘曲线，两条线要一起看，只看增益会忽略遗忘；SFT 用少量数据看格式能否稳定，因为格式是 RL 的前置条件；RL 用小批 rollout 看 pass@k、奖励差异和 sampler/trainer 数值一致性，这三个指标分别对应「有没有可学的」「信噪比够不够」「数据是不是 on-policy」。三个检查加起来的成本可能不到一次全量训练的百分之几，却能挡掉上面 11 条陷阱里的大部分。三者「不是互斥方案，而是作用于不同位置」，这是这里的原话。ICL 用示例、规则和当前状态实现零参数的即时适应，但随着上下文增长，延迟与费用也会上升；RAG 把事实与证据放在可动态更新、可追溯的外部知识中；后训练则把高维感知、生成风格和隐式决策策略写入参数。选择依据不只是任务是否长期稳定，更重要的是能力能否被外部符号充分表达。医疗影像识别、自然语气等能力即使面对持续变化的领域，仍往往需要参数更新；反过来，长期稳定的转账审批规则也应由代码提供确定性保障，而不能只靠模型记忆。稳健的系统通常组合使用这些方法：用 RAG 管理动态事实与证据，用 ICL 快速试验可用语言描述的策略，用程序固化确定性流程与硬约束，用 Mid-training 吸收稳定领域知识和基础能力，再用 SFT/RL 塑造难以由外部规则完整表达的行为。

蒸馏能把高能力大模型的行为迁移到成本更低的小模型中，这句放在实践要点里出现是有工程含义的。它提示蒸馏不只是训练技巧，也是部署成本优化的手段，用大模型的行为去训练小模型，可以把推理成本降下来。这与 8.13 讲的「样本效率」是两个不同的收益面：8.13 的蒸馏是为了少采样，这里提到的蒸馏是为了少花钱。

「选择依据不只是任务是否长期稳定，更重要的是能力能否被外部符号充分表达」这句值得单独记下来。它把「该不该训练参数」从一个关于时间的问题（知识会不会变）换成了一个关于表达的问题（这个能力能不能写成文字或代码）。这里的两个例子正好是两极：医疗影像识别、自然语气很难用符号充分表达，所以即使领域在持续变化，仍往往需要参数更新；长期稳定的转账审批规则完全可以用代码表达，所以应由代码提供确定性保障，而不能只靠模型记忆。能被写清楚的就别塞进参数，写下来更可查、可改、可审计；写不清楚的才必须进参数。

## 8.16 本章小结

三种训练的分工需要先说清。Mid-training、SFT 和 RL 是分别处理底座、协议与策略的三件事，把它们当成三种可互换的「微调力度」是常见的误读。Mid-training 还应通过长度课程、混合数据和逐级门禁，把标称上下文扩展变成不遗忘短程能力的有效上下文。

阶段判断可以压成三句话，也就是这里整理的那张「三问三答」表（三行判断的依据均出自这里）：

| 症状（可测量） | 缺什么 | 该做什么方法 |
| --- | --- | --- |
| 合理采样下 pass@k 仍接近零 | 底座（知识与能力不在有效支持中） | Mid-training（动态事实则用 RAG） |
| 偶尔会做，但输出不可解析 | 协议（行为协议没固化） | SFT（或约束解码）稳定格式 |
| 有可评分、且有奖励差异的轨迹，但好策略概率低 | 策略（概率质量分配） | RL（探索示范外路径） |

这张表与 8.7 的表 8-4 是同一套逻辑的浓缩版：先看会不会（pass@k），再看说不说得清（解析率），最后才看走不走得远（策略）。如果合理采样下 pass@k 仍接近零，先用 Mid-training 补知识与能力；如果模型偶尔会做却输出不可解析，先用 SFT 稳定格式；只有当前策略能产生可评分且有奖励差异的轨迹时，RL 才能高效地重新分配概率并探索策略。

这些结论都带着限定。「SFT 记忆、RL 泛化」概括的是本章受控实验中观察到的倾向，并不是不受数据、模型、奖励与环境影响的普遍规律。

第一条贯穿全章的判断是数据和环境比算法更重要。Mid-training 语料决定底座补到了哪里，SFT 示范决定协议是否稳定，环境和奖励决定 RL 能探索并强化什么。造不出真实环境时，用模型模拟环境（合成工具返回值、仿真环境动态）也是一条可行路线，但模拟器的偏差就是训练的天花板。很多场景下，只要底座和示范数据到位，甚至不需要做 RL。这句话在章里有四处实证：实验 8-11 的 GeneralPoints 用同一个基模、同一预算，只有训练方法不同，结果 OOD 表现分道扬镳，说明信号决定学到什么；8.10 反复强调环境保真度决定策略能否上线；8.13 的「时间感」任务里，换监督信号（教师逐 token 分布）比换优化目标（四种 RL）更有效；8.14 的三个案例全部是先把期望写成可判定的规则，而不是先选算法。把这句话当作选型时的默认假设，能省下大量无效试错。

「甚至不需要做 RL」是一句很务实的结论。它的意思不是 RL 没用。底座和示范数据到位、任务分布又与测试分布高度一致时，SFT 可能已经足够（陷阱 10 也是这么说的）。RL 的价值在探索示范之外的策略、把低概率成功策略推高这两件事上，当任务不需要它们时，RL 就是在为一个你不需要的东西付几十倍的算力。

第二条贯穿全章的判断是当前 RL 的主要瓶颈在样本效率与分布一致性。On-Policy Distillation 把一条 rollout 的终点标量扩展为学生实际状态上的逐 token 监督，处理的是「同一条轨迹上的信号太稀」，相当于纵向加密；RLVP 把被浪费的环境反馈变成可学习信号，处理的是「组内的差异消失」，相当于横向恢复差异。真正 on-policy 的 rollout 又减少了重要性修正的偏差与方差。训练—推理数值失配会破坏这个前提，因此 sampler/trainer 一致性应与奖励曲线同等重要。两个方法的定位正好互补，本章给出的 RL 改进路线图也就是三条：更密的监督、更可区分的组内信号、更小的分布偏差。数值失配恰好同时破坏第三条和它的前提，所以这里要求把它提到「与奖励曲线同等重要」的监控级别。

本章回答的是怎样通过更新模型参数来实现 Agent 持续进化的问题。下一章会看到，参数只是知识、指令、程序与参数四种 Agent 自我进化的载体之一。

## 思考题

这里在这一页上方标了「深度思考」的栏目名，下面这 13 题就是该栏目的「思考题」，题干照录，星级也按这里保留。每题后面那段思路是这里自己整理的，不是标准答案，跟这里有出入的地方以这里为准。

**1. ★★** 灾难性遗忘——一次针对特定任务的微调破坏了模型原有的通用能力（如通用工具调用）——在 Agent 场景下尤其棘手。相比全参微调，LoRA 冻结基座权重、遗忘风险更低，但并非免疫。有哪些策略可以进一步缓解微调带来的能力遗忘？

本章出现过的手段基本够用。案例 1 要求「按小配比混入通用任务数据」；8.15 的陷阱 7 把「三者都需要独立保留集和早停」写成通例；8.13.2 里有 `retention_regularizer` 这类正则约束；训练数据的多样性也算一条。再往上一层想，遗忘是「参数被新目标占据」的结果，那么减少参数改动量（更小的 LoRA rank、更少 epoch）和减少目标冲突（把通用能力纳入验证集）都是方向。改动量有多大可以拿本章的实验当参照：几个案例用的都是 7B/8B 基座、bf16、2 个 epoch 的 LoRA，本身就不算激进。还有一条别忘了，不值得训练就别训练，很多能力交给 RAG/ICL 承载，根本碰不到遗忘问题。

**2. ★★** 后训练将能力固化为模型权重（「肌肉记忆」），而上下文学习将知识放在推理时的输入中。但有些能力（如领域知识）既可以通过后训练学习，也可以通过 few-shot 示例提供。你会用什么标准来决定某项能力应该走哪条路径？

本章给出的核心判据是「能力能否被外部符号充分表达」（8.15 末），再加上一条「是否需要频繁更新、引用、权限控制或删除」，后一类事实优先 RAG（8.7 第一步）。还能补两条工程维度。成本与延迟：ICL 会随上下文增长推高延迟与费用（8.15 提到过这一点），而写进参数的知识不占上下文。规模与稳定性：少量事实可以随示范学入参数，大量事实不应让少数 QA 对承担（8.7 第三步）。另外，走参数这条路本身也有两种性格：SFT 倾向于覆盖示范中的多个模式（mass-covering），RL 配合反向 KL 时倾向于把概率集中到少数高奖励峰（mode-seeking），同一份数据用哪种训练，模型学到的分布形状并不一样。

**3. ★★** 模型蒸馏让小模型学习大模型的行为。按能力层次，被蒸馏的模型大致可分为三级——Chat 模型（单轮对话、直接作答）、Reasoning 模型（带长链思考再作答）、Agentic 模型（多轮调用工具、与环境交互）。分别蒸馏这三类模型，难点有什么不同？（提示：从「要蒸馏的到底是什么」入手——是输出的风格、完整的思考轨迹，还是与环境交互的决策策略；轨迹里哪些 token 该学、哪些是环境返回的不该学；以及成败信号出现得有多晚、有多稀疏。）

题干里的提示已经把三个维度点出来了，顺着答就行。要蒸馏的对象依次是风格与格式、完整的思考轨迹、与环境交互的决策策略。Chat 这一级的对错容易判定，信号密但信息量低；Reasoning 要教师提供中间步骤，长链上误差会累积，正中 8.13.1 说的「离轨 SFT 覆盖不到学生状态」；Agentic 的状态由环境决定，成败信号出现得最晚、最稀疏。哪些 token 该学，8.11.2 给了明确答案：环境返回的 token 必须屏蔽，只对模型自己的思考与工具参数回传梯度。Reasoning 这一级还有一个争论点，该不该连教师的冗长思考习惯一起学，按实验 8-9 的代价看未必划算。信号密度三级递减，所以越靠后越依赖 8.13.1 的「学生走路径、教师给监督」。这条路线的收益在量级上很可观：达到同等性能所需的训练步数约为纯 RL 的 1/10，「时间感」任务里四种条件的通过率比同源 SFT 基线高 23 到 47 个百分点。教师分布的一个示例也值得记住，查询占 80%、调用占 15%、其余 5%。

**4. ★★★** 在多轮 Agent 交互中，奖励的归因（credit assignment）问题比单轮更严重——一个最终的成功或失败很难归因到第 3 轮还是第 7 轮的决策。你会如何设计奖励分配策略？

本章给了三种可以组合的工具：过程奖励（PRM，密集，但会限制探索）、折扣与优势分配（$\gamma=1$ 时靠 PPO 的价值网络或 GRPO 的轨迹级摊分）、路径信号（RLVP 的 $R=O+\beta\Phi$，用确定性规则给违规扣分、给可达子目标加分）。组内比较长什么样，GRPO 那个例子可以当模板：16 条 rollout 里 4 条通过，组内平均成功率 $4/16$，于是 4 条拿到正优势、12 条拿到负优势。设计时要回答几个具体问题：中间步骤有没有公认标准？部分进展是否可达？惩罚是否总能被检测到？以及最要紧的一条，你的信号能不能在同组 rollout 中产生差异（8.12.4 的判据）。还要留一个「全胜组」的检查，如果所有 rollout 都成功，你手里还有没有信号？RLVP 的效果可以当参照，TerminalBench 上违规次数从 3.71 降到 0.66 而成功率基本持平，miniF2F 达到 0.9 成功率所需的迭代从 7.0 降到 4.4。

**5. ★★★** 如果你有固定预算（比如 \$10,000），要提升一个客服 Agent 的性能，你会如何在上下文与知识、Prompt/Skills、程序约束和参数训练之间分配预算？你的决策取决于哪些因素？

引言里有一条「先排除不需要改权重的方案」（8.7 第一步），先把 Prompt、工具、代码约束、上下文管理的性价比试出来，再考虑训练。分配预算时要看的因素按本章的顺序排：任务分布是否稳定（稳定就可以写进参数或程序）、能力能否被外部符号表达（能就交给 RAG 或程序，不能才进参数）、pass@k 是否为 0（为 0 先做 Mid-training，别直接上 RL）、格式是否稳定（不稳先做 SFT 或约束解码）、有没有可交互环境（没有就照表 8-4 第三行，先建评估，再判断值不值得造环境）。成本量级解释了这套顺序为什么必须遵守：SFT 的代价是几小时到几天，RL 常常是它的几十到上百倍；ReTool 里 SFT 冷启动约 1 小时，RL 跑了约 9 天，差出两百倍以上。客服场景还有一个特有之处，用户模拟器既能当考场也能当练习场（8.10.2），所以「造环境」这一项可能比想象中便宜，代价是模拟器的偏差会变成训练的上限。

**6. ★★★** 让模型在没有明确奖励函数、样本稀少的情况下自主学习，被一些人认为是后训练的终极目标。当前的 RL 训练方法距离这个目标还有多远？你认为下一个突破最可能来自哪个方向？

本章点出的卡点有三个。样本效率，8.13 开篇说反馈太稀疏、在轨数据难复用。分布一致性，8.9.1 和 8.9.1.1 讲的是陈旧与数值失配，量级上给个数：4,000 个 token 的 log ratio 同方向偏 $10^{-3}$，轨迹级比率就会被放大到 $e^{4}\approx54.6$。奖励的可验证性，8.12.1 说只能用代理指标时 hacking 与 seeking 就会冒出来。方向大致也是三条：更密的监督信号（在轨蒸馏、OPSD 这类用特权信息替代奖励的思路）、更好的环境（8.10 的模拟环境与校准）、弱监督激发强能力（下一题提到的 Weak-to-Strong）。本章的实验数据可以让人对「样本稀少」这件事的量级有点感觉。SimpleVLA-RL 在 LIBERO 上只用成功/失败的结果奖励、一条演示轨迹做冷启动，成功率从 17.3% 提到 91.7%，还发现了示范里没有的「推切」动作。ReTool 的 AIME 2024 从 SFT 基线 25% 走到 110 步的 52%、400 步的 67%。GeneralPoints 更直白，同一个基模、同一预算，只有训练方法不同，规则 OOD 上 RL 涨 3.5 个百分点（11.5→15.0）而 SFT 掉 8.1 个百分点，视觉 OOD 上 RL 涨 17.6 个百分点（23.6→41.2）而 SFT 掉 9.9 个百分点。答题时最好把判断依据摆出来，别只给方向。

**7. ★★** 本章指出 LoRA 微调的成本并不高。那么，是否有可能给每个用户（或每个客户公司）训练一个专属的 LoRA，将用户记忆或企业知识写入参数，而非像第三章那样存储在外部知识库中？在什么场景下，「记忆写入参数」比「记忆存入知识库」更有优势？又在什么场景下会适得其反？

优势侧能想到三点。延迟与上下文成本，参数里的知识不占上下文，也没有检索延迟。风格与偏好类记忆，这类东西很难用文字穷举，却可以用示范学。数据隐私，知识不出本地。本章的实验规模说明这件事在算力上确实可行，实验 8-18 用 Qwen/Qwen3-8B、bf16、2 个 epoch 就跑完了。反侧要回到本章反复强调的性质：参数里的知识难更新、难删除、难引用、难做权限控制（8.7 第一步与 8.15 陷阱 1 都点了这几条），此外还有遗忘风险（见第 1 题）与规模化成本，每个用户一份 LoRA 的存储和推理切换都要花钱。判据仍然是那句：这个记忆需不需要被频繁更新、引用、删除或分权限。

**8. ★★★** On-Policy Distillation 依赖更强的教师模型来监督学生。但 OpenAI 的 Weak-to-Strong Generalization 研究提出了一个反直觉的发现：弱模型的监督信号有时能激发强模型本身潜在但未被激活的能力。如果将这一思路应用到 Agent 训练，是否可能实现「小模型教大模型」的逆向蒸馏？

先分清两件事。OPSD 的成立条件是「教师看到特权信息」，而不是「教师更强」，8.13.2 里是同一个模型分饰两角，教师侧多了标准答案。所以「小模型教大模型」有一种可能：弱模型提供的是定位与筛选信号，指出哪些状态值得学，强模型自身潜在的能力被这部分信号激活。风险也要说清。弱监督的系统性偏差会被放大，这与 8.10.2 说的「模拟器的偏差就是训练的天花板」是同一个逻辑；另外本章反复强调，学生至少要能进入教师可纠正的有效状态（8.13.1），如果弱教师根本判断不了强学生的输出好坏，监督就是无效的。

**9. ★★** 过程奖励模型（PRM）评估每个思考步骤，而结果奖励模型（ORM）只看最终结果。但「正确的过程导致错误结果」和「错误的过程侥幸得到正确结果」哪个更值得奖励？在 Agent 的多步工具调用场景中，你会如何权衡？

这一题正好落在 8.12.4 的非对称验证器上。「错误的过程侥幸成功」通常更容易被检测，违规动作可以机器判定，RLVP 的惩罚项几乎总能生效；「正确的过程却失败」很难被证明，这里的说法是，证明「这一步确实朝着目标取得了有意义的进展」很难。所以实践上常见的是这个组合：惩罚违规（可靠）、保留结果奖励（防摆烂）、只在部分进展可达时才加进展奖励。奖励模型这一侧还有一条老路可以对照，RLHF 走的是「人工比较回答 → 训练奖励模型 → 用 PPO 优化策略」，本章只把它当背景；生成式奖励模型（GRM）会多给一层诊断，不只输出分数，还生成「哪里做得好、哪里需要改」，DeepSeek-GRM 的做法是先归纳评价原则再评价，最后用可验证事实自检。答题时把「可达性」这个词用上，因为只有确实区分了组内行为的那些正确过程才值得奖励。

**10. ★★★** 本章讨论的评估数据集（如 SWE-Bench Verified、τ²-bench、AndroidWorld）既可以用于评估也可以用于后训练。但如果将评估集用于训练，它就不再是独立的评估集——这是否违反了训练集与测试集必须分离的基本原则？τ²-bench 的动态参数生成和 AndroidWorld 的参数化模板在一定程度上缓解了这个问题，但模板结构本身仍然是固定的。如何在充分利用评估数据的训练价值与维护评估独立性之间找到平衡？

8.10.3 给的工程答案可以当起点：「训练环境和评估环境可以共享任务生成器与验证代码，却不能共享同一批任务」，而且「测试用例、隐藏状态和参考解法应留在验证器一侧」。再补几条：把评估集拆成训练可用的那一份与永不参与训练的冻结保留集；用动态生成参数的任务（τ²-bench 的思路）让「同一批任务」难以被记忆；把「结构固定」当作已知的残余风险，用人工抽检和新颖任务族补上。任务本身怎么造也值得提一句，本章的「任务蓝图」是从真实业务日志里提炼任务，去掉身份信息后重新生成虚构的人物、订单、文件与状态，真实分布留住了，真实数据却没有被直接搬进训练。答题时要正面回答是否违反原则：被违反的是「同一批数据」的独立性，复用「同一套生成器」这件事本身不构成违规。

**11. ★★★** 面对一个目标任务，基模的 pass@1 很低。你会怎样联合 pass@k、格式解析率、部分进展率和失败归因，判断应该先做 Mid-training、SFT，还是可以直接进入 RL？这些指标达到什么条件时才值得切换阶段？

直接把 8.7 的四步决策流程和表 8-4 的门槛列搬过来答。pass@k 近零、失败集中在知识与基础能力上，先做 Mid-training；pass@k 有非零值但解析率不稳，先做 SFT 或约束解码；已经能打出可评分、偶尔成功、组内有奖励差异的轨迹，才轮到 RL。这里的「用少量示范把模型拉进可用状态」在本章有两种含义，一种指训练初期某类样本太稀缺、学不起来（AdaptThink 碰到的），另一种指 DeepSeek-R1 那种冷启动 SFT，这里说的是后者。切换条件用表 8-4 的第四列：Mid-training 之后要看到领域留出集改善、通用保留集可接受、出现可验证的正确或部分正确轨迹；SFT 之后要看到解析成功率稳定、关键动作能被验证器可靠评分；进 RL 之前要确认奖励与真实目标一致、组内有足够奖励差异、独立测试集随训练改善。部分进展率的用处是判断课程是否可达，失败归因的用处是判断缺的是知识还是协议，落到动作上就是补底座还是固格式。

**12. ★★★** ReTool 的训练动态显示（见实验 8-14），少数超长响应会显著拖长整个训练周期——一批 rollout 里绝大多数已经生成完毕，却要等那几条最长的响应收尾，其间集群的 GPU 利用率很低。如何提升这种长尾响应场景下训练集群的资源利用率？

8.9 的估算已经把这个现象量化过：一个 rollout 阶段的墙钟时间由最慢的那条决定（2,000 s + 600 s ≈ 2,600 s，约 43 分钟），连续 100 个 step 就接近 72 小时。可以动的方向有几个。对超长响应设上限或截断，并让奖励设计配合，别把「写得长」变成加分项。连续批处理或异步 rollout，一条完成就立刻进入下一步，不等整批。把长度接近的样本分到一批，减少长尾拖累；长尾也可以单独调度或降低并行优先级。让验证与采样流水线重叠，8.10.3 提到吞吐量取决于并行的验证器 worker，ReTool 用的是 SandboxFusion 的 128 个并行 worker。补一点数量级：ReTool 每步是 32 题 × 16 候选 = 512 条，平均要 7 到 9 轮交互。任何截断都要回头看它有没有改变奖励的含义，比如「长思考才做对」的任务被截断后会被误判。

**13. ★★★** 用 LLM 模拟环境（如模拟搜索引擎、模拟用户）训练 Agent 时，Agent 钻空子的对象从「真实环境的规则」变成了「模拟器本身的偏见与漏洞」。这类训练中可能出现哪些具体的 reward hacking 行为？又该如何防范？

行为侧顺着模拟器的系统性偏差想就能列出来：发现模拟用户特别有耐心就无限追问，发现模拟搜索从不返回垃圾就只依赖检索，发现模拟器对某种格式有偏好就一味迎合，甚至复现模拟器的错误结论以求通过。8.10.2 明确说过，RL 会主动寻找并利用模拟器的漏洞。防范侧对应本章给出的办法：混合真实环境交互并定期校准（8.10.2）、验证器一侧保留隐藏测试与真实状态断言（8.12.2）、用路径约束惩罚违规动作（8.12.4），再用独立保留集检查「任务确实完成时模型是否还能正常收尾」，案例 1 的边界集 12 条加保留集 8 条就是这个形状。还能加一条监控：定期用真实环境重测同一批策略，把模拟器分数与真实分数的差距当成指标。沙盒训练的规模可以当参照，AWorld-train 那套 MCP 沙盒里有 26 个服务器、126 个工具函数，多轮对话不超过 32 轮、131K 上下文，用 Qwen3-4B 加 8 张 A100，GRPO、lr=1e-6，GAIA 上给出的参考水平是「大模型约 32%」。
