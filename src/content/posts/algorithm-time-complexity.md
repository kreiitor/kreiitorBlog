## 速查：增长阶与可接受规模

| 记法 | 名称 | 典型来源 | 1 秒内可接受的 $n$ |
| --- | --- | --- | --- |
| $O(1)$ | 常数时间 | 数组下标访问、四则运算 | 任意 |
| $O(\log n)$ | 对数时间 | 二分查找、快速幂、最大公约数 | $\le 10^{18}$ |
| $O(\sqrt n)$ | 根号时间 | 试除法判素数、数论分块 | $\approx 10^{12}$ |
| $O(n)$ | 线性时间 | 一次遍历、前缀和、双指针 | $\le 10^7$ |
| $O(n\log n)$ | 线性对数时间 | 排序、线段树、树状数组 | $\le 10^6$ |
| $O(n^2)$ | 平方时间 | 双重循环、朴素 DP | $\le 5\times10^3$ |
| $O(n^3)$ | 立方时间 | Floyd、区间 DP、矩阵乘法 | $\le 5\times10^2$ |
| $O(n^4)$ | 四次时间 | 四维 DP、高维前缀和 | $\le 50$ |
| $O(2^n)$ | 指数时间 | 子集枚举、状压 DP | $\le 20\sim25$ |
| $O(n!)$ | 阶乘时间 | 全排列、TSP 暴力 | $\le 10\sim11$ |

表中的数值按 C++、1 秒时限、单组数据估算，推导与用法见第五章。

## 一、前言

很多人觉得算法难，是因为被困在了「时间」和「空间」这两个维度上。如果不考虑时间和空间的因素，其实我们可以把所有问题都通过穷举解决——你告诉计算机要做什么，然后靠它强大的算力帮你算出来。本文聊的就是其中「时间」这一维：时间复杂度。

---

## 二、穷举

所谓穷举，也就是我们通常所说的枚举，就是把所有情况都遍历一遍。

### 1、小试牛刀

> 【例 1】给定 $n$ 个元素 $a_1,a_2,\dots,a_n$，求其中是偶数的数的个数。

判断一个数是偶数还是奇数，只需看它除以 2 的余数是 0 还是 1。把所有数判断一遍，对符合条件的情况计数，最后返回计数器——这就是穷举。

```cpp
int countEven(int n, int a[]) {
    int cnt = 0;
    for (int i = 0; i < n; ++i) {
        if (a[i] % 2 == 0)
            ++cnt;
    }
    return cnt;
}
```

需要遍历全部 $n$ 个元素，执行次数与 $n$ 成正比。

### 2、乘胜追击

> 【例 2】给定 $n$ 个元素，求有多少个二元组 $(i,j)$（$i<j$），满足 $a_i+a_j$ 是偶数。

秉承穷举的思想，这里需要两个变量 $i$ 和 $j$，所以枚举 $i$ 和 $j$，再对 $a_i+a_j$ 做奇偶性判断：

```cpp
int countEvenPair(int n, int a[]) {
    int cnt = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if ((a[i] + a[j]) % 2 == 0)
                ++cnt;
        }
    }
    return cnt;
}
```

$i<j$ 限制了枚举量：一共只需检查 $\binom{n}{2}=\dfrac{n(n-1)}{2}$ 对。

### 3、举一反三

> 【例 3】给定 $n$ 个元素，求有多少个三元组 $(i,j,k)$（$i<j<k$），满足 $a_i+a_j+a_k$ 是偶数。

```cpp
int countEvenTriple(int n, int a[]) {
    int cnt = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            for (int k = j + 1; k < n; ++k) {
                if ((a[i] + a[j] + a[k]) % 2 == 0)
                    ++cnt;
            }
        }
    }
    return cnt;
}
```

要求多少个元组，就枚举多少层循环。方案数为 $\binom{n}{3}$。

### 4、返璞归真

> 【例 4】给定 $n$ 个元素 $a$ 和一个整数 $k$，求有多少个下标严格递增的 $k$ 元组 $(i_1<i_2<\dots<i_k)$，满足它们的和是偶数。

一层循环、两层循环、三层循环……那 $k$ 层循环呢？

问题在于 $k$ 不是常数：它由输入决定，最大可达 1000。意味着要写 1000 层循环，显然无法接受。比较暴力的做法是改用递归：

```cpp
int dfs(int n, int a[], int start, int k, int sum) {
    if (k == 0)
        return sum % 2 ? 0 : 1;               // (1)
    int s = 0;
    for (int i = start; i < n; ++i)
        s += dfs(n, a, i + 1, k - 1, sum + a[i]); // (2)
    return s;
}
```

1. `dfs(n, a, start, k, sum)` 的含义是：给定 $n$ 个元素的数组 $a$，从下标 `start` 开始选 $k$ 个元素、当前和为 `sum` 时的方案数；`k == 0` 是递归出口（和是偶数返回 1，否则返回 0）。
2. 当前第 `i` 个元素选入之后，剩下就是从 `i+1` 开始选 $k-1$ 个，递归求解。

简单分析一下：$n$ 个元素选 $k$ 个，根据排列组合，方案数为
$$
\binom{n}{k}=\frac{n!}{k!\,(n-k)!}.
$$
当 $n=1000$、$k=500$ 时这已经是天文数字，这段代码完全跑不出结果。

当然，对初学者来说这段代码不理解问题也不大——它只是为了说明穷举这个思想。

## 三、时间复杂度

### 1、时间函数

时间复杂度往往联系到一个函数：自变量表示规模，因变量表示执行时间。

这里所说的执行时间，是广义的时间，单位并不是「秒」「毫秒」，它代表的是一个**执行次数**的概念。我们用 $f(n)$ 来表示这个时间函数。

### 2、经典函数举例

【例 1】中是单层循环，$n$ 是变量，随着 $n$ 增大执行次数增大、执行时间增加，所以有

$$
f(n)=n.
$$

这就是最经典的**线性**时间函数。

【例 2】中是双层循环：

$$
f(n)=\frac{n(n-1)}{2}.
$$

这是一个**平方级**的时间函数。

【例 3】中是三层循环：

$$
f(n)=\frac{n(n-1)(n-2)}{6}.
$$

这是一个**立方级**的时间函数。

### 3、时间复杂度

一个算法中的语句执行次数称为语句频度或时间频度，记为 $T(n)$。更优雅的表示法是

$$
T(n)=O(f(n)),
$$

其中 $O$ 念作「大 O」。

1. 当 $f(n)=n$，称这个算法拥有**线性时间复杂度**，记作 $T(n)=O(n)$；
2. 当 $f(n)$ 是平方级，称它拥有**平方级时间复杂度**，记作 $T(n)=O(n^2)$；
3. 当 $f(n)$ 是立方级，称它拥有**立方级时间复杂度**，记作 $T(n)=O(n^3)$。

严格一点的定义：若存在正常数 $c$ 和 $n_0$，使得当 $n\ge n_0$ 时都有 $f(n)\le c\cdot g(n)$，则记 $f(n)=O(g(n))$。

这时会发现，$f(n)$ 可能很复杂，而 $O$ 表示的函数往往比较简单——它舍弃了一些「细节」。为什么可以舍弃？这就要说到数学上「高阶无穷小」的概念。

### 4、小巫见大巫

定义：如果
$$
\lim_{n\to\infty}\frac{\beta}{\alpha}=0,
$$
则称「$\beta$ 是比 $\alpha$ 较高阶的无穷小」。

以例 2 的时间函数为例：

$$
f(n)=\frac{n(n-1)}{2}=\frac{n^2}{2}-\frac{n}{2}.
$$

它由两部分组成：一部分是 $\dfrac{n^2}{2}$，另一部分是 $\dfrac{n}{2}$。直观感受一下，哪个更大？显然是 $\dfrac{n^2}{2}$。相对于 $n^2$，$n$ 就是「小巫见大巫」。

随着 $n$ 的增长，线性部分的增长已经跟不上平方部分。线性部分的时间消耗相对于平方部分来说已经「微不足道」，所以索性不提它，于是

$$
T(n)=O(n^2).
$$

### 5、简化系数

在上面的推导中，还顺手把 $n^2$ 前面的系数 $\dfrac{1}{2}$ 去掉了，道理是一样的：时间复杂度描述的更多是一个**数量级**，所以要尽量减少干扰项。

对于两个不同的问题，可能执行时间不同，但可以说它们的时间复杂度是一样的。

## 四、常见的时间复杂度

### 1、常数时间

```cpp
const int MAXN = 1024;
int getMAXN() {
    return MAXN;
}
```

一共就一句话，没有循环，是常数时间，记作 $O(1)$。

### 2、对数时间

> 【例 5】给定 $n$ 个元素的有序数组 $a$ 和整数 $v$，求 $v$ 在数组中的下标，不存在输出 $-1$。

这是一个常见的查询问题。可以用 $O(n)$ 的算法遍历整个数组去找 $v$。

当然也有更快的办法：注意题目条件「数组有序」，所以可以利用二分查找。

```cpp
int binaryFind(int n, int a[], int v) {
    int l = 0, r = n - 1;
    while (l <= r) {
        int mid = (l + r) >> 1;
        if (a[mid] == v) return mid;
        if (a[mid] < v) {
            l = mid + 1;
        } else {
            r = mid - 1;
        }
    }
    return -1;
}
```

每次相当于把区间切半，区间长度依次是

$$
n,\ \frac{n}{2},\ \frac{n}{4},\ \dots,\ \frac{n}{2^k}.
$$

这条路径的长度就是执行次数，也就是要求满足 $\dfrac{n}{2^k}=1$ 的 $k$。由 $n=2^k$，两边取以 2 为底的对数，得

$$
k=\log_2 n.
$$

所以 $T(n)=O(\log n)$。（底数不影响数量级，通常就写作 $\log n$。）

### 3、根号时间

> 【例 6】给定一个数 $n$，问 $n$ 是否是一个素数（素数：除了 1 和它本身，没有其它因子）。

基于素数的概念，可以枚举所有 $2\le i<n$，看能否整除 $n$：一旦能整除，代表找到了一个因子，则不是素数；当所有数枚举完还没找到，它就是素数。

但这样做效率太低。进行一些思考后可以得到下面的算法：

```cpp
bool isPrime(int n) {
    if (n <= 1) return false;
    int sqrtn = sqrt(n + 0.0);
    for (int i = 2; i <= sqrtn; ++i) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}
```

时间复杂度为 $O(\sqrt n)$。

为什么只需要枚举到 $\sqrt n$ 内的数？因为一旦有一个因子 $d$，必然有另一个因子 $n/d$，二者必有一个不超过 $\sqrt n$：若 $d>\sqrt n$ 且 $n/d>\sqrt n$，则 $d\cdot\dfrac{n}{d}=n>n$，矛盾。所以只要 $\sqrt n$ 以内找不到因子，$n$ 就是素数。

### 4、线性时间

这个不用多说，【例 1】的实现就是线性时间，即 $O(n)$。

### 5、线性对数时间

> 【例 7】给定 $n$ 个元素，求满足 $a_i+a_j=v$ 的二元组 $(i,j)$ 有多少对（$n$ 的范围较大）。

先思考最朴素的算法：两层枚举，参考【例 2】，时间复杂度 $O(n^2)$。

但这个问题 $n$ 的范围较大。如果理解了【例 5】，这个问题也不难：先对所有元素递增排序（$O(n\log n)$），然后枚举 $i$，并在 $i$ 之后的部分二分查找 $v-a_i$ 是否存在——存在则计数器加 1。$n$ 次二分是 $O(n\log n)$，所以总时间复杂度为

$$
O(n\log n)+O(n\log n)=O(n\log n).
$$

> 若题意把 $(i,j)$ 与 $(j,i)$ 视为不同，排序后只统计一遍的答案再乘 2 即可，复杂度不变。

### 6、多项式时间

多项式的含义是函数 $f(n)$ 可以表示成

$$
f(n)=a_0+a_1n+a_2n^2+\dots+a_kn^k.
$$

所以 $O(1)$、$O(n)$、$O(n^2)$、$O(n^3)$、$O(n^k)$ 都是多项式时间。

### 7、指数时间

> 【例 8】给出 $n$ 个点，以及每两个点之间的关系（连通还是不连通），求一个最大的集合，使得在这个集合中任意两点都连通（即最大团）。

这是求子集的问题。由于最多只有 $n$ 个点，可以枚举每个点选或者不选，总共 $2^n$ 种情况，然后再判断是否满足连通性。这个算法的时间复杂度为 $O(2^n)$。

（严格说，每种情况判定连通还要 $O(n^2)$，量级仍是 $2^n$ 级。）

当然有更加优秀的算法，但不是本文讨论的重点，就交给有兴趣的读者自行探索了。

### 8、阶乘时间

> 【例 9】给定 $n$ 个点，并且给出任意两点间的距离，求从 1 号点开始经过所有点回到 1 号点的距离的最小值（旅行商问题）。

这是典型的暴力枚举：把这些点当成一个排列，排列方案数为 $n!$，暴力枚举的时间复杂度为 $O(n!)$。

（每种排列求和还要 $O(n)$，量级同为 $n!$ 级。）

一般这类问题，暴力搜索没有实际意义，可以通过状压 DP 来进行优化。

## 五、如何判断时间复杂度

拿到一道算法题，如何快速判断应该用什么复杂度的算法？本节给出一个实用的三步判断框架。

### 1、标准

算法能否在规定时间内跑完，取决于**总操作次数**。

以 C++ 为例，现代计算机每秒大约可执行 $10^8$ 次简单运算。

竞赛题目通常包含多组测试数据，设样例（数据组）数为 $T$，则单组数据的可接受操作次数约为 $10^8/T$。

一般题目样例数 $T\le 10$，因此单组数据取保守阈值 $10^7$；若 $T=100$，则需降到 $10^6$。

判断依据：将算法的时间函数 $f(n)$ 代入，若 $f(n)\lesssim 10^8/T$，则基本可在时限内通过。

### 2、问题规模

问题规模即输入数据的大小，通常用 $n$ 表示。

不同问题中 $n$ 的含义不同：数组长度、图的点数、字符串长度等。

部分问题存在多个规模参数（如图论中 $n$ 个点 $m$ 条边），需综合代入时间函数评估。

### 3、套公式

将常见时间复杂度代入 $10^8$（单组数据按 $10^7$ 保守估算），反推出各复杂度对应的最大可接受规模：

| 时间复杂度 | 最大可接受 $n$ | 典型算法 |
| --- | ---: | --- |
| $O(n!)$ | $10\sim11$ | 全排列生成、TSP 暴力、康托展开、逆康托展开、错排枚举 |
| $O(2^n)$ | $20\sim25$ | 状压 DP、子集枚举、容斥原理、折半搜索、枚举子集 |
| $O(n^4)$ | $50$ | 四维 DP、高维前缀和、最大团、四维枚举、子矩阵求和 |
| $O(n^3)$ | $300\sim500$ | Floyd、区间 DP、矩阵乘法、二分匹配、传递闭包 |
| $O(n^2)$ | $3000\sim5000$ | 朴素 DP、双重循环、冒泡排序、选择排序、插入排序 |
| $O(n\log n)$ | $10^6$ | 快速排序、二分、线段树、树状数组、归并排序 |
| $O(n)$ | $10^7$ | 遍历、差分、前缀和、双指针、单调队列、单调栈 |
| $O(\sqrt n)$ | $10^{12}$ | 数论分块、根号分解、试除法、整除分块、因子枚举 |
| $O(\log n)$ | $10^{18}$ | 数位 DP、二分、快速幂、倍增法、最大公约数 |

使用方法：看到题目中 $n$ 的范围，先对照上表锁定可接受的复杂度区间，再选择对应复杂度的算法。

以上为经验值，实际需结合题目时间限制、操作常数、语言效率等因素综合判断。

## 结语

穷举是「理论上能解一切」的兜底，时间复杂度则是判断它到底能不能跑完的尺子。判断只有三步：看规模、算时间函数、对照可接受阈值。

几条可以直接记住的对应关系：

- 一层到四层循环，对应 $O(n)$、$O(n^2)$、$O(n^3)$、$O(n^4)$；
- 二分、快速幂、$\gcd$ 是 $O(\log n)$；排序、线段树、树状数组是 $O(n\log n)$；
- 枚举子集是 $O(2^n)$，枚举排列是 $O(n!)$——所以看到 $n\le 20$ 想状压，$n\le 11$ 想全排列。
