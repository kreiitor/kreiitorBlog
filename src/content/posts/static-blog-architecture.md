如果博客目标只是发几篇随笔，任何静态站工具都够用。但如果目标是持续沉淀论文、项目、实验和博客，站点结构就需要更明确地服务内容增长：内容要容易加，页面要容易改，部署要足够简单，几年后回来还能维护。

## 技术栈

当前站点使用：

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 框架 | Astro | 默认输出静态页面，内容集合适合 Markdown |
| 样式 | Tailwind CSS + 自定义令牌 | 快速搭布局，同时保留自己的视觉系统 |
| 搜索 | Pagefind | 构建期生成索引，不需要搜索服务 |
| 公式 | KaTeX + MathML | 阅读页渲染公式，同时保留可访问副本 |
| 评论 | Giscus | 基于 GitHub Discussions，静态站可直接接入 |
| 部署 | GitHub Actions + Pages | 推送即构建，不需要服务器 |

## 内容模型

内容分成三类，分别放在独立集合中：

- `posts`：文章、学习章节；
- `series`：学习专题，定义标题、封面、图标和排序；
- `projects`：项目，包含状态、仓库地址和展示封面。

文章使用 frontmatter 定义标题、摘要、日期、标签、分类、系列和顺序。校验放在内容集合的 schema 里：缺少必填字段、学习章节缺少 `series` / `order`、系列顺序重复，都会在检查或构建时直接报错。

这样做的好处是，新增内容只需要加一个 Markdown 文件，不需要改页面代码。

## 阅读体验

长文章完整渲染在一个页面里，保留正文、公式、章节锚点和浏览器查找。文章页提供：

- h2/h3 目录；
- 阅读进度与本机阅读记录；
- 代码复制、打印和返回顶部；
- 上一篇 / 下一篇与相关文章。

目录和阅读记录都缓存测量结果，滚动时只更新当前章节，避免反复测量整篇长文。

## 搜索

搜索索引在 `astro build` 之后由 Pagefind 生成，只在构建产物中存在。开发服务器没有索引，所以搜索要在 `npm run preview` 或部署后的网站验证。

快捷搜索和完整搜索页共享同一套查询状态：`Ctrl/Cmd K` 打开弹窗，方向键选择，Enter 打开，Escape 关闭并恢复焦点。搜索结果会核验标题、摘要和正文，避免 Pagefind 对公式或符号归一化后产生无关命中。

## 资源与字体

- 封面使用 SVG，分享预览使用同名 1200×630 PNG；
- 中文字体按站点语料生成子集，构建时不需要下载外部字体；
- 画廊保留原图，同时生成 WebP/AVIF 候选图，用 `<picture>` 按视口选择；
- 图片声明宽高，首屏图片使用 `fetchpriority`，其余懒加载。

这些资源都由脚本生成并提交，部署时不需要额外的图片服务或字体 CDN。

## 部署

推送到 `main` 或 `master` 后，GitHub Actions 依次执行单元检查、Astro 检查和生产构建，再把 `dist/` 发布到 GitHub Pages。

站点域名和子目录通过 `SITE_URL` 与 `BASE_PATH` 控制，因此同一套代码可以部署在根域名，也可以部署在仓库子目录。

## 明确不引入的东西

为了保持低维护成本，这个站点没有引入：

- 运行时数据库；
- 客户端路由框架；
- 第三方搜索服务；
- 需要登录的内容后台；
- 外部字体或图片 CDN。

这些能力不是不能用，而是当前规模下收益不足以抵消维护成本。等内容量或协作需求真正增长，再评估是否引入。

## 维护清单

- 新增文章：复制模板，补 frontmatter，运行检查与构建。
- 新增学习专题：先建系列文件，再给章节填 `series` 和 `order`。
- 新增照片：放入 JPEG，更新 `photos` 数组，运行 `npm run gallery:prepare`。
- 更新字体：运行 `npm run fonts:prepare`，检查清单与页面实际加载。
- 发布前：`npm run check && npm run test:unit && npm run build`，并在预览中检查搜索、公式和移动端。

这套架构的目标不是“功能最多”，而是三五年后仍然能看懂、能改、能部署。
