## 先建立直觉：迭代器到底是什么

很多初学者第一次见 STL 时都会有一个疑问：

```cpp
std::sort(v.begin(), v.end());
std::accumulate(v.begin(), v.end(), 0);
std::copy(v.begin(), v.end(), out);
```

为什么这些算法总爱接收一对 `begin()` 和 `end()`？

答案是：

> STL 不希望算法只绑定某一种容器，而是希望算法只依赖“如何遍历元素”这件事。

这个“如何遍历元素”的统一抽象，就是**迭代器**。

你可以先把迭代器理解成：

- 它像指针一样，能指向某个元素；
- 它通常能 `*it` 取出当前元素；
- 它通常能 `++it` 移到下一个位置；
- 算法只要会“从起点一直走到终点”，就能复用在很多不同数据结构上。

### 面向小白的类比

如果把容器比作一排书架：

- 容器：负责把书放好；
- 迭代器：像你手里的一根“当前位置指针”；
- 算法：像“从头到尾数一遍”“挑出红色封面的书”“按厚度排序”这种操作流程。

算法不必知道书架底层是木头、铁架还是抽屉式结构；它只关心：

```text
我能不能拿到第一个位置？
我能不能一直往后走？
我怎么知道走到头了？
```

这正是 `begin()`、`end()` 和迭代器在解决的问题。

## 8.1 基本概念

先强调：迭代器是 C++ 里非常重要的抽象。它既有一些共性，同时不同类别的迭代器又各有特点。

核心思想是：

> 迭代器把“访问元素的方式”抽象出来，让用户和算法不用关心容器底层实现的复杂细节。

因此，迭代器是一组要求，不是某一个固定类：

- 你能不能解引用当前元素；
- 你能不能移动到下一个位置；
- 你能不能比较是否到达终点；
- 你还能不能后退、跳跃、做随机访问。

不同算法需要的能力不同，所以标准库才把迭代器分成多种类别。

---

### 8.1.1 迭代器的初步示例

这里先用几个简单例子帮助读者建立感觉。

#### 例 1：累加求和

```cpp
template <size_t N>
double sum(const double (&a)[N]) {
    double result = 0.0;
    for (auto ptr = a; ptr != a + N; ++ptr) {
        result = result + *ptr;
    }
    return result;
}
```

这段代码虽然还没显式写“迭代器”这个词，但思路已经很像迭代器了：

- `ptr` 表示当前位置；
- `*ptr` 读取当前位置元素；
- `++ptr` 移动到下一个位置；
- `ptr != a + N` 表示还没走到终点。

也就是说，**指针本身就是一种迭代器**。

#### 例 2：标准算法直接吃一对迭代器

接着用 `accumulate`、`sort`、`partition`、`copy` 这类算法说明：

```cpp
std::accumulate(c.begin(), c.end(), 0);
std::sort(c.begin(), c.end());
std::partition(c.begin(), c.end(), pred);
std::copy(c.begin(), c.end(), out);
```

这些算法不关心 `c` 是：

- `vector`
- `array`
- `deque`
- 甚至某个你自定义的范围

它们关心的只是：

```text
c.begin() 给我起点
c.end() 给我终点
中间我能按要求访问和移动
```

这正是 STL 泛型编程最重要的味道之一。

#### 例 3：`partition` 返回的是“位置”

还有一个例子： `partition` 会把满足条件的元素放在前半部分，并返回一个迭代器，表示前半部分的结尾、后半部分的开头。

```cpp
auto it = std::partition(c.begin(), c.end(), [](int x) {
    return x < 100;
});
std::sort(c.begin(), it);
```

这里初学者要记住的是 API 背后的规则，不是 API 本身：

> 算法经常返回“迭代器位置”，不是“索引”。

这跟 C++ 标准库整体风格非常一致。

#### 例 4：输出到流

```cpp
std::copy(
    c.begin(), c.end(),
    std::ostream_iterator<typename C::value_type>(out, " ")
);
```

这句代码第一次看很吓人，但意思并不复杂：

- 从 `c.begin()` 到 `c.end()` 读元素；
- 把读到的每个元素交给一个输出迭代器；
- 这个输出迭代器底层把元素写到输出流 `out`。

这也说明：

> 迭代器不只用来“从容器里读”，也可以用来“往某个目标里写”。

---

### 8.1.2 `ostream_range.h` 对被输出对象的要求

这里借一个“输出整个范围”的工具说明：一个对象如果想被当成“可遍历范围”，至少得满足一些基本要求。

最朴素地说，需要有：

- `begin()`
- `end()`

并且从 `begin()` 走到 `end()` 的过程中，拿到的元素要能写到输出流里。

也就是说，一个对象想被这样的工具接受，实际上要满足两件事：

1. **它能被遍历**；
2. **遍历出来的元素能被输出**。

### 小白可以这样记

很多时候我们会把“范围”理解得太抽象。其实在本章语境里，你可以把它先理解成：

> 任何一个“能给出起点和终点”的对象。

比如：

- 一个数组；
- 一个 `vector`；
- 一个 `string`；
- 一个自定义类型，只要它提供了 `begin()` 和 `end()`。

这也是为什么 C++20 以后 `ranges` 会变得很自然——因为前面的思想其实早就铺好了。

## 8.2 迭代器的类别

这一节的核心是帮助读者建立“迭代器不是都一样强”的意识。

不同迭代器支持的操作不同，因此算法会对迭代器能力提出不同要求。

你可以把它理解成一个能力层级：

| 类别 | 能力直觉 |
| --- | --- |
| 输入迭代器 | 我能往前读，但通常只保证单趟。 |
| 前向迭代器 | 我能往前读，而且可以多趟遍历。 |
| 双向迭代器 | 我不仅能 `++`，还能 `--`。 |
| 随机访问迭代器 | 我能像数组下标那样跳来跳去。 |
| 连续迭代器 | 我不仅能随机访问，还保证底层内存连续。 |
| 输出迭代器 | 我主要负责写入目标。 |

一个重要结论是：

> 算法不是“想用谁都行”，它通常会要求至少某一级别的迭代器。

比如：

- `std::sort` 需要随机访问迭代器；
- 所以 `vector` 能用 `std::sort`；
- `list` 只有双向迭代器，所以不能直接用 `std::sort`，而要用 `list::sort()`。

---

### 补充：标准里的命名问题

这里要特别提到一个容易让初学者迷糊的点：标准库历史上有个 `std::iterator`，而很多容器内部又有自己的 `iterator` 类型名。

例如：

```cpp
std::vector<int>::iterator
std::list<int>::iterator
```

这里的 `iterator` 表示“这个容器的迭代器类型”。

但旧代码里还可能看到：

```cpp
struct MyIterator : std::iterator<...> { ... };
```

这属于历史写法。对初学者而言，先记住两点就够了：

1. `iterator` 既可能是“类型名的一部分”，也可能在历史资料里指一个旧辅助模板；
2. 现代 C++ 新代码里，通常不再依赖旧的 `std::iterator` 来定义自定义迭代器。

### 8.2.1 迭代器

这里给一个自定义输入迭代器的骨架，重点不在于你现在就能手写复杂迭代器，而在于理解：

> 一个迭代器类型通常不只要会 `*` 和 `++`，还要向标准库说明自己是什么类型、属于哪一类迭代器。

常见关联类型包括：

```cpp
using difference_type   = std::ptrdiff_t;
using value_type        = T;
using pointer           = T*;
using reference         = T&;
using iterator_category = std::input_iterator_tag;
```

这些名字的作用大致是：

| 名字 | 含义 |
| --- | --- |
| `difference_type` | 两个迭代器之间距离的类型。 |
| `value_type` | 迭代器指向的元素类型。 |
| `pointer` | 指针类型。 |
| `reference` | 解引用后得到的引用类型。 |
| `iterator_category` | 这是哪一类迭代器。 |

### 对小白最重要的理解

你现在不必死记这些 typedef / using 细节，但要抓住核心：

> STL 不只是“调用你的 `operator*` 和 `operator++`”，它还会根据迭代器提供的类别信息，判断你能不能参与某种算法。

---

### 8.2.2 输入迭代器

输入迭代器（input iterator）的关键词是：

> 能读，通常只保证单趟读取。

典型特征：

- 可以 `*it` 读取当前元素；
- 可以 `++it` 前进；
- 不保证能来回走；
- 不保证一个位置可以反复读取很多次而语义完全稳定。

这里用“从流中读取一行一行内容”的思路来说明输入迭代器。它非常适合表示：

```text
我从某个输入源里不断读下一个值
读过去就过去了
```

### 小白类比

输入迭代器像你在看一卷自动吐纸的打印纸：

- 你可以读当前这一行；
- 然后纸往前走一格；
- 过去的行不一定还能重新读。

所以输入迭代器非常适合“流式输入”场景。

### 易错点

不要默认输入迭代器支持“多次遍历同一区间”。

如果一个算法需要：

- 先走一遍统计；
- 再走一遍处理；

那输入迭代器就可能不够强。

---

### 8.2.3 前向迭代器

前向迭代器（forward iterator）比输入迭代器更强。

它除了能：

- 读取当前位置；
- `++` 往前走；

还额外强调：

> 它支持多趟遍历。

也就是说，你可以：

- 保存某个位置；
- 之后再回来继续用；
- 同一个区间可以被反复遍历。

这比输入迭代器稳定得多。

### 为什么这很重要

很多容器算法默认你可以多次遍历同一个范围。如果只有输入迭代器，那些写法就不一定成立。

因此前向迭代器在“泛型算法能否放心使用”这件事上，是一个很重要的门槛。

---

### 8.2.4 双向迭代器

双向迭代器（bidirectional iterator）在前向迭代器基础上，再增加了一个能力：

```cpp
--it
```

也就是说，它既能往前，也能往后。

典型容器：

- `list`
- `set`
- `map`

### 反向迭代器

这里也结合反向迭代器来讲。

容器常见接口：

```cpp
rbegin()
rend()
crbegin()
crend()
```

它们让你可以倒着遍历：

```cpp
for (auto it = c.rbegin(); it != c.rend(); ++it) {
    // 从后往前看元素
}
```

### 一个特别容易糊涂的点：`reverse_iterator::base()`

如果以后你读到反向迭代器的 `base()`，要知道：

> `base()` 指向的是“当前反向位置所对应元素的下一个正向位置”。

这是反向迭代器最常见的绕点之一。初学阶段先知道它不等于“当前元素的正向迭代器”就够了。

---

### 8.2.5 随机访问迭代器

随机访问迭代器（random access iterator）已经很强了。它支持的典型操作包括：

```cpp
i += n
i -= n
i + n
i - n
i[n]
i < j
i > j
j - i
```

也就是说，它几乎像数组指针一样，可以快速跳到任意偏移位置。

需要明确，标准库容器里：

- `array`
- `vector`
- `deque`

的迭代器都满足随机访问迭代器的要求。

### 为什么 `std::sort` 需要它

排序算法内部会频繁：

- 跳到中间位置；
- 比较两个位置；
- 根据偏移快速定位。

如果只能 `++` 一步一步挪，那效率和实现方式都会受很大限制。

所以：

> `std::sort` 需要随机访问迭代器，而不是所有容器都能直接用它。

---

### 8.2.6 连续迭代器

连续迭代器（contiguous iterator）是 C++20 里强调的概念。

它比随机访问迭代器还要多一个保证：

> 迭代器指向的元素在内存中是连续存放的。

这意味着它不仅能跳跃访问，还能和底层连续内存的假设配合使用。

核心意思是：

- “能随机访问”不等于“内存连续”；
- `deque` 可以随机访问，但整体通常不是一整块连续内存；
- `array` 和 `vector` 的迭代器才满足连续迭代器要求；
- `string` 的迭代器通常也可以看成满足这一要求。

### 小白要区分的两个概念

| 概念 | 含义 |
| --- | --- |
| 随机访问 | 我能快速跳到第 `n` 个位置。 |
| 连续存储 | 第 `n` 个元素和第 `n+1` 个元素在内存里紧挨着。 |

这两个概念相关，但不完全相同。

---

### 8.2.7 输出迭代器

输出迭代器（output iterator）的重点是：

> 它是用来“写”的，不是用来“读”的。

例如 `ostream_iterator` 的例子：

```cpp
std::copy(c.begin(), c.end(), std::ostream_iterator<int>(cout, " "));
```

这里的输出迭代器每次“接到一个值”，就把这个值写到输出流里。

### 另一个很常见的输出迭代器：`back_inserter`

```cpp
std::vector<int> d;
std::copy(c.begin(), c.end(), std::back_inserter(d));
```

这句代码的效果相当于：

- 每复制一个元素；
- 就调用一次 `d.push_back(...)`。

因此 `back_inserter` 很适合：

- 目标容器一开始是空的；
- 你不知道最终会复制多少个元素；
- 你不想自己先 `resize` 好目标区间。

### 但也别把 `back_inserter` 神化

特别提醒：`back_inserter` 很方便，但不是所有场景都最优。

如果：

- 目标大小早已明确；
- 目标容器已经 `resize` 到位；

直接复制到现成区间里可能更直接，也可能更高效：

```cpp
std::vector<int> d(c.size());
std::copy(c.begin(), c.end(), d.begin());
```

### 关键区别

- 输出迭代器强调“把值送出去”；
- 它不保证你能再把那个位置读回来；
- 所以输出迭代器和输入迭代器的关注点完全不同。

## 8.3 基于范围的 `for` 循环

接着看：前面很多地方我们已经在使用“一对迭代器”遍历对象了，于是 C++11 引入了更自然的写法：

```cpp
for (auto ch : s) {
    ...
}
```

这就是基于范围的 `for` 循环（range-based for loop）。

重点是：

> 范围 `for` 并不是新遍历机制，它实际上仍然是 `begin/end` 加普通循环的语法糖。

### 一个直观例子

先看传统写法：

```cpp
size_t countLowerCase(const string& s) {
    size_t count = 0;
    for (auto it = s.begin(); it != s.end(); ++it) {
        if (islower(static_cast<unsigned char>(*it))) {
            ++count;
        }
    }
    return count;
}
```

然后改写成范围 `for`：

```cpp
size_t countLowerCase(const string& s) {
    size_t count = 0;
    for (auto ch : s) {
        if (islower(static_cast<unsigned char>(ch))) {
            ++count;
        }
    }
    return count;
}
```

第二种写法更短，也更贴近“逐个取元素”的思维。

### 它背后大致会展开成什么

对一个普通范围表达式 `_range`，可以粗略理解成：

```cpp
{
    auto&& __range = _range;
    auto __begin = begin(__range);
    auto __end = end(__range);
    for (; __begin != __end; ++__begin) {
        auto ch = *__begin;
        ...
    }
}
```

所以只要一个对象能：

- `begin(...)`
- `end(...)`

它通常就能参与范围 `for`。

---

### 8.3.1 范围表达式的生存期问题

这是本章一个非常容易踩坑、也非常值得记住的点。

：如果范围表达式是一个**临时对象**，那么要特别小心生命周期。

例如某些写法里：

```cpp
for (auto x : getObj().getLines()) {
    ...
}
```

如果 `getObj()` 返回临时对象，而 `getLines()` 又返回依赖这个对象内部状态的范围，那么临时对象销毁后，遍历就可能悬空。

### 初学者应该怎么记

记住一句非常实用的话：

> 如果范围表达式有点复杂，先把它存进一个具名变量，再遍历。

例如：

```cpp
auto obj = getObj();
for (auto x : obj.getLines()) {
    ...
}
```

这样通常更安全，也更清楚。

还提到新标准对这个问题做过修补和改进，但学习阶段最稳妥的策略仍然是：

- 不要过度依赖复杂临时表达式；
- 先保存，再遍历。

### 8.3.2 键-值对容器的遍历

这里要专门提醒一个 `map` 遍历时非常常见的错误。

假设：

```cpp
std::map<int, std::string> mp;
```

很多人会写：

```cpp
for (const std::pair<int, std::string>& kv : mp) {
    ...
}
```

这其实不对。因为 `map` 的元素类型不是：

```cpp
std::pair<int, std::string>
```

而是：

```cpp
std::pair<const int, std::string>
```

也就是说，键是 `const`。

### 最推荐的写法

方向很明确：

#### 写法 1：直接 `auto`

```cpp
for (const auto& kv : mp) {
    std::cout << kv.first << ": " << kv.second << '\n';
}
```

#### 写法 2：结构化绑定

```cpp
for (const auto& [k, v] : mp) {
    std::cout << k << ": " << v << '\n';
}
```

这两种都很好。

### 为什么推荐 `const auto&`

因为它能同时解决三个问题：

- 不用手写容易写错的真实元素类型；
- 不会复制每个键值对；
- 表意清楚：只是读，不修改容器元素。

---

### 8.3.3 哨兵类型

这节是本章比较进阶、但非常有启发的一节。

很多初学者默认会以为：

> `begin()` 和 `end()` 返回的必须是同一种类型。

答案是：不一定。

有时候终点完全可以由一个**哨兵类型**（sentinel）来表示。

#### 典型例子：C 风格字符串

C 风格字符串靠结束符判断，不靠现成长度：

```cpp
'\0'
```

所以可以设计一个哨兵：

```cpp
template <typename I>
bool operator!=(null_sentinel, I i) {
    return *i != 0;
}
```

于是就能让一段 C 字符串像范围一样被遍历。

进一步给出一个包装类思路：

```cpp
class c_string_reader {
public:
    explicit c_string_reader(const char* s) : ptr_(s) {}

    const char* begin() const { return ptr_; }
    null_sentinel end() const { return {}; }

private:
    const char* ptr_;
};
```

这样就可以：

```cpp
for (char ch : c_string_reader(msg)) {
    std::cout << ch;
}
```

### 这一节真正想教什么

重点在建立一个更现代的认识，不是马上手写各种哨兵：

> “一段范围的结束条件”不一定必须是“另一个同类型位置”；只要能判断什么时候该停，就可以抽象成终点。

这也是 C++20 ranges 体系里的重要思想之一。

---

## 8.4 小结

本章主线非常清晰：

1. **迭代器是统一遍历接口**：算法尽量不依赖具体容器，而依赖迭代器；
2. **迭代器有能力层级**：不同算法需要不同强度的迭代器；
3. **范围 `for` 只是语法糖**：背后仍然是 `begin/end` 和迭代器循环；
4. **终点不一定是同类型迭代器**：哨兵让“结束条件”这个概念更灵活。

如果你只记住一句话，那就是：

> STL 的很多威力，都来自“容器负责存数据，迭代器负责走数据，算法负责处理数据”。

## 关键术语表

| 术语 | 解释 |
| --- | --- |
| 迭代器 | 用统一方式访问序列中元素的位置对象或抽象。 |
| 泛型算法 | 不依赖具体容器、只依赖迭代器能力的算法。 |
| `begin()` | 返回范围起始位置的迭代器。 |
| `end()` | 返回尾后位置或终止标记。 |
| 尾后位置 | 指向最后一个元素后面的位置，不能解引用。 |
| 输入迭代器 | 主要用于读取、通常只保证单趟遍历的迭代器。 |
| 前向迭代器 | 支持多趟遍历的向前迭代器。 |
| 双向迭代器 | 同时支持 `++` 和 `--` 的迭代器。 |
| 随机访问迭代器 | 支持跳跃访问、下标、距离计算等操作的迭代器。 |
| 连续迭代器 | 额外保证底层元素在内存中连续存放的迭代器。 |
| 输出迭代器 | 主要用于向目标位置或目标对象写入数据的迭代器。 |
| `ostream_iterator` | 把写入动作转成输出流写出的输出迭代器。 |
| `back_inserter` | 把赋值动作转成 `push_back` 的插入迭代器适配器。 |
| 反向迭代器 | 让容器按反方向遍历的迭代器。 |
| 范围 `for` | 基于 `begin/end` 的遍历语法糖。 |
| 结构化绑定 | 用 `auto [a, b]` 形式拆开复合对象的语法。 |
| 哨兵 | 表示遍历终止条件的类型，不必与起点迭代器同型。 |
