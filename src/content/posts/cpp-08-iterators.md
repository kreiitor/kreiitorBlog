## 先建立直觉：迭代器到底是什么

很多初学者第一次见 STL，会疑惑这些算法为什么总接收一对 `begin()` 和 `end()`：

```cpp
std::sort(v.begin(), v.end());
std::accumulate(v.begin(), v.end(), 0);
std::copy(v.begin(), v.end(), out);
```

STL 不希望算法只绑定某一种容器，只希望它依赖「如何遍历元素」这件事。

这个统一抽象就是**迭代器**。

你可以先把迭代器理解成：

- 它像指针一样，能指向某个元素；
- 它通常能 `*it` 取出当前元素；
- 它通常能 `++it` 移到下一个位置；
- 算法只要会「从起点一直走到终点」，就能复用在很多不同数据结构上。

### 书架类比

如果把容器比作一排书架，容器负责把书放好，迭代器像你手里的一根「当前位置指针」。算法则是「从头到尾数一遍」「挑出红色封面的书」这类操作流程。

算法不必知道书架底层是木头、铁架还是抽屉式结构，它只关心：

```text
我能不能拿到第一个位置？
我能不能一直往后走？
我怎么知道走到头了？
```

`begin()`、`end()` 和迭代器解决的就是这几个问题。

## 8.1 基本概念

迭代器是 C++ 里非常重要的抽象。各类迭代器有共性，也有各自的能力边界。

> 迭代器把「访问元素的方式」抽象出来，让用户和算法不用关心容器底层实现的细节。

所以迭代器是一组要求，没有对应的固定类：

- 你能不能解引用当前元素；
- 你能不能移动到下一个位置；
- 你能不能比较是否到达终点；
- 你还能不能后退、跳跃、做随机访问。

不同算法需要的能力不同，所以标准库才把迭代器分成多种类别。

---

### 8.1.1 迭代器的初步示例

先看几个例子。

#### 例 1：累加求和

```cpp
template <size_t N>
double sum(const double (&a)[N]) {
    double result = 0.0;
    for (auto ptr = a; ptr != a + N; ++ptr) {
        result = result + *ptr;
    }
    return result;
}
```

这段代码没有出现「迭代器」这个词，做法却已经是迭代器的做法：

- `ptr` 表示当前位置；
- `*ptr` 读取当前位置元素；
- `++ptr` 移动到下一个位置；
- `ptr != a + N` 表示还没走到终点。

**指针本身就是一种迭代器**。

#### 例 2：标准算法直接吃一对迭代器

它们的共同点是只接收起止位置：

```cpp
std::accumulate(c.begin(), c.end(), 0);
std::sort(c.begin(), c.end());
std::partition(c.begin(), c.end(), pred);
std::copy(c.begin(), c.end(), out);
```

这些算法不关心 `c` 是：

- `vector`
- `array`
- `deque`
- 甚至某个你自定义的范围

它们关心的只是：

```text
c.begin() 给我起点
c.end() 给我终点
中间我能按要求访问和移动
```

STL 泛型编程的复用就来自这里。

#### 例 3：`partition` 返回的是「位置」

`partition` 会把满足条件的元素放在前半部分，并返回一个迭代器，表示前半部分的结尾、后半部分的开头。

```cpp
auto it = std::partition(c.begin(), c.end(), [](int x) {
    return x < 100;
});
std::sort(c.begin(), it);
```

要记住的是这条规则：

> 算法返回的常常是「迭代器位置」，而不是索引。

C++ 标准库整体保持这个风格。

#### 例 4：输出到流

```cpp
std::copy(
    c.begin(), c.end(),
    std::ostream_iterator<typename C::value_type>(out, " ")
);
```

这句代码第一次看很吓人，意思并不复杂：

- 从 `c.begin()` 到 `c.end()` 读元素；
- 把读到的每个元素交给一个输出迭代器；
- 这个输出迭代器底层把元素写到输出流 `out`。

迭代器不只用来从容器里读，也可以往某个目标里写。

---

### 8.1.2 `ostream_range.h` 对被输出对象的要求

一个对象想被「输出整个范围」的工具接受，至少要有：

- `begin()`
- `end()`

从 `begin()` 走到 `end()` 的过程中，拿到的元素要能写到输出流里。

于是要求变成两件事：

1. **它能被遍历**；
2. **遍历出来的元素能被输出**。

### 范围的最低条件

「范围」这个词容易被想得太抽象。在这里可以把它理解成：

> 任何一个能给出起点和终点的对象。

比如：

- 一个数组；
- 一个 `vector`；
- 一个 `string`；
- 一个自定义类型，只要它提供了 `begin()` 和 `end()`。

C++20 之后 `ranges` 显得自然，是因为这套思想已经在了。

---

## 8.2 迭代器的类别

迭代器支持的操作不同，算法对迭代器能力的要求也不同。可以把它们看成一层层的能力：

| 类别 | 能力直觉 |
| --- | --- |
| 输入迭代器 | 我能往前读，但通常只保证单趟。 |
| 前向迭代器 | 我能往前读，而且可以多趟遍历。 |
| 双向迭代器 | 我不仅能 `++`，还能 `--`。 |
| 随机访问迭代器 | 我能像数组下标那样跳来跳去。 |
| 连续迭代器 | 我不仅能随机访问，还保证底层内存连续。 |
| 输出迭代器 | 我主要负责写入目标。 |

算法不会「想用谁都行」，通常要求至少达到某一级别的迭代器。

`std::sort` 需要随机访问迭代器，所以 `vector` 能直接用。`list` 只有双向迭代器，得改用 `list::sort()`。

---

### 标准里的命名问题

标准库历史上有个 `std::iterator`，很多容器内部又有自己的 `iterator` 类型名，这两个名字容易混。

例如：

```cpp
std::vector<int>::iterator
std::list<int>::iterator
```

这里的 `iterator` 表示这个容器的迭代器类型。

但旧代码里还可能看到：

```cpp
struct MyIterator : std::iterator<...> { ... };
```

这是历史写法。先记住两点：

1. `iterator` 既可能是类型名的一部分，也可能在历史资料里指一个旧辅助模板；
2. 现代 C++ 新代码里，通常不再依赖旧的 `std::iterator` 来定义自定义迭代器。

---

### 8.2.1 迭代器

自定义输入迭代器的骨架大致如下。要点是：

> 一个迭代器类型通常不只要会 `*` 和 `++`，还要向标准库说明自己是什么类型、属于哪一类迭代器。

常见关联类型包括：

```cpp
using difference_type   = std::ptrdiff_t;
using value_type        = T;
using pointer           = T*;
using reference         = T&;
using iterator_category = std::input_iterator_tag;
```

这些名字的作用大致是：

| 名字 | 含义 |
| --- | --- |
| `difference_type` | 两个迭代器之间距离的类型。 |
| `value_type` | 迭代器指向的元素类型。 |
| `pointer` | 指针类型。 |
| `reference` | 解引用后得到的引用类型。 |
| `iterator_category` | 这是哪一类迭代器。 |

### 类别信息的作用

这些 typedef / using 细节不必死记，核心是：

> STL 会调用你的 `operator*` 和 `operator++`，也会根据迭代器提供的类别信息，判断你能不能参与某种算法。

---

### 8.2.2 输入迭代器

输入迭代器（input iterator）能读，通常只保证单趟读取。

典型特征：

- 可以 `*it` 读取当前元素；
- 可以 `++it` 前进；
- 不保证能来回走；
- 不保证一个位置可以反复读取很多次而语义完全稳定。

输入迭代器适合表示这种过程：

```text
我从某个输入源里不断读下一个值
读过去就过去了
```

### 打印纸类比

输入迭代器像一卷自动吐纸的打印纸：你读当前这一行，纸往前走一格，过去的行不一定还能重新读。

所以它适合流式输入的场景。

### 易错点

不要默认输入迭代器支持多次遍历同一区间。

一个算法如果要先统计一遍再处理一遍，输入迭代器就可能不够强。

---

### 8.2.3 前向迭代器

前向迭代器（forward iterator）比输入迭代器更强。它除了能读取当前位置、用 `++` 往前走，还支持多趟遍历。

你可以保存某个位置，之后再回来继续用；同一个区间也能被反复遍历。这比输入迭代器稳定得多。

### 多趟遍历的前提

很多容器算法默认你可以多次遍历同一个范围。如果只有输入迭代器，那些写法就不一定成立。

所以前向迭代器是泛型算法能否放心使用的一道门槛。

---

### 8.2.4 双向迭代器

双向迭代器（bidirectional iterator）在前向迭代器基础上多了一个能力：

```cpp
--it
```

它既能往前，也能往后。

典型容器：

- `list`
- `set`
- `map`

### 反向迭代器

容器提供这些反向接口：

```cpp
rbegin()
rend()
crbegin()
crend()
```

它们让你可以倒着遍历：

```cpp
for (auto it = c.rbegin(); it != c.rend(); ++it) {
    // 从后往前看元素
}
```

### `reverse_iterator::base()`

反向迭代器的 `base()` 容易被误解：

> `base()` 指向的是「当前反向位置所对应元素的下一个正向位置」。

这是反向迭代器最常见的绕点之一。初学阶段记住它不等于当前元素的正向迭代器就行。

---

### 8.2.5 随机访问迭代器

随机访问迭代器（random access iterator）支持这些操作：

```cpp
i += n
i -= n
i + n
i - n
i[n]
i < j
i > j
j - i
```

它几乎像数组指针，可以快速跳到任意偏移位置。

标准库容器里：

- `array`
- `vector`
- `deque`

的迭代器都满足随机访问迭代器的要求。

### 为什么 `std::sort` 需要它

排序算法内部要频繁跳到中间位置、比较两个位置。

只能 `++` 一步一步挪的话，效率和实现方式都会受很大限制。

`std::sort` 需要随机访问迭代器，所以不是所有容器都能直接用它。

---

### 8.2.6 连续迭代器

连续迭代器（contiguous iterator）是 C++20 里强调的概念。它比随机访问迭代器多一个保证：

> 迭代器指向的元素在内存中是连续存放的。

它不仅能跳跃访问，还能和底层连续内存的假设配合使用。具体区别是：

- 「能随机访问」不等于「内存连续」；
- `deque` 可以随机访问，但整体通常不是一整块连续内存；
- `array` 和 `vector` 的迭代器才满足连续迭代器要求；
- `string` 的迭代器通常也可以看成满足这一要求。

### 随机访问与连续存储

| 概念 | 含义 |
| --- | --- |
| 随机访问 | 我能快速跳到第 `n` 个位置。 |
| 连续存储 | 第 `n` 个元素和第 `n+1` 个元素在内存里紧挨着。 |

这两个概念相关，但不完全相同。

---

### 8.2.7 输出迭代器

输出迭代器（output iterator）是用来写的，不是用来读的。

例如 `ostream_iterator`：

```cpp
std::copy(c.begin(), c.end(), std::ostream_iterator<int>(cout, " "));
```

这个输出迭代器每接到一个值，就把它写到输出流里。

### 另一个很常见的输出迭代器：`back_inserter`

```cpp
std::vector<int> d;
std::copy(c.begin(), c.end(), std::back_inserter(d));
```

这句代码的效果相当于每复制一个元素，就调用一次 `d.push_back(...)`。

因此 `back_inserter` 适合目标容器一开始是空的、又不知道最终会复制多少个元素的场景。这样也不用先 `resize` 好目标区间。

### 已有目标区间时

`back_inserter` 很方便，但不是所有场景都最优。

目标大小早已明确、容器也 `resize` 到位时，直接复制到现成区间可能更直接，也可能更高效：

```cpp
std::vector<int> d(c.size());
std::copy(c.begin(), c.end(), d.begin());
```

### 关键区别

输出迭代器强调把值送出去，不保证你能再把那个位置读回来。它的关注点和输入迭代器完全不同。

## 8.3 基于范围的 `for` 循环

前面一直在用「一对迭代器」遍历对象。C++11 给了更自然的写法：

```cpp
for (auto ch : s) {
    ...
}
```

这就是基于范围的 `for` 循环（range-based for loop）。

范围 `for` 背后仍然是 `begin/end` 加普通循环，只是语法更短。

### 两种写法

先看传统写法：

```cpp
size_t countLowerCase(const string& s) {
    size_t count = 0;
    for (auto it = s.begin(); it != s.end(); ++it) {
        if (islower(static_cast<unsigned char>(*it))) {
            ++count;
        }
    }
    return count;
}
```

然后改写成范围 `for`：

```cpp
size_t countLowerCase(const string& s) {
    size_t count = 0;
    for (auto ch : s) {
        if (islower(static_cast<unsigned char>(ch))) {
            ++count;
        }
    }
    return count;
}
```

第二种写法更短，也更贴近逐个取元素的思维。

### 它背后大致会展开成什么

普通范围表达式 `_range` 大致展开成：

```cpp
{
    auto&& __range = _range;
    auto __begin = begin(__range);
    auto __end = end(__range);
    for (; __begin != __end; ++__begin) {
        auto ch = *__begin;
        ...
    }
}
```

所以一个对象只要能提供 `begin(...)` 和 `end(...)`，通常就能参与范围 `for`。

---

### 8.3.1 范围表达式的生存期问题

如果范围表达式是**临时对象**，要特别小心生命周期。

例如：

```cpp
for (auto x : getObj().getLines()) {
    ...
}
```

如果 `getObj()` 返回临时对象，而 `getLines()` 又返回依赖这个对象内部状态的范围，那么临时对象销毁后，遍历就可能悬空。

### 先存再遍历

一条实用的规则：

> 如果范围表达式有点复杂，先把它存进一个具名变量，再遍历。

例如：

```cpp
auto obj = getObj();
for (auto x : obj.getLines()) {
    ...
}
```

这样通常更安全，也更清楚。

新标准对这个问题做过修补，但学习阶段最稳妥的做法仍然是：

- 不要过度依赖复杂临时表达式；
- 先保存，再遍历。

### 8.3.2 键-值对容器的遍历

`map` 遍历有一个很常见的错误。

假设有：

```cpp
std::map<int, std::string> mp;
```

很多人会写：

```cpp
for (const std::pair<int, std::string>& kv : mp) {
    ...
}
```

这不对。`map` 的元素类型常被写成：

```cpp
std::pair<int, std::string>
```

实际是：

```cpp
std::pair<const int, std::string>
```

键是 `const`。

### 推荐写法

#### 写法 1：直接 `auto`

```cpp
for (const auto& kv : mp) {
    std::cout << kv.first << ": " << kv.second << '\n';
}
```

#### 写法 2：结构化绑定

```cpp
for (const auto& [k, v] : mp) {
    std::cout << k << ": " << v << '\n';
}
```

这两种都很好。

### 为什么推荐 `const auto&`

它不用手写容易写错的真实元素类型，也不会复制每个键值对。读的意图也清楚：不修改容器元素。

### 8.3.3 哨兵类型

很多初学者默认 `begin()` 和 `end()` 返回同一种类型。

不一定。

有时候终点完全可以由一个**哨兵类型**（sentinel）来表示。

#### 典型例子：C 风格字符串

C 风格字符串没有现成长度，靠结束符判断：

```cpp
'\0'
```

所以可以设计一个哨兵：

```cpp
template <typename I>
bool operator!=(null_sentinel, I i) {
    return *i != 0;
}
```

于是就能让一段 C 字符串像范围一样被遍历。

包装类可以这样写：

```cpp
class c_string_reader {
public:
    explicit c_string_reader(const char* s) : ptr_(s) {}

    const char* begin() const { return ptr_; }
    null_sentinel end() const { return {}; }

private:
    const char* ptr_;
};
```

这样就可以：

```cpp
for (char ch : c_string_reader(msg)) {
    std::cout << ch;
}
```

### 结束条件不必同型

更现代的认识是：

> 「一段范围的结束条件」不一定必须是「另一个同类型位置」；只要能判断什么时候该停，就可以抽象成终点。

这也是 C++20 ranges 体系里的重要想法之一。

---

## 8.4 小结

四条主线：

1. **迭代器是统一遍历接口**：算法尽量不依赖具体容器，而依赖迭代器；
2. **迭代器有能力层级**：不同算法需要不同强度的迭代器；
3. **范围 `for` 只是语法糖**：背后仍然是 `begin/end` 和迭代器循环；
4. **终点不一定是同类型迭代器**：哨兵让「结束条件」这个概念更灵活。

容器存数据，迭代器走数据，算法处理数据。三者能拼在一起，靠的是迭代器这个统一接口。

## 关键术语表

| 术语 | 解释 |
| --- | --- |
| 迭代器 | 用统一方式访问序列中元素的位置对象或抽象。 |
| 泛型算法 | 不依赖具体容器、只依赖迭代器能力的算法。 |
| `begin()` | 返回范围起始位置的迭代器。 |
| `end()` | 返回尾后位置或终止标记。 |
| 尾后位置 | 指向最后一个元素后面的位置，不能解引用。 |
| 输入迭代器 | 主要用于读取、通常只保证单趟遍历的迭代器。 |
| 前向迭代器 | 支持多趟遍历的向前迭代器。 |
| 双向迭代器 | 同时支持 `++` 和 `--` 的迭代器。 |
| 随机访问迭代器 | 支持跳跃访问、下标、距离计算等操作的迭代器。 |
| 连续迭代器 | 额外保证底层元素在内存中连续存放的迭代器。 |
| 输出迭代器 | 主要用于向目标位置或目标对象写入数据的迭代器。 |
| `ostream_iterator` | 把写入动作转成输出流写出的输出迭代器。 |
| `back_inserter` | 把赋值动作转成 `push_back` 的插入迭代器适配器。 |
| 反向迭代器 | 让容器按反方向遍历的迭代器。 |
| 范围 `for` | 基于 `begin/end` 的遍历语法糖。 |
| 结构化绑定 | 用 `auto [a, b]` 形式拆开复合对象的语法。 |
| 哨兵 | 表示遍历终止条件的类型，不必与起点迭代器同型。 |
