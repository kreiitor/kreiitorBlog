## 退回分节阅读（2026-10-13 晚）

分节让长文首屏更小（公式长文第一节 414,882B），但把一篇文章切成多个网址：跨节回看、引用上下文、复制整篇都要翻页。按阅读体验优先，本次退回分节：

- 移除 `src/utils/reading.mjs`、`src/pages/blog/[slug]/[part].astro` 和文章页的分节导航与旧锚点转发，文章重新用内容集合的 `render()` 整篇渲染，页内锚点回到同一页面。
- 保留重构期间的其余改动：pagefind 权重与页面元信息、封面图 `fetchpriority`、相邻章节导航、移动端目录、评论接近正文末尾才加载。
- 测试同步为单页语义：单元测试改为“整页渲染时重复标题仍有独立锚点”，浏览器测试改为“整篇长文渲染在一页且页内锚点可用”。

| 指标 | 分节实现 | 退回后 |
| --- | --- | --- |
| 构建 HTML 页面 | 431 | 124 |
| 站内引用检查 | 27,899 | 5,511 |
| 公式长文 HTML | 414,882B（第一节） | 4,131,727B（整篇） |

公式长文回到整篇 4.1MB 量级，与退回基点 `49922ef` 的 4,137,472B 相当，页内 26 个二级标题锚点齐全；这一页的手机性能会相应回落，属于用体积换阅读连续性的取舍，本次未重新测量 Lighthouse。

验证：`npm run check`（52 个文件，0 错误、0 警告、0 提示）、3 项单元测试与学习系列检查、`npm run build`（124 页，pagefind 索引 58 页），以及根路径与 `BASE_PATH=/kreiitorBlog` 子目录各 16 项浏览器测试（合计 32 项）全部通过；构建后检查 124 个 HTML 页面、5,511 条内部引用、每页单一 H1、无公式错误。
