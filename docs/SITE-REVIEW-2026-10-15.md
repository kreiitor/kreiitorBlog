## 顶部滚动问题：确认与修复

原实现有如下反馈链：`scrollY > 20` 切换 `data-scrolled` → 导航内容高度从 88px 变为 64px → 文档布局变化 24px → 某些长文场景下浏览器补偿滚动位置 → 再次跨过阈值，触发反向动画。

首页可以稳定观察到 24px 的额外布局位移；数学长文还复现了反复切换与滚动偏移。750ms 采样窗口中，部分试验状态切换达到 4–5 次。例如，从深处设置到 19px 的一轮长文试验，采样结束时实际是 42px；这些是动画反馈期间的实测位置，不表示每次必现或所有浏览器都相同。

独立测试中，原有浮动“回到顶部”按钮仍能到达 `scrollY = 0`，因此不能把它描述为每次都失效。已确认的是阈值附近的布局跳动、回弹和反复切换，它与用户描述的“差一截、抖动”相符。原手机样式的导航高度一直为 74px，本次桌面根因不能直接等同于所有真实手机上的问题。

本次修改 `src/components/SiteHeader.astro`：桌面导航内容高度始终为 88px，手机始终为 74px；去掉滚动时的高度与图标尺寸动画，保留 sticky 定位和滚动阴影。代价是桌面阅读时导航比原收缩状态多占 24px。

新增 `tests/browser/scroll.spec.mjs`，逐帧检查跨阈值时导航高度和正文文档坐标，检查滚轮、浮动链接、页脚链接、键盘和触摸输入回顶后能保持在 0。旧实现的首页回归用例确实失败，测得高度变化为 24px；修复后，首页与长文的 40 组阈值对照中，布局额外位移均为 0，最终位置均等于请求位置。

| 相同的 40 组阈值试验 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 最大额外布局位移 | 24px | 0px |
| 单次 750ms 内最多状态切换次数 | 5 | 1 |
| 采样窗口结束时偏离请求位置的试验数 | 9 | 0 |

## 验证与后续优先级

- `npm run check`：0 errors / 0 warnings / 0 hints。
- `npm run test:unit`：3 项单元测试和系列检查通过。
- `npm run build`：131 页、11,041 处本地引用检查通过，单一 H1 与公式检查通过。
- 原有 50 项浏览器测试：41 通过，9 未通过。失败项为主题旧预期 6 项、分页硬编码数量 2 项、320px 首页真实横向溢出 1 项。主题测试仍断言三态/旧纸色；当前实现是两态/新纸色。分页测试仍预期第二页 2 条，当前内容实际为 6 条。这些失败在修改导航之前已出现，本次不调整这些功能或测试契约。
- 新增滚动回归独立复验：9 通过、1 跳过（桌面项目不运行手机触摸用例）。涵盖首页与长文的逐帧布局稳定性、滚轮、键盘、两种回顶链接和手机原生触摸输入。

全量运行中，新增触摸用例最初使用 Chrome 的 `Input.synthesizeScrollGesture`，协议调用成功但没有产生滚动。已用真实 `Input.dispatchTouchEvent` 序列替换，并对新增测试单独复验。完整原始运行记录保留在 `browser-final.json`，修正输入驱动后的滚动测试记录在 `browser-scroll-final.json`，因此前者仍保留这一项已处理的测试驱动失败。

3. **随后处理**：h3 目录高亮、过时主题与分页测试、画廊图片尺寸声明。
