## 2. 重构方向

### 2.1 方向一（P0）：暗色模式

#### 2.1.1 用什么色：暖底 + 提亮的强调色

**不要用 Material 的 `#121212`。** 实测 18 个实现暗色的站点里**只有 2 个**用它（`allanware-zh`、`andlukyane`），且都是最套模板的两个；而 `gwern` 与 `mollywhite` **互不相关却独立收敛到 `#161616` / `#f1f1f1`**，`gwern` 还在 CSS 注释里写明理由：纯 `#000` 会因像素熄灭造成 *"nasty scrolling/update jank"*，纯 `#fff` 正文 *"too high & stark"*。

**更要紧的是：`#121212` 是冷中性，紧邻我们的陶土 `#925134` 会把暖意抽干**——等于用暗色模式否定「温暖数字花园」的品牌。

建议 token（沿用现有名，只换值）：

| token | 浅色（现状） | 建议暗色 | 理由 |
| --- | --- | --- | --- |
| `--color-paper` | `#f4f1e8` | **`#1a1a17`** | 取 `#161616` 的思路 + 保留纸色暖相 |
| 卡片/抬升面 | — | `#22211d` | 靠提亮表达层级，而非阴影 |
| 内嵌/代码块 | — | `#141412` | 更深一层 |
| 边框/分隔 | — | `#35342e` | **亮色的墨绿正好当暗色边框** |
| `--color-ink` | `#35382f` | **`#e6e2d6`** | **不用纯白** |
| `--color-ink-soft` | `#5e6458` | `#c9c4b6` | |
| `--color-ink-mute` | `#5e6458` | `#a09b8c` | |
| `--color-accent` | `#925134` | **`#c9805c`** | **必须提亮，见下** |

**这组值我逐条复算过对比度（WCAG 相对亮度公式，独立实现）**：

| 组合 | 对比度 | 判定 |
| --- | --- | --- |
| 正文 `#e6e2d6` / `#1a1a17` | **13.47:1** | ✅ AA |
| 次级 `#c9c4b6` / `#1a1a17` | **10.01:1** | ✅ AA |
| 弱化 `#a09b8c` / `#1a1a17` | **6.28:1** | ✅ AA |
| **陶土原值 `#925134` / `#1a1a17`** | **2.86:1** | ❌ **不达 AA** |
| 陶土提亮 `#c9805c` / `#1a1a17` | **5.59:1** | ✅ AA |

**这是本方向最关键的一条**：我们现在的陶土色**不能直接搬到暗底**，必须另出一档提亮值。同行的一致手法是「**同色相、只抬亮度**」：`mollywhite` 是 `#5948a4 → #b4abda`，`taniarascia` 是 `#fede91 → #b26a34`，`leaverou` 直接写相对色语法 `oklch(from var(--color) clamp(0.7, l, 1) a b)`。

> **WCAG 依据**（W3C 官方仓库原文）：AA 级正常文本 ≥ **4.5:1**，大字号 ≥ **3:1**；「大字号」界定为 *"18 point text or 14 point bold text"*，换算 *"14pt and 18pt are equivalent to approximately 18.5px and 24px"*；**且计算值不得四舍五入**（*"4.499:1 would not meet the 4.5:1 threshold"*）。我们正文 18px **未达 24px 门槛**，因此**必须按 4.5:1 要求**。

#### 2.1.2 用什么机制：两条通路 + 一份变量表

**照抄 `benmyers` 的机制**（已独立核验：它的 **52 处 `:root:not([data-theme])` 无一例外都位于 `prefers-color-scheme` 媒体查询内**）：

```
① :root[data-theme="dark"]    → 用户显式选暗
② :root[data-theme="light"]   → 用户显式选亮
③ @media (prefers-color-scheme: dark) { :root:not([data-theme]) { … } }  → 未设置时跟随系统
④ :root { color-scheme: dark light }   → 表单控件与滚动条跟随
```

**必须避开的坑（都是实测出来的）**：

1. **「跟随系统」必须靠 `removeAttribute`，不能靠空值。** 属性只要存在（**哪怕值是空字符串**），`:not([data-theme])` 就不匹配 → **系统偏好会永远失效**。`benmyers` 是靠 JS 主动 `documentElement.removeAttribute('data-theme')` 才让 System 生效的。
2. **规则不要写成三份。** `benmyers` 为此写了 21 个 dark + 15 个 light 媒体块；`taniarascia` 更极端——**每个 token 复制 4 条规则（59 个 token → 约 236 条）**。在 Tailwind 4 里应压缩成「**一份变量表 + 两条选择器通路**」。
3. **`color-scheme` 必须改。** 现在 `global.css:19` 是硬编码 `color-scheme: light`，要改成 `color-scheme: dark light` 并加 `[data-theme="dark"]{color-scheme:dark}`，否则暗色下表单控件与滚动条会刺眼。

#### 2.1.3 首屏防闪白：内联脚本必须放 `<head>`

**PaperMod 的原始实现有 5 个坑，逐条记录以免照抄**：

| # | PaperMod 的坑（`lilianweng.html`） | 正确做法 |
| --- | --- | --- |
| 1 | 主题脚本是 **`<body>` 的第一个元素**（`:100`）→ 返回访客会闪白 | **放 `<head>` 内的阻塞式内联脚本**；Astro 里**必须用 `<script is:inline>`**（普通 `<script>` 会被提升/打包成 module，就失去解析期阻塞的意义） |
| 2 | `document.body.className.includes("dark")`（`:450`）是**子串匹配**，任何含 "dark" 的类名都会误判 | 用 `classList.contains('dark')` / `dataset.theme` |
| 3 | 暗色 token **只写在 `<noscript>` 里**（`:33-60`），JS 开启时不生效 → 同一套配色维护在两处 | 用 `@media (prefers-color-scheme:dark){:root:not([data-theme])}` 作为**无 JS 也正确**的路径 |
| 4 | **只给 `<body>` 加类**，`<html>` 拿不到 → `color-scheme` 无法切换 | 属性设在 **`documentElement`** |
| 5 | `theme-color` **只有一组值** `#2e2e33`（`:20`） | **明暗两套，带 `media` 属性** |

第 5 点的正确写法（全语料只有 `swyx` 做对）：

```html
<meta name="theme-color" content="#f4f1e8" media="(prefers-color-scheme: light)" />
<meta name="theme-color" content="#1a1a17" media="(prefers-color-scheme: dark)" />
```

另加 `<meta name="color-scheme" content="light dark">`（`leaverou` 的做法），让浏览器在 CSS 到达前就把 UA 底色画对。

#### 2.1.4 需要一并处理的 4 处

1. **代码高亮要双主题。** `src/styles/code-theme.mjs` 现在是单一 `type: 'light'` 的自定义 Shiki 主题，需补一套暖色暗版（沿用现有 scope 分工，只换明度/饱和度），并在 `astro.config.mjs` 的 `shikiConfig` 改为双主题输出。
2. **评论 iframe 要单独处理。** `public/giscus-garden.css` 是浅色花园主题；暗色需一份对应文件。注意 Giscus 主题通过 iframe 的 `theme` 参数注入，**切换主题时要重建 iframe**，否则会出现「页面黑了、评论还是白的」。
3. **插图的双版切换（不必重绘）。** `joshwcomeau` 的做法是给插画准备明暗两版、用 `data-use-global-color-mode` 切换——**我们不必重绘插图，只需在暗色下换一版或加轻度的亮度/对比度校正**。`public/social-card.png` 分享图**保持浅色**（社交预览不随主题变）。
4. **打印不受影响，但要守住。** `global.css:163-171` 已强制白底黑字，暗色不会污染打印。

#### 2.1.5 要不要做切换按钮：两种方案（这是本方向唯一需要你决策的点）

| 方案 | 站点依据 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. 纯 CSS，不做按钮** | `mollywhite`、`leaverou`、`allanware-zh`、`craigmod`（18 个实现暗色的站点里 **4 个这样**） | 零 JS、零状态、**零闪白**、成本最低（`allanware-zh` 的完整实现只有 9 行变量）；`leaverou` 专门撰文主张 **"The best dark mode toggle is probably none"** 与 **"Dark mode toggles: two states are enough"** | 用户在系统设为浅色但想夜间阅读时无解 |
| **B. 三态（亮/暗/跟随系统）+ localStorage** | `benmyers`（最成熟）、`lilianweng`、`swyx`、`liruifengv` | 用户可控；`benmyers` 用 `<segmented-control>` + `aria-pressed`，**「System」选项 = 显式承认系统偏好**，比二态按钮更诚实 | 多一份状态与防闪白脚本；PaperMod 那样只做二态会**钉死**用户选择、没有回到系统的路径 |

**建议：先做 A，把暗色能力建起来；B 作为紧随其后的增量。** 理由：A 是暗色的**前置条件**（变量表 + 两通路本来就要建），且不需要调试首屏闪白；B 只是在 A 之上加一个控件与一个 `removeAttribute` 逻辑。这样风险最低、可分段验收。

### 2.2 方向二（P1/P2）：令牌化与长文阅读的三项补强

#### 2.2.1 颜色与间距令牌化（P1）

**间距走 0.25rem 网格 + 语义名。** 实测 36 个可分析站点：**明确刻度 10 站、部分 4 站、随手值 6 站**；而 **rem / 0.25rem 步进是唯一高一致度体系**（`benmyers` 99%、`mccormickml` 95%、`lutaonan` 89%、`taniarascia` 89%），px 系只有 4px 或 5px 能过半、且从不混用。

**我们的症状与 `alexwest`、`lilianweng` 最像**——`lilianweng` 连自己的 token 都不在同一网格（`--gap:24px` 属 4px 网格、`--content-gap:20px` 属 5px 网格、移动端 `--gap:14px`），于是高频值散成 10/20/14/4/5/8/12/3。

```
--space-3xs:.25rem; --space-2xs:.5rem; --space-xs:.75rem; --space-s:1rem;
--space-m:1.5rem;   --space-l:2rem;    --space-xl:3rem;   --space-2xl:4rem; --space-3xl:6rem;
```

映射：`8→.5rem 12→.75rem 16→1rem 24→1.5rem 32→2rem 48→3rem 64→4rem`。

**两条纪律**：① **不要同时保留 px 与 rem 两套间距刻度**（`lilianweng` 即反面教材）；② **断点、列宽、1px 描边不属于间距刻度，显式登记为例外，不要强行吸附**。

**颜色侧**：43 个硬编码 hex 集中在 8 个文件。**这一步与 §2.1 的变量化是同一件事**（暗色化的前置条件），**合并为一次令牌化工作**：颜色令牌先做，间距令牌紧随其后，共用同一轮截图基线。

#### 2.2.2 目录升到 h3（P2，成本低、收益最高的长文改进）

**我们最实的缺口**：`ArticlePage.astro:19` 只取 `depth === 2`，而实测 **57 篇里 48 篇含 h3、共 1211 个 h3**（`fods-linear-algebra-calculus-convexity.md` 单篇 **26 个 h2 + 83 个 h3**）→ **目录只覆盖骨架的约 1/4**。

**照抄组合**：① **`gwern` 的深度**（目录树嵌到 h3/h4，每项带稳定 `id`）；② **`lilianweng` 的可折叠容器**（`<details>` + `accesskey`，**默认收起**——条目多了必须收起，`benmyers` 默认 `open` 是因为他只有 10 项）；③ **保留我们已有的 `aria-current="location"`**。

**并行可选项**：`allanware-zh` 的**列外 TOC**（`position:fixed; top:50%; left:calc((100vw + var(--width-max))/2); width:calc((90vw - var(--width-max))/2)`）——把目录放进正文栏之外的空白区，不挤占正文、不打断节奏。

#### 2.2.3 脚注：走 craigmod 的语义路线，**不做边注**（P2）

**先确认一个好消息**：`remark-gfm` 由 Astro 默认注入，`[^1]` 语法**本来就能解析**，输出的结构正好是我们要的（我从 `mdast-util-to-hast` 源码确认）：

```html
<sup><a href="#user-content-fn-1" data-footnote-ref aria-describedby="footnote-label">1</a></sup>
<section data-footnotes class="footnotes">
  <h2 class="sr-only" id="footnote-label">Footnotes</h2>
  <ol><li id="user-content-fn-1">…<a href="#user-content-fnref-1" data-footnote-backref>↩</a></li></ol>
</section>
```

**但我们有一个会真实踩到的坑**：那个 `<h2 class="sr-only" id="footnote-label">` 是 **h2**，而我们的 TOC 取 `depth === 2` → **文章一旦用脚注，目录里就会多出一个假的 "Footnotes" 条目**。干净修法是配置项（已从源码确认存在）：

```js
remarkRehype: { footnoteLabel: '脚注', footnoteLabelTagName: 'p' }   // 改 tag 名，假条目不进 TOC
```

**两条路线的取舍（实测）**：

| 路线 | 站点 | 优点 | 代价 |
| --- | --- | --- | --- |
| **文末 endnotes** | `craigmod-essay`、`lilianweng`（后者干脆 `sup`=0，用文末 `<h1 id="references">` + 逐条 `<p>[N] …</p>` + 正文行内链接） | 零 JS、纯静态、无障碍与打印都友好、任何 Markdown 管线都能产出 | 长文里读者要跳到底部再回来 |
| **页边注** | **只有 `gwern` 一家** | 阅读零跳转、信息密度高 | **成本高得多**：`@media (max-width:1760px)` 直接 `display:none`；需 JS 全文 reflow（`gwern` 自述 *"reflow as necessary over the whole page, which is **user-visible & distracting**"*）；纯 CSS 方案会被长注撑爆 |

**结论：做文末脚注（craigmod 的语义标记），暂不做边注。** 边注是 60 站里的孤例，且 `gwern` 自己都承认收益接近无法测量。**若将来真要做，栏宽不要硬写，要从正文测度反推**：

```css
width: calc(50vw - (var(--body-max-width) / 2 + 96px));
max-width: 550px;   /* gwern 的 --GW-sidenotes-max-width */
```

#### 2.2.4 标题永久链接（P2，成本最低、覆盖最高）

3/9 个文章页都做了，且我们**已经有 heading id**（TOC 依赖它），增量只是渲染一个属性 + 一个 `<a>`。**对我们这种跨文档连载（ai-agent ch01–10、ai-infra ch01–12）+ 学习系列导航的站点，「指向某一节」是章节互链与外部引用的前置条件。**

照抄 `benmyers` 最规范的写法：heading 上 `tabindex="-1"`，锚点 `<a rel="bookmark" aria-label="Permalink to «标题»">`。

### 2.3 方向三（P3）：一行级修正（性价比最高的一批）

#### 2.3.1 动效时长收敛到主流带

我们现有 `160 / 220 / 360 / 380ms`。按**站点覆盖率**统计（36 站）：

| 值 | 覆盖站点数 | 判定 |
| --- | --- | --- |
| 200ms / 300ms | **各 14 站**（并列第一） | 主流 |
| 500ms | 11 站 | 常用（面板/页面级） |
| **220ms** | **仅 1 站（`swyx`）** | 我们的值，几乎孤例 |
| **360ms / 380ms** | **59 个实测值里 0 次** | 我们的值，**不存在于语料** |

**建议收敛到 4 档：`150 / 200 / 300 / 500ms`。**
- `150ms`：hover / 焦点 / 颜色
- `200–250ms`：按钮 / 图标 / 透明度
- `300ms`：卡片 / 下拉 / 弹层
- `500ms`：面板 / 页面级
- `≥800ms`：**只给入场与自绘，且必须配 reduce**

**easing**：若只保留一条自定义曲线，用 **`cubic-bezier(0.4, 0, 0.2, 1)`**（Material 标准，语料里自定义曲线中最通用；关键字里 `ease`/`ease-in-out` 占绝对多数）。**不要引入 `joshwcomeau` 那种 `linear()` 弹簧**——它的过冲曲线必须 833ms–1.167s 才看得完整，与我们「克制」的基调不符。

#### 2.3.2 `prefers-reduced-motion` 改成反向 opt-in

**这是本次最值得抄的一条机制。** `benmyers` 的写法经独立核验：**`prefers-reduced-motion` 出现 13 次，全部是 `no-preference`，`reduce` 是 0 次**。

```css
/* 样式表默认一条 transition/animation 都不声明 */
@media (prefers-reduced-motion: no-preference) {
  :root:not([data-animations]) .something { transition: … }
}
```

**为什么比「写了再关掉」更好**：「减少动效」用户的偏好**天然被满足**，不依赖任何覆盖能生效。可另加 `swyx` 的全局兜底作为双保险：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important; animation-iteration-count: 1 !important;
    transition-duration: .001ms !important; scroll-behavior: auto !important;
  }
}
```

**保留**我们已有的 `@media (prefers-reduced-motion: reduce){ @view-transition { navigation: none } }`（`Motion.astro:65`）——`andlukyane` 也有同样写法。

#### 2.3.3 三处 CJK / 排版一行修正

| 现状 | 问题 | 改法 |
| --- | --- | --- |
| `global.css:22` 的 `line-break: strict` **只在 `h1,h2,h3,h4`** | **正文 `.rich-content` 完全没有 CJK 禁则** | 扩展到 `.rich-content`——**本报告性价比最高的一条**，1 行、只影响 CJK 禁则、拉丁无副作用 |
| `global.css:75` 的 `.rich-content{overflow-wrap: anywhere}` | `anywhere` **会参与 `min-content` 尺寸计算**，与我们的 `minmax(0,760px)` 栅格和宽表格相互作用。**语料里 0 家对正文用 `anywhere`**（`gwern`/`joshwcomeau`/`tonsky` 均 `break-word`） | 正文改 `break-word`；`anywhere` **只留给 `pre` 与长 URL** |
| 无中英混排间隙 | 语料里只有 3 家做过（`yibie` 用 Heti、`aemoncao` 用 pangu.js、`lutaonan` 只有 CSS 垫片无运行时） | `.rich-content{text-autospace: normal}` **一行、零依赖、不支持即退化为现状**——**先上这一行，不要一上来就写 JS** |

**可选低优先**：删掉 `.rich-content{letter-spacing:.005em}`（≈0.09px，无视觉收益，却是人为引入 CJK 字距）。

#### 2.3.4 行高：`1.95` 需要自知

语料长文行高聚在 **1.5–1.6**；中文唯一有正文规则的正样本 `lutaonan` 是 **1.85**；`craigmod` 给日文的规则也是 **1.6**。**我们的 `1.95` 是语料观测上限之外的值。**

中文 + 高公式密度确实有理由疏排（900px 阅读高度下 1.95≈25 行/屏、1.6≈30 行），**维持 1.95 不算错**；但要知道这是**超出所有观测样本的选择**，不是「大家都这样」。若想更稳，**建议落到 1.85–1.9**。

### 2.4 方向四（P4）：长文的工程事实与能做的事

#### 2.4.1 已经证实：那 4.1MB 里 41% 是不可见的 MathML

初版与上一轮实施记录都只说了「整篇约 4.1MB」，没查成因。我直接对构建产物做了量化：

| 指标 | 实测 |
| --- | --- |
| `fods-linear-algebra-calculus-convexity` 页面总字节 | **4,083,673** |
| `katex-mathml` 块数（隐藏的 MathML） | **2,232** |
| `katex-html` 块数（可见排版） | **2,232** |
| **MathML 子树估算字节** | **1,661,341 ≈ 全页 40.7%** |
| 元素总数 / `<span>` / `<annotation>` | 109,789 / 75,024 / 2,232 |

**结论：那篇页面约 41%（1.66MB）是视觉上完全不可见的 MathML**，每个公式都同时输出「可见 HTML」与「隐藏 MathML + TeX 源码副本」两份。

**但这是自觉的取舍，不是 bug**——MathML 服务于读屏软件与复制粘贴（我们的实施记录明确写了「可访问 MathML 均保留」）。KaTeX 的 `output` 选项切到单份可近乎减半体积，**代价是牺牲无障碍与公式复制**。

**正确的动作是把这个数字记录下来，而不是删掉 MathML**：它解释了「全文单页必然重」，也说明**继续在 CSS 层微调收益有限**（能动的只有那 59%）。

#### 2.4.2 `content-visibility`：同行已经替我们试过了

**不要再回头做「按章节 content-visibility」**——`gwern--css1.css:1081` 那段被注释掉的代码写着：

> *"Lazy-load below-fold sections in supported browsers. **Disabled temporarily pending layout redesign to compensate for layout containment.** —Obormot 2021-03-21"*

即 **Gwern 团队做过与我们几乎相同的实验（按章节、第 4 节起、`200vh` 占位），并因同一个布局包含问题放弃**。全语料**没有任何站点把 `content-visibility` 用于正文**。

**但有一条安全增量**：把 `content-visibility:auto` **只用在 `<img>` 上**（`maggieappleton`、`allanware-zh` 的既有做法）——图片有显式 `width/height` 时**占位高度确定、文档总高不变，因此不动 TOC 位置、不动阅读进度**，与那个被否决的实验有本质差别。同理 `contain: content` 可挂在**折叠内容包裹层**上（`gwern--css2.css:1534`）：合上时高度为 0。

#### 2.4.3 用 `<details>` 承载长附录

**`chinese-independent-blogs` 给出了最好的范式**：它把「424 个疑似失效博客」的整张表塞进 `<details><summary>展开列表</summary>`。

**这正是我们该抄的形态**：长文里的**附录、原始数据表、超长代码清单**用 `<details>` 折叠，正文只留一句摘要。我们目前 `<details>` 只用在移动端菜单，**没有把它当作「承载长附录」的语义工具**。

### 2.5 方向五（P5）：内容组织与工程卫生

#### 2.5.1 内容组织：没有任何站点实现了真正的「主题树」

**这一点要更正你的原始清单**：你推荐 Eugene Yan 的「把文章归入主题树而非时间流」。实测——**`eugeneyan` 没有层级主题树**（无 series、无父子关系、无反向链接）。它的可导航性来自三层叠加：① **首页人工策展「书架」**（Latest / Trending This Week / More than 50k Reads / Featured Talks / My Favourites / Selected Prototypes / Resources）；② **扁平标签分两类**——**emoji 标签当「栏目」用**（`/tag/🔥/`、`/tag/🩷/`，书架标题直链 tag 页）+ 普通词标签；③ Algolia 搜索。

`swyx` 按**类型**分类（essay/tutorial/podcast/talk），`sgugger` 是 Categories/Tags/Archives 三页分开，`mollywhite` 是侧栏人工分组，**`danluu` 连标题层级都没有**（`h1/h2/h3` 计数全为 0，全站 204 个 `<li>`，CSS 只有 4 条规则）。

**共同结论：层级感全部来自人工策展，而非数据模型。** 这对我们是好消息——**不需要新建数据模型**。

**可落地的三条**（按性价比）：
1. **首页改成策展书架**：手写 4–5 个书架子块、每块 5–10 篇（可用 frontmatter 一个 `shelf:` 字段，或直接列 slug）。**零数据模型改动。**
2. **相关文章**：用「共享 tag 数 + 时间衰减」**本地算**。**不要引入 Algolia**——`eugeneyan` 的相关文章绑死 Algolia Recommend（容器初始 `display:none`），而我们已有 Pagefind，**引入第二个搜索后端是纯负担**。
3. **不做反向链接**（现在）：60 站里**只有 `gwern` 一家**有渲染出来的 backlinks，且依赖「离线 cron 解析全站 URL+ID 链接图」；其余站点只有 `<link rel="webmention">` 声明。等脚注与永久链接落地、内部引用密度上来之后再评估。

**一个反向印证**：`chinese-independent-blogs` 收录 982 个中文博客，**自由标注产生了 630 个不同标签**——**标签词汇量会爆炸**。这印证我们已有的 `canonicalTag` + `tagAliases` 规范化是必需的，**不应放松**。

#### 2.5.2 外链必须机器校验（30% 的损坏率）

`chinese-independent-blogs` 收录 982 个博客，**末尾另有 424 个被移入「疑似失效」区**（RSS 持续抓取失败），并逐条标注失败原因（`HTTP 522/526/530`、`response is not RSS/Atom`）。**即约 30%（424/1406）的中文独立博客已经损坏。**

你实测 404 后剔除的那批链接里，`randallkanna.com`、`sjmielke.com`、`1023.io`、`mithi.github.io` **恰好都收录在一份 2020 年的清单里**——说明**站点后来死了，不是清单造假**。

**可落地的做法**：把他们的机制搬成我们**构建期的一次外链检查**——「明确错误（404/证书）持续 1 天即标记，其他错误持续 7 天即标记」。**任何依赖外部链接长期有效的功能都必须配机器校验，否则必然腐烂。**

#### 2.5.3 工程卫生三项

1. **图片属性清单**：凡输出 `<img>` 就带齐 `width`/`height`（防 CLS）、`loading="lazy"`、`decoding="async"`，多尺寸时上 `srcset`+`sizes`。**基准是 `lutaonan`**（全语料单标签属性最完整）。**注意 `brutalistwebsites` 是反面教材**：1599 张全部 `lazy`（**含首屏**）且只有 `style="width:400px"`、**无 height** → 既伤 LCP 又抖布局。**「一律 lazy」这条规则不成立，必须配宽高与首屏 eager。**
2. **图注规范（我们最缺的一项）**：抄 `gwern` 的三段分工——**短句进 `<figcaption>`，长解释进 `title`，无障碍描述进 `alt`**（三者互不重复），并给 `figure`/`figcaption` 写样式。参考 `lilianweng` 的统一句式：`描述文字 (Image source: <a>作者 年份</a>)`（17 处同一句式）。
3. **暂不引入 `avif` / `<picture>`**：**全语料 60+ 页面里 `avif` 出现 0 次**，`<picture>` 只在 `hugo-themes`（产品页）大量出现。我们站内几乎不落位图，为不存在的负载引入是过度设计。**保留「社交图 PNG」这一条位图通道即可。**

| 不做 | 理由（有据） |
| --- | --- |
| 换框架 | 已是 Astro 7.3.8；两个 Astro 同行（`lutaonan` 7.3.5、`liruifengv` 5.0.2）都没用视图过渡，**我们在架构上并不落后** |
| **按章节用 `content-visibility`** | **Gwern 团队做过相同实验并放弃**（§2.4.2），同行证据 + 我们自己的否决 |
| **页边注** | 60 站孤例；`gwern` 在 `<1760px` 直接隐藏、需 JS reflow，自述 *"user-visible & distracting"* |
| 表格排序 | **60 个样本里 0 个真实实例**（唯一命中是 `gwern` 的 CSS 注释，而那几页一个 `<table>` 都没有） |
| 反向链接 | 只有 `gwern` 一家，实现成本高（§2.5.1） |

| **`joshwcomeau` 式弹簧/长时长编排** | 它的 `linear()` 过冲曲线需 833ms–1.167s 才完整，与克制基调不符 |
| **`taniarascia` 式 per-token ×4 规则** | 59 个 token 生成约 236 条主题规则，规则数 ×4 |
| **icon font CDN / emoji 图标系统** | 10 家仍引 Font Awesome CDN（`axutongxue` 甚至引百度 CDN）；`marginalia` 的 emoji 图标**不可着色**，会与我们的配色体系打架。`mollywhite` 的正面参照是**把 FA 内联成 SVG**，只借图形不引单点 |
| **Heti / pangu 运行时** | 单点 CDN、会污染复制文本、且**必须给 `.katex` 打排除补丁**（我们已支持 KaTeX，这是实际回归面） |
| **`text-indent: 2em` 首行缩进** | 中文站 0 例；它与 1.5em 段间距是**重复标记**（书籍排版里缩进本就是替代段间距的手段） |
| 全局 `keep-all` / 中文 `justify` / 正文 `break-all` | `keep-all` 语料仅用于短 UI 串与表格；justify 全是英文站；`break-all` 只用于 code/表格 |
| **`palt`/`halt` 做标点挤压** | 语料 0 例，且需字体保留对应 GSUB 表——我们的思源宋体子集是否保留**本地无法验证** |
| **`tonsky` 的 cap-height 体系（整体）** | 优雅但产物 17.91px/12.5px/4.17px **不落任何标准网格**、与 Tailwind 刻度不能混用，且**他自己也要 5px/6px 逃生舱** |
| 追求 Lighthouse 满分 | 那 4.1MB 里 41% 是**为无障碍保留的 MathML**（§2.4.1），是自觉取舍；优化目标是**不让读者感到慢**，不是刷分 |
| 因为调研列了某站就增加对应功能 | 那 50+ 个站点风格差异极大却都自洽——可迁移的是**判断方式**，不是功能清单 |

## 5. 一句话方向

**本站已经过了「该长什么样」的阶段。这一轮既不是加功能，也不是换风格，而是补三件结构性的事。**

1. **补上暗色模式**——唯一的大块能力缺口。但要**暖底而非 Material 冷灰**，且**陶土色必须另出一档提亮值**（原值在暗底不达 AA）。
2. **把颜色与间距收进令牌**——决定「专业」与「业余」的隐形差别。间距走 **0.25rem 网格 + 语义名**，这是语料里唯一高一致度的体系。
3. **把长文阅读的三项补到齐**——目录升到 h3（我们现在只覆盖 1/4）、标题永久链接、脚注走语义路线。

**以及一批一行级修正**（动效时长收敛、reduced-motion 反向 opt-in、CJK 禁则补到正文），它们是投入产出比最高的部分。

**同时要守住三件已经做对的事**：`prefers-reduced-motion` 完整处理（只有 25% 的站点做到）、跨文档视图过渡（语料里几乎只有我们在用）、SVG 优先的图形策略（同行里少数派正解）。以及一条已被同行印证的判断：**按章节用 `content-visibility` 是死路——Gwern 试过并放弃了。**
