全站使用暖纸色、鼠尾草表面与陶土操作色。首页精选采用主推文章与紧凑条目组合；项目使用实验方法图；学习专题用书脊边界、主题结构图与统一图标表达不同学习路径。博客、学习、项目、关于、标签、归档与搜索共享排版、颜色、按钮与焦点规范。

## 公式修复

行内 KaTeX 恢复自然布局，短公式不再成为滚动容器。块公式由单一外层负责横向滚动，正常宽度居中，真正超宽时左对齐且两端可达。测量保留 3px 容差和 6px 留边，接近视口时才测量；内联强调元素的 `clientWidth=0` 不被当作正文宽度。

桌面与手机的数学附录验证中，短行内公式滚动容器为 0，正常块公式的多余滚动为 0，整页横向溢出为 0。超宽公式具备键盘焦点和可访问操作名称。删除每条公式下面占一整行的滑动提示，保留简短悬停提示和原生细滚动条。公式编号、矩阵、根式、上下标及 MathML 保留。编号留边针对 KaTeX 0.19 的 `katex-tag` 元素处理，验证全部公式主体分段与编号之间的空间。

## 单页性能与保守取舍

保留完整文章意味着数学附录仍有约 11 万个 DOM 元素和约 4.1MB 的未压缩 HTML。此轮主要减少公式滚动容器与滚动过程中的测量和属性更新，保留按字形加载字体、懒加载图片、延迟评论和搜索引擎加载。

实验将正文按 26 个自然章节组织并使用 `content-visibility:auto` 与 2,000px 初始占位。章节真实高度在桌面约 461–6,345px、手机约 626–8,695px；正文估算总高度从桌面约 70,800px 变为 53,339px，手机约 88,905px 变为 53,634px。这会改变目录位置与阅读进度，故没有采用该实验。实验脚本只修改临时浏览器 DOM，未进入生产正文。

当前全文单页的冷启动实测表将在最终构建后写入此处；历史分节页面的性能数字不用于本次对比。

## 验收与复现

工程检查：`npm run check`、`npm run test:unit`、`npm run build`、`npm run test:browser`。构建检查覆盖所有页面、内部引用、一级标题与公式错误。浏览器覆盖桌面/手机、320–1440px 边界、搜索与焦点、失败恢复、短/长公式、阅读记录、远距离锚点、复制、打印和减少动态效果。

截图和测量保存在忽略的 `.artifacts/warm-garden/`。可以重跑：

```powershell
node scripts/review-garden.mjs --offline
node scripts/review-garden.mjs
node scripts/audit-garden.mjs after
node scripts/probe-reading-layout.mjs
```

`review-garden` 先滚动页面加载图片，再等待动效结束；在线模式额外只读检查评论。`audit-garden` 每个页面/视口创建三个独立浏览器上下文，记录 LCP、CLS、长任务、HTML 和资源传输、实际字体请求，取中位数。此为本机 Chrome 未限速的实验室数据，390px 代表视口宽度，不代表真实手机 CPU 或移动网络。

最终根路径和 `/kreiitorBlog/` 构建/浏览器结果将在验收结束后补录。仅本地提交，没有推送或发布。
