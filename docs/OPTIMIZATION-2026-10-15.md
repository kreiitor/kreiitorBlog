# 2026-10-15 网页优化与修正

承接 [网站评估与滚动问题复现](SITE-REVIEW-2026-10-15.md)。保留温暖数字花园的视觉方向，集中处理滚动稳定性、可读性、窄屏布局、阅读辅助与视觉资产。

## 实现

- **滚动稳定性**：sticky 导航保持桌面 88px、手机 74px，不再跨过 20px 阈值时改变文档高度。保留滚动阴影；代价是桌面导航比原收缩状态多占 24px。
- **可读性**：浅色强调色调整为 `#9e5130`，辅助字号令牌从 12px 提升为 13px；修正标题永久链接的颜色变量拼写，触屏锚点完整显示。深浅模式的主按钮、链接、标签和辅助文字按浏览器实际合成背景验证对比度。
- **窄屏**：精选区域使用可收缩的栅格列，允许摘要里的长英文标识符换行，消除 320px 首页 9px 横向溢出；未用全页隐藏横向溢出来掩盖问题。
- **首页信息组织**：最近札记排除已展示的精选文章，保留五条最近内容；箭头使用共享图标组件。
- **主题异常恢复**：存储读取或写入失败时，主题按钮仍可在当前页面切换；正常情况下保留首次系统偏好、后续显式两态选择与持久化。
- **阅读目录**：桌面与手机目录同步高亮 h2/h3，保存的阅读记录继续采用 h2 节段，兼容既有记录。缓存链接映射，仅更新前后两个章节；正文几何未改变时不重复遍历标题。
- **公式**：只在正文扫描公式节点，首次进入视口或尺寸/字体变化时测量溢出。两份目录使用原生 MathML 与 TeX 注释，正文仍保留完整 KaTeX 视觉输出和 MathML。
- **图片稳定性**：画廊五张图片补齐真实固有宽高；专题与项目封面按 800:420 完整显示，避免标题被裁切。
- **封面与图标**：18 张封面统一主题标题、放大主图、修正文字重叠与路线断线；补齐四张编程语言分享图，19 张 PNG 均为 1200×630。共享图标统一边界与笔画；首页内嵌插画随主题换色，手机使用简化嫩芽。favicon 包含 16/32/48px 图层。生成器以完整临时文件替换，避免预览读到部分写入的文件。

## 封面留白与色调追加修正

用户进一步指出封面标题贴顶、橙绿底色混用不均匀。确认有三层原因：原稿按主题使用三种背景色；专题卡片还按类别设置不同底色；手机卡片将原稿 800:420 裁为 2.1:1，减少了标题顶部的实际留白。

- 18 张封面统一为 `#f6f3eb` 浅暖纸底，内部面块仅使用中性纸色。鼠尾草绿承担结构线，陶土色只强调少量节点/标记，不再用整片橙绿底区分主题。
- 标题基线从 y58 下移到 y66，分割线统一 y88；主图统一处于 x32–768、y100–392 安全区内，底部至少留 28px。联系表与逐像素边界检查保存在 `.artifacts/cover-unified-paper*`。
- 首页插画、专题卡片、专题徽记和侧栏收敛为中性暖纸表面；去掉专题之间的绿底/暖棕底切换与徽记渐变。深浅主题保留原有文字和操作强调色，保证已验证的对比度。
- 文章、札记、专题与项目封面统一 800:420 原始比例，完整显示；加载占位也采用纸底，减少图片载入前后的橙绿色块闪变。

## 字体与长文章的取舍

文楷子集现在覆盖 Markdown 章节标题，拉丁字体声明真实字符范围。首页不再因为标题缺字下载三份中文宋体回退，也不再下载没有实际用途的拉丁正文回退。

| 相同冷缓存条件，390px 宽 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首页字体传输量 | 749,232 B | 369,104 B（减少 50.7%） |
| 首页字体请求数 | 8 | 4 |
| 首页 DOM 元素 | 477 | 485 |
| 首页解码后 HTML | 40,519 B | 43,034 B |
| 数学附录 A 字体传输量 | 1,176,476 B | 1,292,984 B（增加 9.9%） |
| 数学附录 A DOM 元素 | 111,868 | 110,800（减少 1,068 个） |
| 数学附录 A 解码后 HTML | 4,262,702 B | 4,217,219 B |

文楷完整标题字形使长文章冷载字体增加约 117KB，这是保持标题字形一致的成本。两份目录精简只降低约 1% DOM；正文仍有 109,766 个元素，不能称作已解决长文体量问题。保留全文、浏览器查找、复制、打印、章节锚点和正文 MathML；没有引入会干扰滚动几何的正文虚拟化。

测量脚本：`node scripts/audit-reading-performance.mjs before|after`。Chrome 手机视口模拟，独立浏览器上下文、禁用缓存，CPU 正常/6 倍降速各一次，页面加载并等待字体后进行 36 次逐帧滚动。数据保存在忽略的 `.artifacts/optimization/before/` 与 `after/`。HTML 是解码后大小；字体传输量含浏览器响应头估计，并非线上压缩 HTML 传输量。

| 本机单次采样 | 优化前 LCP | 优化后 LCP | 前/后滚动帧超过 50ms 次数（共 36 帧） |
| --- | ---: | ---: | ---: |
| 首页，CPU 正常 | 576ms | 376ms | 4 / 3 |
| 数学附录 A，CPU 正常 | 992ms | 684ms | 4 / 1 |
| 首页，CPU 6 倍降速 | 2,760ms | 1,992ms | 9 / 0 |
| 数学附录 A，CPU 6 倍降速 | 3,948ms | 2,124ms | 35 / 35 |

本机单次计时只用于定位，不代表真实低端手机、弱网或稳定的线上百分位性能。CPU 正常时数学页长任务总耗时从 752ms 到 1,274ms，存在波动；不能只取 LCP 改善宣称所有性能都提升。6 倍降速下长文依然明显卡顿，后续需针对正文公式排版成本单独测量和设计。

## 验收

色调与留白修正后的完整浏览器回归：75 通过、1 跳过（桌面项目不执行手机触摸用例）。覆盖滚轮、键盘、两种回顶入口、原生触摸、逐帧布局稳定性、窄屏、深浅主题与存储失败、目录、公式、打印、搜索、分页、评论与阅读记录。

逐帧测试修复了测试驱动自身的采样竞态：原先启动 700ms 采样后，再经一次工具往返触发滚动；长文追踪快照有时使采样在指令到达前结束。现在采样和滚动在同一个浏览器任务启动，保持原有布局/最终位置断言，并检查确实取得多帧。失败追踪保留为 `.artifacts/optimization/sampling-race-trace.zip`；修正后完整回归记录为 `browser-final.json`。

封面库与专题配置扩展后的最终验收：

- `npm run check`：69 个文件，0 errors / 0 warnings / 0 hints。
- `npm run build` 成功生成 131 页；构建后检查通过 11,172 个本地引用、每页一个 H1、无公式错误，并确认同站分享 PNG 存在。
- `npm run test:unit`：3 项单元测试及专题排序、草稿/空组过滤、无效配置检查通过。
- 新版专项浏览器检查：桌面/手机的封面相邻不重复与回顶入口共 4 项通过。另在 320/390/1440px、深浅两种主题完成 48 个页面场景，确认首页/学习页三张专题卡片、专题目录封面与分享图、章节分享图继承及正文不额外插入大封面；无页面脚本错误，首页/学习页/专题目录无横向溢出。截图与记录位于 `.artifacts/optimization/cover-integration/`。
- 30 张封面主图均处于安全区，同名 PNG 均为 1200×630。离线选图册验证了 22 篇文章/6 组专题/2 个项目的用途筛选、关键词搜索、无结果提示、键盘复制和剪贴板失败时的文本选择回退；320/390/768/1440px 无横向溢出，零外部请求、零脚本错误。记录位于 `.artifacts/cover-library-validation.json`。

上文 75 通过、1 跳过属于统一色调和留白后的完整回归；最终封面库扩展使用上述专项验证，未重复运行整套浏览器测试。
