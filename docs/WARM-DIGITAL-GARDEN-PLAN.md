站点：kreiitor · 研究札记。沿用现有 Astro 静态站、Markdown 内容与既有文章地址。

## 2. 已确认的问题与处理方向

### 2.1 评论功能回退

上一轮移除了 Giscus 原有默认仓库和分类配置。本地缺少对应环境配置时，评论组件只输出邮件入口；已确认本地构建没有评论容器。部署端如果没有设置对应 Variables，也会出现相同结果。

将原有公开仓库、分类配置恢复为明确的站点配置，允许环境变量覆盖。核对现有 Giscus 安装与分类有效性，沿用原来 pathname 对应的讨论，保留旧评论关联。

评论接近正文末尾时加载，入口提供可见的“加载中、加载失败、重试”状态。邮件交流作为补充入口。通过 Giscus 支持的主题机制协调 iframe 内的纸色、文字和链接颜色，单独验证 iframe 内外的视觉衔接。

验收覆盖完整配置、缺少配置、网络失败、重试、原有讨论关联和移动端布局；通过浏览器实际确认评论 iframe 与输入界面，而非只检查配置布尔值。

### 2.2 正常公式出现滚动条

当前 `.rich-content .katex` 对行内公式也设置了横向滚动与纵向裁切。2026-10-13 的本机 Chrome 样本中，桌面数学附录有 316 处公式产生仅 1–3px 的微小溢出；`a_{ij}` 宽约 22px，仍有 2px 的溢出。这解释了视觉上并不宽的公式为何会触发滚动。

修复按公式语义区分：

- 行内公式恢复自然排版，处理上下标、字形边缘与小数像素造成的微小几何溢出，保持基线和行高稳定。
- 块公式正常宽度时保持居中；真正超出正文可用宽度时，由单一外层容器负责横向滚动，并保证两端完整可达。
- 结合内容几何尺寸、适当留边和测量容差判断溢出。同步调整 CSS 与测量逻辑，仅提高 JavaScript 阈值无法阻止 CSS 自行产生滚动区域。
- 真正超宽时提供轻微边缘提示、可聚焦的操作区域和清楚的可访问名称；提示不占据每条公式下方的一整行。
- 保留公式编号、MathML、上下标和原始正文。检查矩阵、根式、多行推导、带编号公式及中文说明。

补充公式级测试：短公式无多余滚动，长公式能完整查看，字体加载前后与浏览器缩放不误判。现有“整页没有横向溢出”测试继续保留，并增加公式容器内部的验证。

## 3. 视觉系统

### 3.1 色彩与材质

以下为第一轮样稿的候选色值，正式落地按实际背景上的对比度复核。

| 角色 | 候选色值 | 使用方式 |
| --- | --- | --- |
| 页面纸色 | `#F4F1E8` | 全站主要背景，保持暖白而非泛黄。 |
| 阅读与局部表面 | `#FAF8F1` | 正文、搜索面板及少量需要分层的组件。 |
| 主文字 | `#35382F` | 温暖的深炭色，提供清楚的文字对比。 |
| 次级文字 | `#62685B` | 日期、摘要和补充说明；关键信息仍使用主文字。 |
| 陶土强调 | `#925134` | 主要操作、精选标记与少量交互反馈。 |
| 鼠尾草表面 | `#E5EAD9` | 学习专题、插图底色及小范围内容分组。 |
| 亚麻表面 | `#E9E1D3` | 项目与工具主题的辅助背景。 |
| 分隔线 | `#D7D6C7` | 结构分隔和轻边界；交互控件单独验证辨识度。 |

纸色占据主要面积，色彩集中在操作与有意义的内容分组上。正文背景保持干净；纸张质感优先通过色温、间距和局部阴影表达。需要纹理时只在插图局部使用轻量细节，避免降低文字清晰度。

### 3.2 字体与排版

延续 Source Serif 4 / 思源宋体的标题和阅读正文，DM Sans / 系统中文字体承担界面信息。使用已有自托管字形、真斜体与字重范围，根据新增界面文字更新语料子集。

桌面正文以 18px、手机正文以 17–18px 为起点，随字体实际效果复查。界面正文以 14–15px 为主，日期、标签和辅助说明至少 12px。中文标题允许自然断行，按语义安排标题宽度和层级；控制英文眉题的数量，减少重复的装饰性英文。

首页标题、页面标题、卡片标题和正文标题形成清楚的尺度差异。通过标题、摘要、图形和留白共同建立重点，确保手机第一屏能看清身份和主要浏览入口。

### 3.3 页面节奏

首页采用“个人介绍与研究图形 → 精选札记 → 项目实践 → 学习路径 → 最近更新”的内容主线。精选札记可采用一篇主推搭配紧凑条目；项目与学习专题各有自己的展示构图。区块之间以网格、留白和信息密度建立变化。

正文页保持阅读中心：标题区适度收敛，桌面目录辅助定位，手机目录按需展开。装饰集中在标题区、封面和文末，正文中的论证、公式和代码保持连续。

## 4. 组件、图标与插图的审美规格

### 4.1 组件按用途设计

| 组件 | 设计方向 | 交互与信息要求 |
| --- | --- | --- |
| 札记卡片 / 条目 | 以标题和摘要为主体，精选可有局部插图；列表采用安静的分隔与清楚的排列。 | 主要阅读入口明确，标签入口独立，日期与阅读时间不争夺重点。 |
| 项目卡片 | 用横向或不对称图文表达问题、方法和当前状态，展示真实的结构图或界面。 | 项目状态可辨识；已有仓库、演示和交流操作容易找到。 |
| 学习专题 | 用书脊、章节路径或知识结构呈现“成体系地读”，标题区留出完整空间。 | 显示真实章节数量与主题；学习入口一致，长中文标题自然断行。 |
| 按钮与链接 | 主操作用陶土色实心按钮，次操作用轻表面或文字；箭头使用统一组件。 | 按下、悬停、键盘焦点和禁用状态完整，触摸操作无需依赖悬停。 |
| 标签与筛选 | 标签轻量，筛选具备明确选中状态；通过位置和文字同时表达状态。 | 切换后数量与列表同步，刷新后保留选择，键盘可操作。 |
| 搜索面板 | 暖纸表面与清楚输入区域，结果用标题、类型和真实摘要形成层级。 | 加载、无结果、失败与重试状态完整，保留查询、焦点与键盘导航。 |
| 阅读目录与进度 | 细线、清楚的当前章节标记，手机展开后易于扫描。 | 不遮挡正文，不随每次滚动做昂贵的全篇测量。 |
| 评论区 | 与阅读表面协调，讨论标题与输入区域清楚。 | 嵌入加载和失败状态可见，保持原有讨论关联。 |

统一间距、描边、边界与状态规范。圆角随用途变化：文章条目可用直线分隔，工具面板使用小圆角，少量插图表面可以更柔和。阴影主要帮助表达层次与操作反馈。概念图中的倾斜便签只在少数插图中使用。

### 4.2 图标系统

导航与操作图标优先统一为一套轻量线性图标，例如按需引入 Lucide。以 16、20、24px 为基础尺寸，描边以 1.5–1.75px 为样稿起点，统一端点、光学重量、对齐和可点击区域。

搜索、返回、目录、复制、展开、外链采用一致语义；外链和站内“继续阅读”使用不同方向的标记。文本和图标共同承担重要操作，图标按钮提供清楚的可访问名称。

品牌标识可保留并精修 `k.`，少量专题符号可用自绘 SVG。品牌图形与功能图标分别维护，保持站点独有的识别性。插图里的装饰符号不承担按钮功能。

### 4.3 图片与插图系统

以“研究笔记、知识结构、实验过程”为图形主线，统一纸色、线条、阴影和细节密度，每种内容选择对应的构图。

- **首页主视觉**：研究路径、笔记层叠与实验痕迹形成一个清楚焦点，桌面和手机分别构图；手机保持文字入口优先。
- **数学与学习**：坐标、结构关系、推导路径和章节组织，图形能传达主题。
- **Agent 与 Infra**：用工作流程、记忆与工具关系、计算或存储层级表达差异，统一视觉语言。
- **项目**：优先使用真实界面、方法结构图或实验流程。没有可公开结果时，采用主题结构插图并准确表达项目状态。
- **文章封面**：建立少量可维护的主题模板，使同系列可识别、不同主题有变化；封面文字在小尺寸中仍清楚。

结构图和可控几何插图优先使用 SVG，位图用于确有必要的照片、截图或独特材质。统一裁切、安全区与移动端重排，为图片设置尺寸以减少布局跳动。站内图片与分享预览分别适配，分享图继续提供 1200×630 PNG。

图片验收包括：主题是否准确、视觉焦点是否明确、细节是否过多、手机是否仍可辨识、配色是否与表面协调、是否出现拉伸或失真，以及替代文本是否与图片用途一致。

## 5. 动效与交互

### 5.1 运动规范

| 场景 | 初始时长范围 | 表达方式 |
| --- | --- | --- |
| 悬停与颜色反馈 | 120–180ms | 文字、下划线、箭头和局部图形细微联动。 |
| 按下与释放 | 90–120ms | 短促明确，视觉重心稳定。 |
| 页面切换与筛选 | 180–260ms | 保持导航连续，内容短距离位移与淡入，布局变化平顺。 |
| 手机菜单与目录展开 | 220–300ms | 与打开方向一致，操作完成后焦点位置清楚。 |
| 首次局部出现 | 280–420ms | 只用于需要建立层级的少量元素。 |

数值是调试起点，最终按操作感受和设备表现调整。位移以 2–6px 的细微反馈为主，使用减速曲线；弹性只用于确有反馈价值的局部控件。动画集中在 `transform` 与 `opacity`，尊重系统减少动态效果设置。

### 5.2 具体交互

**导航和页面切换**：共享页头保持位置连续，当前栏目清楚；标题与内容建立短促的过渡。保留链接与浏览器前进后退语义，移动端导航有明确的打开、关闭、焦点与页面滚动管理。

**卡片**：标题下划线、箭头与插图局部响应形成统一反馈，按下后迅速进入目标内容。触摸与键盘操作获得等价反馈。

**筛选**：选中标记平滑移动，结果数量和列表协调更新，避免整片空白后突然出现。列表翻页保留位置逻辑，焦点不落到被隐藏内容。

**搜索**：快捷入口和搜索页共享查询状态。快捷面板打开后聚焦输入；方向键选择结果、Enter 进入、Escape 关闭并恢复触发位置。保留中文标题优先、真实摘要、全文覆盖与结果去重。加载状态稳定，错误可重试。

**阅读工具**：目录准确标记当前章节，手机目录展开有轻巧过渡，代码复制有即时反馈。提供“在本机继续阅读”的可见入口，记录章节锚点与近似位置；带明确锚点的链接优先定位到该锚点。阅读记录仅保存在本机，并提供关闭或清除入口。

交互验收关注键盘、触摸、焦点、状态反馈和减少动态效果；动画完成前后，正文位置与内容仍应稳定。

## 6. 单页长文的性能策略

当前数学附录样本约有 11 万个 DOM 元素，恢复单页后整篇 HTML 约 4.1MB。优化以完整内容和阅读连贯性为约束。

1. 正文完整生成在同一页面。保留原地址、旧锚点、MathML、浏览器全文查找、复制全文和打印行为。
2. 按自然章节组织渲染边界，实验离屏布局与绘制延后；评估 `content-visibility` 和占位尺寸时，重点检查远距离锚点、查找命中、打印和字体变化。只采用通过这些验证的方案。
3. 阅读进度与目录位置缓存测量结果，在内容、字体或视口变化时更新；滚动期间批量处理读写，避免反复测量整篇公式。
4. 公式溢出测量集中在接近视口的区域；字体就绪、相关区域尺寸变化和窗口缩放后重新校验。
5. 字体继续使用自托管语料子集，按页面实际需求加载；新增文字与设计字重后复核覆盖、真实请求和渲染效果。
6. 移动端压缩装饰图片与非必要动画工作量，保持正文、搜索与导航优先可用。

延后布局不会消除完整 HTML 的传输体积，也不会移除全文 DOM。报告应区分传输、解析、布局、脚本与字体开销，按当前单页版本建立基线。历史分节性能结果继续作为历史记录。

## 8. 最终验收清单

- 评论：配置正确时 iframe 和输入界面实际出现，原讨论关联正确；缺配置与网络失败有明确状态。
- 公式：短行内与正常块公式无多余滚动；超宽公式完整可操作；编号、MathML、根式和矩阵无裁切。
- 连续阅读：全文单页；旧链接、目录、远距离锚点、浏览器查找、复制全文和打印有效。
- 视觉：组件层级清楚，图标尺寸与描边统一，插图主题准确；文字和重要控件在实际背景上具有足够对比度。
- 响应式：检查 320、390、768、900、1024、1440px，以及长标题、空状态和加载状态。
- 交互：键盘、触摸、返回路径、焦点恢复、复制反馈和减少动态效果有效，阅读记录入口透明且可清除。
- 性能：以当前单页版本做独立冷启动测量，多次运行取中位数；记录 LCP、CLS、长任务、资源传输和真实字体请求。
- 工程：类型检查、内容/系列验证、相关浏览器测试、构建资源与锚点检查，以及部署子目录验证通过。
